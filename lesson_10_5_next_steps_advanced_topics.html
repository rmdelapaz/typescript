⚡ Introduction to Next.js

You already know React. A meta-framework is what turns React from a UI library into a full application platform — it answers the questions React deliberately leaves open: How do I route between pages? Where does data fetching happen? How do I render on the server for speed and SEO? Next.js, built by Vercel, is the most widely used answer, and as of 2026 it's fully built around React 19 and the App Router.

📖 What is Next.js?

Next.js is a full-stack React framework offering server-side rendering (SSR), static site generation (SSG), React Server Components, Server Actions, file-based routing, and automatic code splitting. Its newer Turbopack bundler (Rust-based, replacing webpack) makes dev startup and hot-reload dramatically faster. The mental model: you write React components, and Next.js decides where and when each one runs.

💡 Next.js isn't the only game in town

It's the default choice, but the meta-framework space is healthy and worth knowing:

  • React Router v7 (formerly Remix): Remix merged into React Router — v7 is the framework mode of the router you already learned. If you liked React Router, this is your smoothest on-ramp to SSR.
  • TanStack Start: a newer, type-safe full-stack framework built on TanStack Router, popular with developers who love end-to-end type inference.
  • Astro: content-first framework that ships zero JavaScript by default and lets you drop in React "islands" only where you need interactivity — excellent for blogs, docs, and marketing sites.

For a client-only single-page app today, scaffold with Vite (npm create vite@latest); for anything needing routing, SSR, or SEO, reach for a meta-framework like Next.js. 🔄 Data Fetching in Next.js

// A Server Component fetches on the server — no useEffect, no loading spinner.
interface Post {
  id: string;
  title: string;
  excerpt: string;
}

async function getPosts(): Promise<Post[]> {
  const res = await fetch('https://api.example.com/posts', {
    next: { revalidate: 3600 }, // Re-fetch at most once an hour (ISR)
  });
  if (!res.ok) throw new Error('Failed to load posts');
  return res.json() as Promise<Post[]>;
}

// Note: the component itself is `async` — a Server Component superpower.
export default async function Blog() {
  const posts = await getPosts();

  return (
    <main>
      <h1>Blog Posts</h1>
      {posts.map((post) => (
        <article key={post.id}>
          <h2>{post.title}</h2>
          <p>{post.excerpt}</p>
        </article>
      ))}
    </main>
  );
}

🖥️ React Server Components

React Server Components (RSC) are the headline feature of the modern React era — now stable and shipping in React 19. They let some of your components render on the server and send finished HTML (plus a little data) to the browser, instead of shipping the component's JavaScript for the browser to run. The result: less JavaScript downloaded, faster first paint, and the ability to talk to your database directly from a component.

📖 What are Server Components?

Server Components run exclusively on the server and never send their JavaScript to the client. They can directly access databases, file systems, and backend resources without a separate API route. Because their code stays on the server, heavy dependencies (a Markdown parser, a date library) add zero weight to your bundle.

💡 The bigger React 19 picture

Server Components arrive alongside a family of React 19 features that change how you write everyday code. You don't need to master these today — just recognize the names so they're not a surprise:

  • Actions & useActionState: pass an async function straight to a <form action={...}> to handle submissions, pending states, and errors with far less boilerplate.
  • use(): a new primitive to read a promise (or context) during render, unwrapping async data with Suspense instead of a manual loading flag.
  • useOptimistic: show an instant, optimistic UI update while the real request is in flight.
  • The React Compiler: an opt-in build-time optimizer that auto-memoizes your components. As it matures, most of the manual useMemo/useCallback you learned becomes unnecessary — you write simpler code and the compiler handles the performance.

📝 Server Component Example

// app/posts/page.tsx (Server Component by default)
// This component runs on the server
async function getPosts() {
  // Direct database access - no API route needed!
  const posts = await db.post.findMany();
  return posts;
}

export default async function PostsPage() {
  const posts = await getPosts();
  
  return (
    <div>
      <h1>Blog Posts</h1>
      {posts.map(post => (
        <article key={post.id}>
          <h2>{post.title}</h2>
          <p>{post.content}</p>
          {/* This is a Client Component for interactivity */}
          <LikeButton postId={post.id} />
        </article>
      ))}
    </div>
  );
}

📝 Client Component Example

// components/LikeButton.tsx
'use client'; // Mark as Client Component

import { useState } from 'react';

interface LikeButtonProps {
  postId: string;
}

export default function LikeButton({ postId }: LikeButtonProps) {
  const [likes, setLikes] = useState(0);
  const [isLiked, setIsLiked] = useState(false);

  const handleLike = async () => {
    if (isLiked) return;
    
    setLikes(prev => prev + 1);
    setIsLiked(true);
    
    // Call API to update likes
    await fetch(`/api/posts/${postId}/like`, { method: 'POST' });
  };

  return (
    <button onClick={handleLike} disabled={isLiked}>
      ❤️ {likes} {isLiked ? 'Liked!' : 'Like'}
    </button>
  );
}

🎯 When to Use Each Type

✅ Use Server Components for:

  • Fetching data from databases or APIs
  • Reading files from the filesystem
  • Accessing backend resources
  • Static content that doesn't need interactivity
  • Large dependencies that can stay on the server
  • Protecting sensitive data (API keys, secrets)

💡 Use Client Components for:

  • Interactive elements (buttons, forms, inputs)
  • Event listeners (onClick, onChange, etc.)
  • React hooks (useState, useEffect, etc.)
  • Browser-only APIs (localStorage, window, etc.)
  • Custom hooks for state or effects
  • Class components (if you still use them)

🔄 Composition Pattern

// app/dashboard/page.tsx (Server Component)
async function getUserData() {
  const user = await db.user.findUnique({ where: { id: userId } });
  return user;
}

export default async function Dashboard() {
  const user = await getUserData();
  
  return (
    <div>
      <h1>Welcome, {user.name}!</h1>
      
      {/* Server Component - no JS to client */}
      <UserStats stats={user.stats} />
      
      {/* Client Component - interactive */}
      <UserSettings initialSettings={user.settings} />
      
      {/* Server Component with Client Component children */}
      <ActivityFeed>
        <RefreshButton /> {/* Client Component */}
      </ActivityFeed>
    </div>
  );
}

⚠️ Important Notes

  • Server Components are the default in the Next.js App Router (and in React Router v7's framework mode)
  • Add the 'use client' directive at the top of a file to make it a Client Component
  • You can't import a Server Component into a Client Component — but you CAN pass one as children/props (the composition pattern above)
  • Keep interactive leaves (buttons, inputs) as small Client Components; let everything around them stay on the server
  • This isn't the future anymore — it's the present of React 19, and it's worth learning now

✨ Animation Libraries

Animations bring your React applications to life. Let's explore the most popular animation libraries and when to use each one.

🎨 Popular Animation Libraries

1. Motion (formerly Framer Motion) — Recommended for Most Projects

Best for: Production-ready animations with minimal code

  • Now shipped as the framework-independent Motion library (motion.dev) — the same declarative API you may know as Framer Motion
  • Declarative API — describe the target, not the steps; easy to learn
  • Excellent TypeScript support out of the box
  • Gestures (drag, tap, hover) and layout animations built-in
  • Tree-shakeable, and a hybrid engine that hands off to the browser's hardware-accelerated animations where possible
npm install motion

// The React entry point is 'motion/react'
import { motion } from 'motion/react';

function AnimatedBox() {
  return (
    <motion.div
      initial={{ opacity: 0, y: 20 }}
      animate={{ opacity: 1, y: 0 }}
      exit={{ opacity: 0, y: -20 }}
      transition={{ duration: 0.3 }}
      whileHover={{ scale: 1.05 }}
      whileTap={{ scale: 0.95 }}
    >
      Animated content
    </motion.div>
  );
}

// Page transitions
function PageTransition({ children }: { children: React.ReactNode }) {
  return (
    <motion.div
      initial={{ opacity: 0, x: -20 }}
      animate={{ opacity: 1, x: 0 }}
      exit={{ opacity: 0, x: 20 }}
      transition={{ duration: 0.3 }}
    >
      {children}
    </motion.div>
  );
}

2. React Spring

function SpringBox() {

    from: { opacity: 0, transform: 'scale(0.8)' },

Best for: Complex, timeline-based animations

  • Industry standard for complex animations
  • Extremely powerful and flexible

import { useEffect, useRef } from 'react';
import { gsap } from 'gsap';

function GSAPAnimation() {
  const boxRef = useRef<HTMLDivElement>(null);

  useEffect(() => {
    if (boxRef.current) {
      gsap.from(boxRef.current, {
        duration: 1,
        opacity: 0,
        y: 50,
        ease: 'power3.out'
      });
    }
  }, []);

  return <div ref={boxRef}>GSAP Animation</div>;
}

🧩 Component Libraries

Component libraries provide pre-built, accessible UI components that speed up development. Before we list them, a quick word on styling, because the two decisions go hand in hand.

💡 How to style React in 2026

  • Tailwind CSS v4: the dominant choice. v4 rewrote the engine for a big speed boost and now configures largely through CSS itself (@theme) instead of a JavaScript config file. Utility classes right in your JSX.
  • CSS Modules: plain, scoped .module.css files — built into Vite and Next.js, zero runtime, great when you prefer "just CSS."
  • vanilla-extract: write styles in TypeScript with full type-safety, compiled to static CSS at build time — the type-lover's zero-runtime option.
  • Runtime CSS-in-JS (styled-components/Emotion) still works, but note it doesn't play naturally with Server Components — prefer the zero-runtime options above for new RSC apps.

🎯 Advanced React Patterns

As you continue your React journey, you'll encounter advanced patterns that solve complex problems. A modern heads-up first: in today's React, custom hooks are the default tool for sharing logic — most jobs that once needed render props or higher-order components are now a clean custom hook. So why learn these? Because you'll meet them in existing codebases and library APIs, and knowing them makes you a stronger reader of other people's React. Learn to recognize them; reach for a custom hook first.

1. Render Props Pattern

Share code between components using a prop whose value is a function.

interface MouseTrackerProps {
  render: (state: { x: number; y: number }) => React.ReactNode;
}

function MouseTracker({ render }: MouseTrackerProps) {
  const [position, setPosition] = useState({ x: 0, y: 0 });

  const handleMouseMove = (e: React.MouseEvent) => {
    setPosition({ x: e.clientX, y: e.clientY });
  };

  return (
    <div onMouseMove={handleMouseMove} style={{ height: '100vh' }}>
      {render(position)}
    </div>
  );
}

// Usage
function App() {
  return (
    <MouseTracker
      render={({ x, y }) => (
        <h1>Mouse position: {x}, {y}</h1>
      )}
    />
  );
}

2. Higher-Order Components (HOC)

A function that takes a component and returns a new component with added functionality.

// HOC that adds loading state
function withLoading<P extends object>(
  Component: React.ComponentType<P>
) {
  return function WithLoadingComponent({ isLoading, ...props }: P & { isLoading: boolean }) {
    if (isLoading) return <div>Loading...</div>;
    return <Component {...props as P} />;
  };
}

// Usage
const UserListWithLoading = withLoading(UserList);

function App() {
  const [isLoading, setIsLoading] = useState(true);
  
  return <UserListWithLoading isLoading={isLoading} users={users} />;
}

4. State Reducer Pattern

Give users control over internal state changes.

type Action = 
  | { type: 'increment' }
  | { type: 'decrement' }
  | { type: 'reset' };

interface State {
  count: number;
}

function useCounter(
  initialCount: number = 0,
  reducer?: (state: State, action: Action) => State
) {
  const defaultReducer = (state: State, action: Action): State => {
    switch (action.type) {
      case 'increment':
        return { count: state.count + 1 };
      case 'decrement':
        return { count: state.count - 1 };
      case 'reset':
        return { count: initialCount };
      default:
        return state;
    }
  };

  const [state, dispatch] = useReducer(
    reducer || defaultReducer,
    { count: initialCount }
  );

  return {
    count: state.count,
    increment: () => dispatch({ type: 'increment' }),
    decrement: () => dispatch({ type: 'decrement' }),
    reset: () => dispatch({ type: 'reset' }),
  };
}

// Users can override behavior
const customReducer = (state: State, action: Action): State => {
  if (action.type === 'increment') {
    // Custom behavior: increment by 2
    return { count: state.count + 2 };
  }
  return defaultReducer(state, action);
};

5. Controlled Props Pattern

Let components be controlled or uncontrolled.

interface ToggleProps {
  value?: boolean; // Controlled
  defaultValue?: boolean; // Uncontrolled
  onChange?: (value: boolean) => void;
}

function Toggle({ value, defaultValue = false, onChange }: ToggleProps) {
  const [internalValue, setInternalValue] = useState(defaultValue);
  
  // If value prop exists, component is controlled
  const isControlled = value !== undefined;
  const currentValue = isControlled ? value : internalValue;

  const handleToggle = () => {
    const newValue = !currentValue;
    
    if (!isControlled) {
      setInternalValue(newValue);
    }
    
    onChange?.(newValue);
  };

  return (
    <button onClick={handleToggle}>
      {currentValue ? 'ON' : 'OFF'}
    </button>
  );
}

// Uncontrolled usage
<Toggle defaultValue={false} onChange={(v) => console.log(v)} />

// Controlled usage
const [isOn, setIsOn] = useState(false);
<Toggle value={isOn} onChange={setIsOn} />

💡 When to Use These Patterns

  • Render Props: When you need maximum flexibility in rendering
  • HOCs: For cross-cutting concerns (auth, logging, etc.)
  • Compound Components: For flexible, semantic APIs
  • State Reducer: When building libraries/components others will use
  • Controlled Props: For form components and reusable widgets
