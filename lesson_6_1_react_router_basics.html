🌐 Understanding Single Page Applications

Before we touch a single line of React Router, let's build the right mental model. Understanding what problem routing solves makes every API in this lesson feel obvious instead of arbitrary.

What is a Single Page Application?

A Single Page Application (SPA) is a web app that loads one HTML document up front, then rewrites the page's content on the fly as you interact with it. Compare that to a traditional Multi-Page Application (MPA) — think of an old-school news site — where every click asks the server for a brand-new HTML page and the browser throws away everything and repaints from scratch.

Here's the everyday analogy: an MPA is like ordering at a restaurant where the kitchen clears your entire table and resets it for every course. An SPA is like a chef who simply swaps out the plate in front of you — same table, same tablecloth, same silverware, just new food. Faster, smoother, and nothing you were using disappears. 🍽️

Traditional Multi-Page vs Single Page Apps

Neither approach is universally "better" — they trade off different things. Here's how they stack up:

Aspect Traditional MPA Modern SPA
Navigation Full page reload Instant, no reload
User Experience Slower, jarring transitions Smooth, app-like feel
Server Load Higher (every navigation) Lower (initial load only)
SEO Easier (native) Requires configuration (or SSR)
Initial Load Faster Slower (loads the app bundle)
State Management Simpler (resets each page) Richer (state persists across views)

📖 Key Concept: Client-Side Routing

Client-side routing means the URL in the address bar changes, but no request is sent to the server. JavaScript intercepts the navigation, updates the URL through the browser's History API, and swaps in the component that matches the new path. The result: the illusion of many pages while you never actually leave the one page you loaded.

Why Do We Need React Router?

Here's a surprise for newcomers: React itself has no concept of URLs or pages. Out of the box, a React app is one component tree rendered into one <div>. Without a router, you'd end up hand-rolling something like const [page, setPage] = useState('home') and a giant if/else to decide what to show — and you'd get no working back button, no bookmarkable URLs, and no shareable links. That gets painful fast.

React Router is the community-standard library that fills this gap. It connects the browser's URL to your component tree, giving you:

  • 🗺️ URL-based navigation: Different URLs display different components
  • 🔗 Linkable pages: Users can bookmark and share specific views
  • ⬅️ Browser history: Back and forward buttons work as expected
  • 📱 Deep linking: Direct access to any part of your app
  • 🎯 Code organization: Separate concerns by route/page

💡 Real-World Example

Think of Netflix: when you click on a movie, the URL changes to something like /watch/12345, but the page doesn't reload. The video player component appears instantly. When you browse back to the home page, it's immediate. That's the power of client-side routing!

How React Router Works

React Router works by:

sequenceDiagram participant U as User participant B as Browser participant RR as React Router participant R as React U->>B: Clicks link B->>RR: URL changes RR->>RR: Matches URL to route RR->>R: Renders matched component R->>B: Updates DOM B->>U: Shows new view Note over RR: No server request!
  1. Listening to URL changes: React Router watches for URL changes using the browser's History API
  2. Matching routes: It compares the current URL against your defined routes
  3. Rendering components: When a match is found, it renders the corresponding component
  4. Managing history: It keeps track of navigation so back/forward buttons work

At its heart, a router is just a lookup table from URL to component. Picture it like the receptionist directory in an office lobby — a URL walks in, the router reads the directory, and points it to exactly the right room:

✅ Benefits of React Router

  • Declarative: Define routes using JSX components
  • Dynamic: Routes can have parameters and nested structures
  • Type-Safe: Full TypeScript support
  • Flexible: Supports multiple routing strategies
  • Well-Maintained: Industry standard with great documentation

📦 Installing and Setting Up React Router

Let's get React Router installed and configured in your TypeScript project.

Installation

React Router v7 is the current version (released in late 2024 and the standard throughout 2026). The good news: everything you learn here is API-compatible with v6.4+, so the concepts transfer directly to any recent project. Install it with your package manager of choice:

# Using npm
npm install react-router-dom

# Using yarn
yarn add react-router-dom

# TypeScript types ship inside the package (v6+).
# You do NOT need @types/react-router-dom anymore.

⚠️ Version Note

This lesson targets React Router v7 with React 19 and TypeScript 5.x. The v7 API is a smooth continuation of v6, so v6.4+ code works unchanged. The big break was v5 → v6: if you meet older tutorials using <Switch> or component={Home}, those are outdated — v6/v7 use <Routes> and element={<Home />}. Confirm your version any time with npm list react-router-dom.

A note on names: the React Router team also ships a full-stack "framework mode" (the evolution of Remix) with its own file-based conventions. This lesson stays in library mode — plain components and hooks you drop into any React app. That's all you need to build great SPAs.

Project Structure for Routing

Before adding routes, let's organize our project structure. Here's a recommended folder layout:

src/

│   └── ...

📖 Naming Convention

Pages vs Components: We put route components (pages) in a separate pages/ folder to distinguish them from reusable components. This makes it clear which components are tied to specific routes.

Two Ways to Set Up Routing

Modern React Router gives you two styles for defining routes, and it's worth knowing both:

  • The declarative approach — wrap your app in <BrowserRouter> and describe routes with JSX <Routes>/<Route>. Simple, readable, perfect for learning and small-to-medium apps. We'll use it for most of this lesson.
  • The data router — build a router object with createBrowserRouter and render a single <RouterProvider>. This is the newer, recommended style for larger apps because it unlocks data loading, actions, and better error handling (topics for later lessons). Same routing concepts underneath.

Think of them as two doors into the same house — pick whichever fits your project. Let's start with the declarative door.

Basic Router Setup (Declarative)

The foundation of the declarative approach is the <BrowserRouter> component. It must wrap your entire application so routing is available everywhere inside it.

Update your src/main.tsx (or src/index.tsx). Note the React 19 createRoot entry point:

import React from 'react';
import { createRoot } from 'react-dom/client';
import { BrowserRouter } from 'react-router-dom';
import App from './App';
import './index.css';

createRoot(document.getElementById('root')!).render(
  <React.StrictMode>
    <BrowserRouter>
      <App />
    </BrowserRouter>
  </React.StrictMode>
);

💡 Why Wrap in main.tsx?

We wrap the app with <BrowserRouter> at the very top (the entry point) so routing is available throughout the entire tree. Any component, no matter how deeply nested, can then use React Router's hooks and components. It's like installing the plumbing before you build the rooms — every faucet downstream just works.

Alternative Setup: The Data Router

Here's the same app wired up with the modern data router. Instead of nesting <Route> elements in JSX, you describe your routes as a plain array of objects and hand them to createBrowserRouter:

// src/main.tsx — data router style
import React from 'react';
import { createRoot } from 'react-dom/client';
import { createBrowserRouter, RouterProvider } from 'react-router-dom';
import Home from './pages/Home';
import About from './pages/About';
import Contact from './pages/Contact';
import NotFound from './pages/NotFound';

const router = createBrowserRouter([
  { path: '/', element: <Home /> },
  { path: '/about', element: <About /> },
  { path: '/contact', element: <Contact /> },
  { path: '*', element: <NotFound /> },
]);

createRoot(document.getElementById('root')!).render(
  <React.StrictMode>
    <RouterProvider router={router} />
  </React.StrictMode>
);

✅ Which Should You Use?

For this lesson and for learning, the declarative <Routes>/<Route> style is the friendliest — you can see the whole route tree as JSX. Reach for the createBrowserRouter data router when your app grows and you want route-level data loading, form actions, and richer error handling. Both use the exact same path-matching rules, so nothing you learn here goes to waste.

Alternative: HashRouter

React Router also offers HashRouter as an alternative to BrowserRouter:

import { HashRouter } from 'react-router-dom';

// URLs will look like: http://example.com/#/about
<HashRouter>
  <App />
</HashRouter>
Router Type URL Format When to Use
BrowserRouter /about Modern apps with server support
HashRouter /#/about Static hosting (GitHub Pages)

✅ Recommendation

Use BrowserRouter for most projects. It creates cleaner URLs and is the standard for modern web applications. Only use HashRouter if you're deploying to static hosting that doesn't support server-side routing configuration.

💡 Page Component Pattern

Notice that page components are just regular React components. The only difference is their purpose: they represent entire pages/views in your application, not reusable UI pieces.

Defining Routes with Routes and Route

Now let's wire up these pages to URLs. Update your src/App.tsx:

import React from 'react';
import { Routes, Route } from 'react-router-dom';
import Home from './pages/Home';
import About from './pages/About';
import Contact from './pages/Contact';
import NotFound from './pages/NotFound';

function App() {
  return (
    <div className="app">
      <Routes>
        <Route path="/" element={<Home />} />
        <Route path="/about" element={<About />} />
        <Route path="/contact" element={<Contact />} />
        <Route path="*" element={<NotFound />} />
      </Routes>
    </div>
  );
}

export default App;

📖 Understanding the Code

  • <Routes>: Container for all your route definitions
  • <Route>: Defines a single route mapping
  • path: The URL path to match
  • element: The component to render when the path matches (note: element={<Home />}, an actual JSX element — not the old v5 component={Home} prop)
  • path="*": Wildcard that matches any unmatched route (your 404 page)

How Route Matching Works

When the URL changes, React Router looks at all your <Route> definitions, scores each one for how well it matches, and renders the single best match. For a simple app you can picture it walking the list until something fits:

flowchart TD A["URL: /about"] --> B["Check routes"] B --> C["path = / ?"] C -->|"No match"| D["path = /about ?"] D -->|"Match!"| E["Render About component"] D -->|"No match"| F["path = /contact ?"] F -->|"No match"| G["path = * ?"] G -->|"Match!"| H["Render NotFound"] style E fill:#48bb78,color:#fff style H fill:#fc8181,color:#fff

⚠️ Route Order Matters (Sort of)

Unlike the old v5 <Switch> (which took the first textual match), React Router v6/v7 ranks routes by specificity, so a more specific path wins even if it's listed later. In practice you rarely fight ordering — just remember the wildcard path="*" is your catch-all 404 and belongs conceptually last.

🔗 Navigation with Link and NavLink

Manually typing URLs in the browser isn't a great user experience. Let's add proper navigation links that work without full page reloads.

The Problem with Regular Anchor Tags

You might be tempted to use regular HTML <a> tags for navigation:

// ❌ DON'T DO THIS
function Navbar() {
  return (
    <nav>
      <a href="/">Home</a>
      <a href="/about">About</a>
      <a href="/contact">Contact</a>
    </nav>
  );
}

The problem: Regular <a> tags cause full page reloads, defeating the purpose of a Single Page Application. Your React app will restart from scratch on every navigation!

⚠️ Why Full Reloads Are Bad

  • Loses all component state
  • Slower user experience
  • Re-downloads JavaScript bundles
  • Triggers unnecessary re-initialization
  • Wastes bandwidth and server resources

Using the Link Component

React Router provides the Link component for client-side navigation:

import React from 'react';
import { Link } from 'react-router-dom';

function Navbar() {
  return (
    <nav>
      <Link to="/">Home</Link>
      <Link to="/about">About</Link>
      <Link to="/contact">Contact</Link>
    </nav>
  );
}

export default Navbar;

📖 How Link Works

Link renders as a real <a> tag in the DOM (great for accessibility and "open in new tab"), but React Router intercepts left-clicks, calls preventDefault(), and updates the URL through the History API. That swaps in the new route component without a page reload — you get the best of both worlds.

Link Props and Options

The Link component accepts several useful props:

import { Link } from 'react-router-dom';

function NavigationExample() {
  return (
    <div>
      {/* Basic link */}
      <Link to="/about">About Us</Link>
      
      {/* Link with relative path */}
      <Link to="../parent">Go to Parent</Link>
      
      {/* Link with state (pass data to next page) */}
      <Link 
        to="/profile" 
        state={{ from: 'homepage', userId: 123 }}
      >
        View Profile
      </Link>
      
      {/* Link that replaces history entry */}
      <Link to="/login" replace>
        Login
      </Link>
      
      {/* Link with additional props */}
      <Link 
        to="/docs"
        className="nav-link"
        target="_blank"
        rel="noopener noreferrer"
      >
        Documentation
      </Link>
    </div>
  );
}
Prop Type Description
to string | Partial<Path> Destination path (required)
replace boolean Replace current history entry instead of pushing
state unknown Pass data to the destination route
relative "route" | "path" How relative paths are resolved

Complete Navbar Example

Let's create a full-featured navbar component. Create src/components/Navbar.tsx:

import React from 'react';

function Navbar() {

        </NavLink>
      </div>
      
      <div className="navbar-links">
        <NavLink to="/" end className={getNavLinkClass}>
          Home
        </NavLink>
        <NavLink to="/about" className={getNavLinkClass}>

Notice the end prop on the Home link. Without it, / would match all paths (since all paths start with /). The end prop ensures it only matches the exact path.

📝 Typing Routes with TypeScript

One of the benefits of using React Router with TypeScript is type safety. Let's explore how to properly type your routing code.

Typing Route Parameters

When you have dynamic routes (which we'll cover more in the next lesson), you'll want to type the parameters. Here's a preview:

import { useParams } from 'react-router-dom';

function UserProfile() {
  // Parameterize useParams with the exact keys you expect
  const { userId } = useParams<{ userId: string }>();

  // TypeScript now knows userId is string | undefined
  if (!userId) {
    return <div>User ID is required</div>;
  }

  return <div>User Profile: {userId}</div>;
}

export default UserProfile;

📖 Why string | undefined?

Route parameters are always string | undefined, never a number and never guaranteed to exist. Why? Because a param is just a slice of the URL text, and a user can type any URL by hand. TypeScript refuses to lie to you about it — so you narrow it with a quick guard (like the if (!userId) check above) before using it. This tiny habit prevents a whole class of "cannot read property of undefined" crashes.

Programmatic Navigation with useNavigate

Links are for things the user clicks. But sometimes your code needs to move the user — after a form submits, once login succeeds, or when a timer runs out. That's the job of the useNavigate hook, which hands you a fully-typed navigate function:

import { useNavigate } from 'react-router-dom';

function LoginForm() {
  const navigate = useNavigate();

  const handleSubmit = async (event: React.FormEvent) => {
    event.preventDefault();
    await logIn();
    // Push a new entry onto history and go to the dashboard
    navigate('/dashboard');

    // Other handy options:
    // navigate('/login', { replace: true });        // replace instead of push
    // navigate(-1);                                  // go back one step
    // navigate('/profile', { state: { from: 'login' } }); // pass state
  };

  return <form onSubmit={handleSubmit}>{/* fields... */}</form>;
}

💡 Link vs. useNavigate

Rule of thumb: if the user is choosing where to go, render a <Link> — it's accessible and keyboard-friendly out of the box. If your logic decides where to go (after saving, redirecting, or reacting to an event), call navigate(). Don't reach for useNavigate just to make a clickable link.

Creating a Routes Configuration

For larger applications, it's helpful to centralize your route definitions with proper types:

// src/types/routes.ts

export const ROUTES = {
  HOME: '/',
  ABOUT: '/about',
  CONTACT: '/contact',
  PROFILE: '/profile/:userId',
  BLOG: '/blog',
  BLOG_POST: '/blog/:postId',
  NOT_FOUND: '*'
} as const;

// Type for route keys
export type RouteKey = keyof typeof ROUTES;

// Type for route values
export type RoutePath = typeof ROUTES[RouteKey];

Now use these constants throughout your app:

✨ Best Practices and Common Patterns

Let's explore some best practices and common patterns when working with React Router to build maintainable and scalable applications.

1. Organize Routes by Feature

As your application grows, organize routes by feature rather than keeping everything in one file:

src/
├── features/
│   ├── auth/
│   │   ├── routes.tsx        # Auth-related routes
│   │   ├── Login.tsx
│   │   └── Register.tsx
│   ├── blog/
│   │   ├── routes.tsx        # Blog-related routes
│   │   ├── BlogList.tsx
│   │   └── BlogPost.tsx
│   └── dashboard/
│       ├── routes.tsx        # Dashboard routes
│       └── Dashboard.tsx
└── App.tsx                   # Main app with route imports

Example feature routes file (features/blog/routes.tsx):

import { Route } from 'react-router-dom';
import BlogList from './BlogList';
import BlogPost from './BlogPost';

export const blogRoutes = (
  <>
    <Route path="/blog" element={<BlogList />} />
    <Route path="/blog/:postId" element={<BlogPost />} />
  </>
);

// In App.tsx
import { Routes } from 'react-router-dom';
import { blogRoutes } from './features/blog/routes';
import { authRoutes } from './features/auth/routes';

function App() {
  return (
    <Routes>
      {blogRoutes}
      {authRoutes}
      {/* ... other routes */}
    </Routes>
  );
}

✅ Benefits of Feature-Based Routes

  • Scalability: Easy to add new features without cluttering App.tsx
  • Maintainability: Routes live with related components
  • Team Collaboration: Different teams can work on different features
  • Code Splitting: Easier to implement lazy loading per feature

2. Nested Routes and Shared Layouts with <Outlet>

Here's a pattern you'll use constantly: a group of pages that share the same chrome — a dashboard with a sidebar, say, where only the middle panel changes. Instead of repeating that sidebar in every page, you nest child routes inside a layout route and mark the swap-in spot with <Outlet />.

Think of <Outlet> as a picture frame. The layout is the frame (and the wall around it); the matched child route is the photo you slot in. Change routes, swap the photo — the frame stays put.

graph TD A["/dashboard (DashboardLayout + Outlet)"] --> B["index → Overview"] A --> C["settings → Settings"] A --> D["billing → Billing"] style A fill:#667eea,color:#fff style B fill:#48bb78,color:#fff 
import { Routes, Route, Outlet, NavLink } from 'react-router-dom';
import Overview from './Overview';
import Settings from './Settings';
import Billing from './Billing';

// A layout component renders shared UI + an Outlet for the active child
function DashboardLayout() {
  return (
    <div className="dashboard">
      <aside>
        <NavLink to="/dashboard" end>Overview</NavLink>
        <NavLink to="/dashboard/settings">Settings</NavLink>
        <NavLink to="/dashboard/billing">Billing</NavLink>
      </aside>
      <main>
        {/* The matched child route renders right here */}
        <Outlet />
      </main>
    </div>
  );
}

function App() {
  return (
    <Routes>
      <Route path="/dashboard" element={<DashboardLayout />}>
        {/* Index route: shown at exactly /dashboard */}
        <Route index element={<Overview />} />
        {/* Child routes: shown at /dashboard/settings, /dashboard/billing */}
        <Route path="settings" element={<Settings />} />
        <Route path="billing" element={<Billing />} />
      </Route>
    </Routes>
  );
}

📖 Index Routes and Outlet

An index route (<Route index ... />) is the default child — it renders into the parent's <Outlet /> when the URL matches the parent exactly (here, /dashboard with nothing after it). Child paths are written relative to the parent, so path="settings" becomes /dashboard/settings. This same layout-route idea is exactly how you could refactor our multi-page app to stop repeating <Navbar /> and <Footer /> in every page. We'll go deeper on nested routes in Lesson 6.2.

Show feedback during route changes (especially important with lazy loading):

import React, { Suspense } from 'react';

💡 Why Lazy Loading?

Lazy loading (code splitting) loads route components only when needed, reducing initial bundle size. This makes your app load faster, especially important for users on slow connections.

5. Scroll to Top on Route Change

By default, React Router doesn't scroll to the top when navigating. Create a component to handle this:

import { useEffect } from 'react';
import { useLocation } from 'react-router-dom';

function ScrollToTop() {
  const { pathname } = useLocation();
  
  useEffect(() => {
    window.scrollTo(0, 0);
  }, [pathname]);
  
  return null;
}

// In App.tsx
function App() {
  return (
    <div className="app">
      <ScrollToTop />
      <Navbar />
      <Routes>
        {/* ... routes */}
      </Routes>
    </div>
  );
}

6. Use URL Parameters for Shareable State

Put important state in the URL so users can bookmark and share specific views:

// ✅ GOOD: State in URL
// URL: /products?category=electronics&sort=price&page=2

import { useSearchParams } from 'react-router-dom';

function Products() {
  const [searchParams, setSearchParams] = useSearchParams();
  
  const category = searchParams.get('category') || 'all';
  const sort = searchParams.get('sort') || 'name';
  const page = searchParams.get('page') || '1';
  
  const handleCategoryChange = (newCategory: string) => {
    setSearchParams({ category: newCategory, sort, page });
  };
  
  // Users can bookmark this URL and return to exact state!
  return (
    <div>
      <select value={category} onChange={e => handleCategoryChange(e.target.value)}>
        <option value="all">All</option>
        <option value="electronics">Electronics</option>
      </select>
      {/* ... */}
    </div>
  );
}
// ❌ BAD: State only in React
// URL: /products (no context)

import { useState } from 'react';

function Products() {
  const [category, setCategory] = useState('all');
  
  // State is lost on refresh!
  // Can't share this view with others!
}

⚠️ When to Use URL vs Local State

Use URL for: Filters, search queries, pagination, sort order - anything users might want to bookmark or share.

Use local state for: UI-only state like modals, tooltips, form inputs (before submission).

7. Breadcrumb Navigation

Create breadcrumbs to help users understand their location:

import { Link, useLocation } from 'react-router-dom';

function Breadcrumbs() {
  const location = useLocation();
  
  const pathnames = location.pathname.split('/').filter(x => x);
  
  return (
    <nav className="breadcrumbs">
      <Link to="/">Home</Link>
      {pathnames.map((name, index) => {
        const routeTo = `/${pathnames.slice(0, index + 1).join('/')}`;
        const isLast = index === pathnames.length - 1;
        
        return isLast ? (
          <span key={routeTo}> / {name}</span>
        ) : (
          <span key={routeTo}>
            {' / '}
            <Link to={routeTo}>{name}</Link>
          </span>
        );
      })}
    </nav>
  );
}

// Usage: Renders "Home / blog / post-title" for /blog/post-title

Common Pitfalls to Avoid

⚠️ Don't Use <a> Tags

Always use <Link> or <NavLink> for internal navigation. Regular <a> tags cause full page reloads.

⚠️ Don't Forget the Wildcard Route

Always include a path="*" route for 404 handling. Place it last in your route definitions.

⚠️ Don't Nest BrowserRouter

Only wrap your app once with <BrowserRouter> at the top level. Don't add additional routers in child components.

⚠️ Don't Store Everything in URL

Not all state belongs in the URL. Keep form inputs, modal states, and temporary UI state in local component state.

Complete Example: Everything Together

Here's a complete, production-ready routing setup:

// src/main.tsx
import React from 'react';
import ReactDOM from 'react-dom/client';
import { BrowserRouter } from 'react-router-dom';
import App from './App';
import './index.css';

ReactDOM.createRoot(document.getElementById('root')!).render(
  <React.StrictMode>
    <BrowserRouter>
      <App />
    </BrowserRouter>
  </React.StrictMode>
);

// src/config/routes.ts
export const ROUTES = {
  HOME: '/',
  ABOUT: '/about',
  SERVICES: '/services',
  BLOG: '/blog',
  CONTACT: '/contact',
  NOT_FOUND: '*'
} as const;

// src/App.tsx
import React from 'react';
import { Routes, Route } from 'react-router-dom';
import { ROUTES } from './config/routes';
import Navbar from './components/Navbar';
import Footer from './components/Footer';
import ScrollToTop from './components/ScrollToTop';
import Home from './pages/Home';
import About from './pages/About';
import Services from './pages/Services';
import Blog from './pages/Blog';
import Contact from './pages/Contact';
import NotFound from './pages/NotFound';

function App() {
  return (
    <div className="app">
      <ScrollToTop />
      <Navbar />
      <main className="main-content">
        <Routes>
          <Route path={ROUTES.HOME} element={<Home />} />
          <Route path={ROUTES.ABOUT} element={<About />} />
          <Route path={ROUTES.SERVICES} element={<Services />} />
          <Route path={ROUTES.BLOG} element={<Blog />} />
          <Route path={ROUTES.CONTACT} element={<Contact />} />
          <Route path={ROUTES.NOT_FOUND} element={<NotFound />} />
        </Routes>
      </main>
      <Footer />
    </div>
  );
}

export default App;

Quick Reference: React Router Essentials

Component/Hook Purpose Example
BrowserRouter Wrap app for routing (declarative) <BrowserRouter><App /></BrowserRouter>
createBrowserRouter Build a router from a routes array (data router) createBrowserRouter([{ path: '/', element: <Home /> }])
RouterProvider Render a data router <RouterProvider router={router} />
Routes / Route Container for / definition of a route <Route path="/" element={<Home />} />
Link Navigate to a route <Link to="/about">About</Link>
NavLink Link with active state <NavLink to="/">Home</NavLink>
Outlet Render the matched child route <Outlet />
useParams Read typed URL parameters const { userId } = useParams<{ userId: string }>()
useNavigate Programmatic navigation navigate('/about')
