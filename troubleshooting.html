🔧 Troubleshooting

Stuck? Find the message you see, learn what usually causes it, and apply the fix that works on the course's stack.

🧭 How to Use This Page

Find your symptom (press Ctrl+F, or ⌘ Cmd+F on a Mac, and paste the first words of your error), read the likely causes, and try the fixes in order. Nearly every message quoted here was produced on purpose while the lessons were checked (Node.js 24, TypeScript 7.0, React 19.3, Vite 8.3, React Router 8.5, TanStack Query 5, Zod 4, Vitest 5, MSW 3, Playwright 1.65, Chromium); your file names, line numbers, paths and times will differ, and other browsers word some messages differently. Each problem links to the lesson that teaches the idea behind the fix.

✅ Before You Dig In

  • Is shoreline-api running? A terminal in shoreline/shoreline-api should show Shoreline Crew API running at http://localhost:4000/api. Open that address in a browser to prove it.
  • Are you in the right folder? App commands run in shoreline-hq, API commands in shoreline-api, Module 2's checks in ts-lab. Glance at the prompt before every command.
  • Is the browser's console open? F12 (⌘ Cmd+⌥ Option+I on a Mac), Console and Network tabs. Read the first red message, not the last.
  • Did you type-check? The dev server runs TypeScript without checking it. Run npx tsc -b (or npm run build) and npm run lint, and read the whole message, from the file and line at the top to the "expected type comes from" lines below.
  • Did you change .env.local or vite.config.ts? Stop npm run dev with Ctrl+C and start it again.
  • Did you change one thing at a time? Undo your last change and see whether the problem goes with it.

📁 "Could not read package.json"

You see: npm error enoent Could not read package.json: Error: ENOENT: no such file or directory, open '/Users/you/shoreline/package.json'

Cause: npm looks for package.json in the folder you are in, and you ran npm run dev in shoreline (the course folder) instead of shoreline-hq. The path line shows where npm looked.

Fix: cd shoreline-hq and run the command again.

Learn it: Lesson 1.2: Common Mistakes.

🪟 Windows: "running scripts is disabled on this system"

You see: PowerShell refuses to run npm with a message that npm.ps1 cannot be loaded because running scripts is disabled.

Cause: PowerShell's script policy, a Windows safety setting. Node and npm are installed fine.

Fix: use the Command Prompt instead of PowerShell, or allow scripts you run yourself: Set-ExecutionPolicy -Scope CurrentUser RemoteSigned.

Learn it: Lesson 1.2: Node.js.

🐢 ERR_UNKNOWN_FILE_EXTENSION ".ts" when starting the API

You see: TypeError [ERR_UNKNOWN_FILE_EXTENSION]: Unknown file extension ".ts" for /Users/you/shoreline/shoreline-api/server.ts

Cause: your Node.js is too old to run TypeScript files directly (Node 20 and 22.9 fail this way; shoreline-api needs Node 22.18 or newer, and the course uses the current LTS, 24 or newer). It can happen when an old version was installed earlier or a version manager is set to one.

Fix: install the current LTS from nodejs.org, open a new terminal, and check that node -v starts with v24 or more.

Learn it: Lesson 1.2: Common Mistakes · Lesson 1.2: Node.js.

🚪 "port 4000 is already in use"

You see: shoreline-api: port 4000 is already in use. Is the API already running in another terminal? Or start it with --port=4100

Cause: only one program can listen on a port, and another copy of the API is still running (often in a terminal you forgot).

Fix: use the copy that is already running, or stop it with Ctrl+C in its terminal first. To run a second copy on purpose, start it with node server.ts --port=4100 and point VITE_API_URL at it. The Vite dev server behaves more quietly: if port 5173 is taken it picks the next free port, so check its Local: line for the address it actually used.

Learn it: Lesson 1.2: Common Mistakes · Lesson 1.2: The Mock API.

📦 npx tsc asks to install a package named "tsc"

Cause: outside a project that has TypeScript installed, npx tsc offers to download the npm package named tsc, a deprecated old release (2.0.4), not today's TypeScript.

Fix: answer n. Run TypeScript from a folder whose package.json lists typescript (shoreline-hq and ts-lab both do), or install it there first with npm install --save-dev typescript.

Learn it: Lesson 2.1: The Workbench · Lesson 1.2: Checking Your Code.

⛔ error TS5112: tsconfig.json is present but will not be loaded

You see: error TS5112: tsconfig.json is present but will not be loaded if files are specified on commandline. Use '--ignoreConfig' to skip this error.

Cause: old tutorials say npx tsc scratch.ts. In a folder with a tsconfig.json, TypeScript 7 refuses, because naming a file would silently ignore your settings.

Fix: run the check with no file name: npm run check (or npx tsc --noEmit) in ts-lab, npx tsc -b in shoreline-hq. For a one-off check of a single file, add --ignoreConfig.

Learn it: Lesson 2.1: Common Mistakes.

🫥 The page loads (or is blank), but the code is wrong

  • The page shows up although the editor shows red: npm run dev and node file.ts run TypeScript by stripping the types, without checking them. "It shows up in the browser" only means Vite could serve it. Run npx tsc -b (or npm run build, which runs it) before you call a step finished.
  • A blank page on the dev server: open the console and read the first error, then run npx tsc -b for the clearer version of the same problem.
  • The app stops reaching the API, or localhost:5173 stops answering: closing a terminal (or VS Code) stops the server in it. Check that both terminals are still running their servers.

Learn it: Lesson 1.2: Common Mistakes · Lesson 1.2: Checking Your Code · Lesson 3.1.

🔐 "VITE_API_URL is not set" or "Property 'VITE_API_URL' does not exist on type 'ImportMetaEnv'"

  • Error: VITE_API_URL is not set: copy .env.example to .env.local (in the console, or the app's error page): the HQ's client.ts throws it when the variable is missing or empty. Copy .env.example to .env.local next to package.json (not in src/), make sure it says VITE_API_URL=http://localhost:4000, and restart npm run dev. In tests, vite.config.ts's test.env sets it.
  • error TS2339: Property 'VITE_API_URL' does not exist on type 'ImportMetaEnv'.: with strictImportMetaEnv on, every variable must be described. Declare it in src/vite-env.d.ts.
  • A variable without the VITE_ prefix is ignored by the front end. And no VITE_ variable is secret: every value ends up in the JavaScript that every visitor downloads.
  • The final project's starter throws the same message on npm run dev when you have no API: use npm run dev:demo, which answers from the in-app mock API.

Learn it: Lesson 2.4: Environment Variables · Lesson 9.2: Common Mistakes · Lesson 11.1: The Starter.

🧹 error TS5102: Option 'baseUrl' has been removed (and TS5108)

You see: error TS5102: Option 'baseUrl' has been removed. Please remove it from your configuration. followed by Use '"paths": {"*": ["./*"]}' instead.; or error TS5108: Option 'moduleResolution=node10' has been removed. Please remove it from your configuration. for "moduleResolution": "node" ("target": "es5" gets the same TS5108).

Cause: settings that older tutorials still recommend. TypeScript 7 removed them, and they are now errors.

Fix: delete baseUrl; if you want import aliases, write paths entries that start with ./, as the message suggests. For a Vite app, keep the template's "moduleResolution": "bundler" and es2023 target.

Learn it: Lesson 2.4: Common Mistakes · Lesson 2.4: tsconfig.

🔢 "TypeScript enum is not supported in strip-only mode" / TS1294

You see: from Node, SyntaxError [ERR_UNSUPPORTED_TYPESCRIPT_SYNTAX]: TypeScript enum is not supported in strip-only mode; in the HQ, error TS1294: This syntax is not allowed when 'erasableSyntaxOnly' is enabled.

Cause: code from an older tutorial: enum Status { Draft, Scheduled }. An enum is not just a type that can be stripped away (it creates an object), so Node refuses to run it and the HQ's settings refuse it too. The same goes for namespace and constructor parameter properties.

Fix: use a union of literal types, like EventStatus ('draft' | 'scheduled' | 'completed' | 'cancelled'): it does the same job and disappears completely when the code runs.

Learn it: Lesson 2.2: Common Mistakes · Lesson 2.2: Unions.

📥 TS1484 "must be imported using a type-only import", or "does not provide an export named"

You see: error TS1484: 'CleanupEvent' is a type and must be imported using a type-only import when 'verbatimModuleSyntax' is enabled., or when the file runs anyway, SyntaxError: The requested module './shapes.ts' does not provide an export named 'CleanupEvent'.

Cause: Node (and Vite) strip the types out of the other file, so at run time there is no CleanupEvent to import.

Fix: import types with import type { CleanupEvent } from './shapes.ts' (or import { type CleanupEvent, isCleanupEvent } when you also import values).

Learn it: Lesson 2.4: Modules.

❓ "'x' is possibly 'undefined'" (TS18048), "possibly 'null'" (TS18047), "Object is possibly 'undefined'" (TS2532)

Cause: the value may really be missing: an optional property, items[0] or a Record lookup under noUncheckedIndexedAccess, array.find(…), ref.current before React attached the element, or typeof x === 'object' without x !== null (because typeof null is 'object').

Fix: answer the question the error asks ("what if it is not there?") with ?., ?? or an if. Adding ! makes the error disappear and the crash stay. Use ??, not ||, when you mean "null or undefined": || also replaces a real 0 or empty string.

Learn it: Lesson 2.2: Handling null · Lesson 2.2: Common Mistakes · Lesson 2.4 · Lesson 4.3.

🧩 "Type '…' is not assignable to type '…'" (TS2322 / TS2345)

  • An object built first and typed later: const flats = { terrain: 'marsh' } infers terrain: string, and passing it where a Site is expected gives a three-level TS2345 ("Types of property 'terrain' are incompatible"). Annotate where you create it: const flats: Site = ….
  • Type 'string' is not assignable to type 'never' when adding to an empty array in state: useState([]) is a never[]. Give the type: useState<string[]>([]).
  • Type 'string' is not assignable to type 'StatusFilter' for a value from the address or a form: narrow it with a type predicate (readParam(…, isEventStatus)), never as.
  • A long message: read the first line (file, line, code) and then the last lines, where it says which property differs.

Learn it: Lesson 2.1: Reading Errors · Lesson 2.2 · Lesson 3.4 · Lesson 6.2.

🧬 Generics: "Property 'id' does not exist on type 'T'", TS1016, TS17008

  • error TS2339: Property 'id' does not exist on type 'T'.: the function has not said what T must have. Add a constraint (T extends { id: string }) rather than any or a !.
  • error TS1016: A required parameter cannot follow an optional parameter.: move the optional one to the end, give it a default, or collect the options in an object.
  • A generic arrow function in a .tsx file is read as a JSX tag: write <T,> (with the comma), or use a function declaration.

Learn it: Lesson 2.3: Constraints · Lesson 2.3: Common Mistakes.

↩️ TS2366 "Function lacks ending return statement", or "not assignable to parameter of type 'never'"

You see: error TS2366: Function lacks ending return statement and return type does not include 'undefined'., or from assertNever, Argument of type '…' is not assignable to parameter of type 'never'.

Cause: a union gained a member (a status, an action type) that one function does not handle yet. That is the error doing its job.

Fix: add the missing case. Avoid default: return state in a reducer: it compiles when a case is missing, so a new action silently does nothing. End with default: return assertNever(action).

Learn it: Lesson 2.3: Common Mistakes · Lesson 5.1: never.

💥 "Cannot read properties of undefined" in code that type-checked

You see: TypeError: Cannot read properties of undefined (reading 'toUpperCase'), far from the line that caused it.

Cause: an as told TypeScript what the data is, and nothing checked it: JSON.parse(…) as Volunteer, (await response.json()) as CleanupEvent[], or a lookup table written { … } as Record<EventStatus, string> that forgot two statuses.

Fix: check data from outside with a type guard (value is T); write tables with satisfies, which names what is missing (error TS2739: … is missing the following properties). Keep as for the rare case where you know more than the compiler, and say why in a comment.

Learn it: Lesson 2.4: Common Mistakes · Lesson 2.4: Type Predicates · Lesson 11.2: Common Mistakes.

📜 TS7016 "Could not find a declaration file for module"

You see: error TS7016: Could not find a declaration file for module 'marisol-tides'.

Cause: TypeScript found the package's JavaScript but no description of it, so everything from that import would be any.

Fix: look for a @types/ package first (npm install --save-dev @types/…). Otherwise write a small .d.ts that declares the functions you call, with real parameter types. The empty declare module 'marisol-tides'; the message suggests silences the error and every check with it.

Learn it: Lesson 11.2: Declaration Files.

🏷️ TSX: "cannot be used as a JSX component" (TS2786), HTML habits

  • error TS2786: 'SiteName' cannot be used as a JSX component. Its type '() => void' is not a valid JSX element type.: return sits on a line of its own, so the function returns nothing. Put return ( on the same line and the TSX inside the parentheses. npm run lint points at the cause with "Unreachable code".
  • Pasted HTML: class, for, unclosed <br> and <img>, lowercase attributes: TypeScript names each fix (className, htmlFor, <br />). An HTML comment is a syntax error in TSX: use {/* … */}.
  • "Objects are not valid as a React child" (a blank page): you put a whole object in the TSX. Show one of its properties.

📤 "does not provide an export named 'default'" (a blank page), TS2613

🎁 Props: "Type '{ name: string; }' is not assignable to type 'string'", missing children

  • Type '{ name: string; }' is not assignable to type 'string'. where the component is used: you wrote function SiteName(name: string). Props are one object; destructure: function SiteName({ name }: { name: string }).
  • Property 'children' does not exist on type 'IntrinsicAttributes & …': the component does not declare children. Add children: ReactNode to its props.
  • An empty space where the page should be: the layout takes children but never draws {children}.
  • Site pictures missing: they are served by shoreline-api. Keep it running.

Learn it: Lesson 3.2: Common Mistakes · Lesson 3.2: Children.

🔑 "Each child in a list should have a unique "key" prop", a stray 0, void[]

  • Each child in a list should have a unique "key" prop. Check the render method of `EventList`.: put key={item.id} on the element the map callback returns (not inside the item component).
  • Encountered two children with the same key, `scheduled`.: the key is not unique. Use the item's id. Index keys silence the warning without fixing anything on a list that changes.
  • A stray "0" on the page: count && … with a number draws the 0. Compare explicitly: count > 0 && ….
  • Type 'void[]' is not assignable to type 'ReactNode'. and an empty list: an arrow with braces and no return. Use (item) => (<li …>) or write return.

Learn it: Lesson 3.3: Keys · Lesson 3.3: Common Mistakes.

🔁 "Too many re-renders", a field that ignores typing, a screen that doesn't update

  • Too many re-renders. React limits the number of renders to prevent an infinite loop. (and TS2322 Type 'void' is not assignable to type 'MouseEventHandler…'): onClick={setOpen(!open)} calls the setter while drawing. Pass a function: onClick={() => setOpen(!open)}.
  • You provided a `value` prop to a form field without an `onChange` handler. and the field ignores every keystroke: add onChange, or use defaultValue for an uncontrolled field.
  • Nothing redraws after a change: savedIds.push(id) then setSavedIds(savedIds) hands React the same array. Make a new one: setSavedIds([...savedIds, id]).
  • A date one day early: new Date('2026-07-04') is midnight UTC, still the day before on the US west coast. Add a time (`${date}T00:00`) to get local midnight, as the HQ's formatDate does.

Learn it: Lesson 3.4: Common Mistakes · Lesson 3.4: Updating State.

📝 Form actions: "Cannot read properties of null (reading 'trim')", a field that is always empty

  • Cannot read properties of null (reading 'trim'): formData.get('title') as string was null, because no field has that name. Narrow with typeof value === 'string' instead of as.
  • A field that is "always empty" ("Add a title." for a title you typed): FormData only collects fields with a name; an id is not enough. Check the name first.
  • The form loses what was typed after a failed check: React resets a form after its action. Give each field defaultValue from the submitted values. A <select> still jumps back to its first option in React 19.3: give it key={values.siteId}.
  • error TS2769: No overload matches this call. on useActionState: an action for useActionState takes (previousState, formData), in that order.
  • A button that submits by accident: inside a <form>, a button without a type submits. Give it type="button".

Learn it: Lesson 3.5: Form Actions · Lesson 3.5: Common Mistakes.

🎨 CSS Modules: lost styles, class="undefined …", "Cannot find name 'link'"

  • A component lost its styles after moving its CSS: a leftover className="badge badge-info" string has no rule behind it any more. Search the project for className=" after the move.
  • class="undefined _info_1nzko_9" in the Elements panel: a misspelled module class (styles.ntoe) is undefined, and a template literal turns it into the text "undefined". Check the class name in the .module.css file.
  • error TS2339: Property 'card' does not exist on type 'typeof import("*.css")'.: the file is Card.css, not Card.module.css. Only *.module.css files are CSS Modules.
  • error TS2304: Cannot find name 'link'. (with TS18048 and more) from styles.skip-link: JavaScript reads it as a subtraction. Use camelCase class names (.skipLink).

📌 Refs and focus: "Cannot access refs during render", TS2554 on useRef, TS2769 on addEventListener

  • ⚠ react(refs): Cannot access refs during render: the screen shows a ref's value. If the screen shows it, it is state.
  • error TS2554: Expected 1 arguments, but got 0. on useRef(): React 19's types need the starting value: useRef<number | null>(null).
  • TS2322 on a callback ref written as (el) => (refs.current[i] = el): an arrow without braces returns the assignment, and a callback ref may only return nothing or a cleanup function. Use braces: (el) => { refs.current[i] = el }.
  • error TS2769: No overload matches this call. on document.addEventListener('keydown', …): VS Code imported KeyboardEvent from 'react'. Remove the import; the browser's global KeyboardEvent is the right one there.
  • Focus jumps to the top of the page after a button disappears or a dialog closes: decide where focus goes next (a neighbor, a heading, the opener) and move it there.

🧮 Reducers: nothing changes after dispatch, "Property 'set' does not exist on type 'ReadonlyMap'"

  • error TS2339: Property 'set' does not exist on type 'ReadonlyMap<…>'.: you tried to change the state in place. With a plain Map type it compiles and the screen does not update, because the reducer returned the same object. Copy first (new Map(old), [...list, item]), then change the copy.
  • TS2344 "does not satisfy the constraint 'AnyActionArg'": useReducer type arguments from older React. Type the reducer function and let useReducer infer the rest.
  • A side effect in the reducer runs twice in development: Strict Mode calls reducers twice to flush out impure ones. Do requests and timers in the event handler; give the reducer only results.

🌐 Context: a blank page and "useAuth() must be used inside <AuthProvider>", Fast Refresh warnings

  • A blank page and useAuth() must be used inside <AuthProvider> in the console: the provider is missing above a component that reads the context. TypeScript cannot see this. Put <AuthProvider> back around everything that reads it.

🔌 "Failed to fetch" or ERR_CONNECTION_REFUSED: the API is not running

You see: in the HQ, Could not load the beach sites. Could not reach the server. Check that shoreline-api is running, then try again.; in the console, Failed to load resource: net::ERR_CONNECTION_REFUSED and TypeError: Failed to fetch.

  1. Start the API: a second terminal in shoreline-api, node server.ts, and keep it open while you work.
  2. Check the address: VITE_API_URL in .env.local should say http://localhost:4000 (no /api, no slash at the end). Restart npm run dev after changing it.
  3. "Loading…" that never ends, with no error: on the Windows + WSL machine the course was checked on, connecting to a localhost port where nothing listened sometimes hung (Node reported a ConnectTimeoutError after a long wait) instead of failing at once with "refused". Treat a request that just waits as "is the API running?" first.

Learn it: Lesson 4.1: Loading, Error and Empty · Lesson 2.4 · Lesson 9.3 (Playwright waiting on a closed port).

🚧 "blocked by CORS policy", or X-Total-Count is null

  • "blocked by CORS policy" in the console: shoreline-api lets any http://localhost:… or http://127.0.0.1:… page read its answers. A deployed site must be named when you start the API: node server.ts --cors=https://your-site.netlify.app (comma-separated, or *). CORS is enforced by the browser, which is why the same request works in curl or in a test. A crash or a wrong address can also look like a CORS problem: check that the API runs.
  • response.headers.get('X-Total-Count') returns null although the Network tab shows the header: a page on another origin (localhost:5173 asking localhost:4000) can only read headers the server lists in Access-Control-Expose-Headers. shoreline-api lists X-Total-Count, X-Total-Pages, Link and Location; a server you write yourself must do the same.

Learn it: Lesson 4.1 · Lesson 10.2 · API reference.

Cause: a practice switch is still on: ?_status=500 left in an address in client.ts, or the API started with --fail-rate (and --latency makes everything slow).

♾️ Effects: endless requests, every request twice, missing dependencies

  • Every request twice in development (one canceled): Strict Mode runs effects twice to prove the cleanup works. Not a bug; production runs them once.
  • Hundreds of requests in the Network tab: an effect with no dependency array runs after every render. Every effect gets an array, even []. A function that is new on every render in the array does the same: read it through useEffectEvent.
  • ⚠ react-hooks(exhaustive-deps): React Hook useEffect has a missing dependency: 'siteId': the effect never runs again when that value changes. Put it in the array.
  • Functions returned from `useEffectEvent` must not be included in the dependency array.: remove it; put the values that should trigger a reload (the key) in the array.
  • ⚠ react(set-state-in-effect): Calling setState synchronously within an effect can trigger cascading renders: start in the right state (useState({ kind: 'loading' })) and set "loading" again in the click handler that retries.
  • "Effect callbacks are synchronous" / TS2345 about EffectCallback: an async effect returns a promise, not a cleanup. Define an async function inside the effect and call it.

Learn it: Lesson 4.1: Dependencies · Lesson 4.1: Common Mistakes · Lesson 4.2: Common Mistakes.

🪝 Rules of Hooks: "is called conditionally", "is called in function … that is neither"

  • × react-hooks(rules-of-hooks): React Hook "useState" is called conditionally.: a Hook after an early return. Move the Hook above the if; in your own Hook, put the condition inside the effect.
  • React Hook "useEffect" is called in function "setTabTitle" that is neither a React function component nor a custom React Hook function.: a function that calls Hooks must be a component (capitalized) or a Hook (named use…).

⏳ Suspense and error boundaries: "Loading…" forever, a boundary that catches nothing
