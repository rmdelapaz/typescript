Lesson

7.1

TanStack Query

By the end you can
  • Explain what server state is, and what a cache adds to fetching it
  • Set up a QueryClient and write typed queryOptions factories with keys that include everything the answer depends on
  • Read a query's result with useQuery, narrowing it with isSuccess, and keep the last list on screen with placeholderData
  • Choose staleTime and retry settings and explain the requests they cause
  • Fill the cache from route loaders and read it with useSuspenseQuery, with a Try again that really tries again
Key ideas
  • Server state is borrowed: the API owns cleanups, sites and the crew; the HQ holds a copy that ages. Client state (a dialog, the search text, the undo history) belongs to the browser.
  • The logbook: a QueryClient (the cache) keeps each answer under a query key; a query function fetches it (with an AbortSignal). Equal keys share one entry and one request.
  • The key rule: the key holds everything the answer depends on (filters, page, who asks), general to specific, the viewer last: ['events', 'list', search, viewer]. Then ['events'] reaches every list and detail.
  • queryOptions factories keep key and function together and carry the data type to every Hook and loader: no type arguments.
  • A result is a union tagged by status: pending / error / success. isSuccess narrows data; isFetching is a separate question (a background refresh). placeholderData: keepPreviousData keeps the last list while a new key loads.
  • Fresh, stale, retried: staleTime (the HQ: 30 s) decides when to ask again; gcTime (5 min) when to forget; retry which failures deserve another try (never a 4xx). Loaders: queryClient.query({ ...q, staleTime: 'static' }), pages: useSuspenseQuery, boundaries: onRetry={reset}.
Worked example: what the query Hooks give back

The lesson's Scratch.tsx, which hands each query result to a function that wants a number:

import { useQuery, useSuspenseQuery } from '@tanstack/react-query'
import { eventQuery, eventsQuery } from './api/queries.ts'

// What do the query Hooks give back? Hand each result to a function that wants a number.
function show(value: number) {
  return value
}

export function Scratch() {
  const list = useQuery(eventsQuery('perPage=50', 'guest'))
  const cleanup = useSuspenseQuery(eventQuery('e08', 'guest'))
  show(list.data)
  show(cleanup.data)
  if (list.isSuccess) {
    show(list.data)
  }
  return null
}

Glossary

TermMeaning
server state / client stateData the API owns and the app copies / data only this browser knows
TanStack QueryThe library that keeps server state in a shared cache (many people still call it React Query)
QueryClientThe cache itself, created once outside React; QueryClientProvider hands it to every component
query keyAn array that labels a cache entry; it holds everything the answer depends on
query functionThe function that fetches an entry; it gets a signal that is aborted when nobody needs the answer
queryOptionsPuts a key and a function together and keeps their types (the HQ's factories)
useQueryReads a query in a component: a result tagged by status (pending, error, success)
isFetchingA request is running right now (also during a background refresh of good data)
placeholderData: keepPreviousDataKeep the last answer on screen while a new key loads; isPlaceholderData says so
fresh / stale, staleTimeYoung enough to use without asking / shown but refetched; the time that separates them
gcTimeHow long an unused entry stays in memory (was cacheTime in version 4)
retryWhich failures to try again, and how often (the HQ: never 4xx, at most 2 more)
useSuspenseQueryReads a query and suspends until there is data: its data is never undefined
queryClient.queryFills (or reads) an entry from outside a component; with staleTime: 'static' any cached copy counts
useQueryErrorResetBoundaryGives reset, which lets queries below an error boundary try again
indexed access typeImpactTotals['byMonth'][number]: the type of one item of a property's array
