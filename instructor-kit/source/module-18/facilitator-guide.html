The four refresher questions, with answers
  1. **R1.** Lesson 4.1's LoadState had three kinds. Name them, and say what TypeScript lets you read in each. **Answer:** loading (nothing), error (the message or error), ready (the data). A switch or an if on kind narrows the union; TanStack Query's result is the same idea with status as its tag.
  2. **R2.** useApi(key, load) from Lesson 4.2: what was the key for, and what happened when it changed? **Answer:** It said what the answer depends on; a new key started a new request (and kept the old data while it loaded). Today's query keys are that idea, shared across components.
  3. **R3.** A guest opens /volunteers. What runs first, and what do they see? **Answer:** The organizersOnly guard loader (Lesson 6.3) throws a redirect to /sign-in?next=%2Fvolunteers before any request; after signing in they land back on the crew list.
  4. **R4.** Why does the events page have no loader, when the sites page does? **Answer:** Its search box changes the address on every letter; a loader on that route breaks typing (Lesson 6.3 measured the caret jumping). The cache gives it the loader's benefits today.

    shoreline-hq/src/api/queries.ts
    export const queryClient = new QueryClient({
  defaultOptions: {
    queries: {
      // An answer counts as fresh for 30 seconds: no new request for it in that time
      staleTime: 30_000,
      // Try again after a network or server failure, but never after 401, 403 or 404:
      // asking again will not change those answers
      retry: (failureCount, error) =>
        !(error instanceof ApiError && error.status < 500) && failureCount < 2,
    },
  },
})
    "The retry function gets the error typed as Error; instanceof ApiError narrows it so we can read status."

Three mistakes to expect, and how to coach each
  • A key that leaves something out. It compiles, lints and "works" until the second search or the second person. Coach: "read the query function: is every variable it uses in the key?" (Lab 7.1 Task 1; self-check Items 2 and 10.)
  • Reading data without narrowing. events.data.items underlined: "Object is possibly undefined". Coach: "which status has data?" An early return on !isSuccess or a check (Item 3).
  • Copying a v4 tutorial. TS2769 on cacheTime or keepPreviousData: true. Coach: read the message from the bottom to the property name, then the renames table (Item 7).

Checks for understanding

Ask these out loud during the demos and the lab:

  • What goes in a key? Answer: everything the answer depends on (filters, page, who asks), general to specific.
