Session 17: Part 2 Project Check-in and Assessment

How to run Session 17, the close of Part 2: a check-in on the Basalt Peak Climbing Gym project with short rubric conversations, the Part 2 assessment (written, closed book, 20 points, 14 to meet), three-minute project demos with peer feedback, and a review that bridges to Part 3 or closes the course when Part 2 runs alone.

How to Use This Guide

  • Session 17 teaches no new lesson. It closes Part 2 with three things: a check-in on the Part 2 project (Basalt Peak Routes for the Basalt Peak Climbing Gym: studio time with short rubric conversations), the Part 2 assessment (written, 45 minutes, closed book), and demos. When Part 2 runs as a course of its own, it is also the last session: the review block then closes the course.
  • The assessment and the rubric are defined once (the kit's final-assessment.html, Part 2 section, and labs/projects/part2-basalt-peak-routes/RUBRIC.md); this guide says how to run them. Part 2 met = the Basalt Peak Routes project complete under its rubric (no row at 0) AND the Part 2 assessment met (14 or more of 20 points, 70 %).
  • Every output quoted here is real: the review and assessment snippets checked by npx tsc -b in a copy of Shoreline Crew HQ at the end of Lesson 6.3 (each message is the one the lessons print), the project run by the kit's lab checker.
  • Teal blocks are hands-on, amber blocks are watch-outs. Lesson codes match the course site.
The #1 risk of Session 17: the assessment loses its conditions

The Part 2 assessment is written and closed book: laptops closed, phones and chat assistants away, no notes. A learner with the course app open is no longer being assessed, and the result says nothing about Part 2. Before: print the question paper (the workbook's assessment pages) one per learner, single-sided, and keep them until the break. In the room: at the break, laptops closed and bags on the floor; walk the room once. A learner who arrives late gets the remaining time, not more; a learner who misses the session takes it at an agreed time with the same paper. Demos run long: three minutes on a timer, questions only from the rubric.

Before the Session

  • ☐ Run the kit check once: python3 labs/check_labs.py projects/part2-basalt-peak-routes (8 runs): the starter's tests fail with TODO messages, the model passes the tests, tsc -b, the linter (0 warnings) and the build, and the gym's API answers the smoke test.
  • ☐ Print: the workbook's assessment pages (one per learner), the scoring sheet (final-assessment.html, Part 2 section), RUBRIC.md for each learner, sticky notes for the exit ticket.
  • ☐ Projector machine: the model solution running (npm run api and npm run dev in two terminals) for the review block, signed out; a 45-minute timer; lesson_23.html for the closing screenshots.
  • ☐ Demo order: a list of learners in groups of the room's size; a peer reviewer for each demo (the next person on the list).
  • ☐ Board, before learners arrive: the agenda; the assessment rules (45 minutes, closed book, 20 points, 14 to meet); the demo script (one route from the address to the screen; the protected page as a guest, a staff member and a setter; one decision you made).

The five-minute check-in (per learner or pair)
  1. "Show me npm test and npx tsc -b." (Where on the TODO list are they? Routing and the data layer, R1 and R2, should be done or close.)
  2. "Which rubric row are you proudest of, and which one worries you?" Read that row with them.
  3. "Open /setter signed out, then as Sam (staff), then as Dana (setter)." (R4, rehearsed for the demo.)
  4. One concrete next step, written in their workbook's check-in box. Nothing more: the hand-in is a week away.
Common problems and the nudge
  • Every test fails at first, and early tests name an earlier TODO. A test that needs /routes fails with TODO R1 until the route exists: work R1 to R5 in order and read the failure's TODO, not only its name.
  • A blank page or Unexpected Application Error!: a loader or a component threw outside the pathless errorElement route (the layout itself crashed, often useAuth() outside AuthProvider). Ask: which route does the error bubble to?
  • isClimbRoute returns true for anything: a check written as typeof value === 'object' alone. The R2 client test sends a wrong-shaped answer; it must be refused.
  • The 404 shows Something went wrong instead of Route not found: the loader rethrows the ApiError instead of throw data(message, { status: 404, statusText: 'Route not found' }).
  • Filters lost on Back, or a select that cannot be cleared: the filter is in useState, or withParam changes the URLSearchParams it was given instead of a copy (new URLSearchParams(params)).
  • ?next= comes back as %2Fsetter or goes off-site: encodeURIComponent when the guard builds the address; nextPath reads it with searchParams.get (already decoded) and keeps only a path that starts with one /.
  • Staff reach the form: the guard checks only session !== null. The role decides; and the API's own 403 is the second lock.
  • The form forgets what was typed after a refusal, or the messages stay after a fix: the failed case replaces values, or the field case keeps the old message for that field.

Part 2 Assessment

A2

Part 2 Assessment

45 min
Rules (say them before you start)
  • Written, closed book, 45 minutes, 20 points: 14 multiple-choice items (1 point each; circle one letter) and 3 short-answer / code-reading items (2 points each; a sentence or two and a line of code). Laptops closed, phones and chat assistants away, no notes.
  • 14 or more of 20 (70 %) = the Part 2 assessment met. Part 2 met = the Basalt Peak Routes project complete under its rubric (no row at 0) AND the Part 2 assessment met (14 or more of 20 points, 70 %).
  • Questions during the assessment: only about a question's wording, never about the content.
  • Below the line is not the end: one retake at a time you agree, on the items that fell short (write new items on the same lessons; the review items are a good source).

Pacing
  • Minute 0: hand out the paper face down; say the rules; start the timer.
  • Minute 30: "Fifteen minutes left: make sure the three short items have an answer." The short items are worth 6 of the 20 points.
  • Minute 45: pens down, papers collected. Mark after the session: the multiple choice with the key line above, the short items with the marking notes.
Watch-outs
  • A learner finishes in fifteen minutes. Ask them to read A15 to A17 again: each needs a reason AND a fix.
  • Someone asks what an error code means. That is the question: point them back to the message text, which is on the paper.
  • Marking the short items. Half marks do not exist: each item has two 1-point halves, both listed in the marking notes. Write the missing half next to a 1.

Project Demos

Protocol

If You Run Long or Short

Running long
  • Protect: the assessment's 45 minutes; the check-in conversations.
  • Cut first (saves 8m): the warm-up's map becomes homework; keep the three questions.
  • Cut second (saves 10m): demos in groups of four with peers scoring; you collect the peer boxes.
Running short
  • Self-check items 4 and 12 live: tsc's message on the projector, the room proposes the fix, then run it.
  • A keyboard pass through two volunteers' projects on the projector: the filters, the sign-in form, the setter form's errors.
