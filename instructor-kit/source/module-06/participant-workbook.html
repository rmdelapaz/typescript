Lessons

3.3

Lists and Conditional Rendering

By the end you can
  • Turn an array into elements with map, filtering and ordering it first without changing the original
  • Explain what a key does, choose a stable one from the data, and read React's key warnings
  • Show parts of a component only when they apply with if and early returns, ? :, && and null, and avoid the 0 trap
  • Give every value of a union a label with a Record lookup table that TypeScript keeps complete
  • Let a discriminated union decide what a component draws, with TypeScript narrowing each case
  • Build the HQ's events page from a typed CleanupEvent[] with EventList, EventCard, StatusBadge and SpotsLine, including an empty state
Key ideas
  • map turns data into elements; filter, toSorted and toReversed shape the list first and return NEW arrays (sort and reverse change the original).
  • A key is a name tag: from the data (event.id), unique among siblings, stable, on the element map returns. Index keys silence the warning without fixing anything once rows have state.
  • Four conditional tools: if + early return (the whole component), ? : (one of two things), && with a REAL boolean (length > 0, never a bare number: 0 draws), null (draw nothing).
  • Record<Union, T> lookup tables are exhaustive: TS2741 for a missing key, TS2561 for a misspelled one; lookups are never undefined. Record<string, T> checks nothing and every lookup may be undefined (TS2532).
  • A discriminated union on kind lets a switch draw each case with that case's data (TypeScript narrows in each case). A switch with a missing case still compiles (Lesson 5.1 fixes that).
  • An empty list deserves a sentence, not a blank space.

3.4

State and Events

By the end you can
  • Explain why a plain variable cannot remember anything between renders, and give a component state with useState
  • Handle clicks, typing and menu changes with typed event handlers such as ChangeEvent<HTMLInputElement>, and pass a function instead of calling it
  • Choose when useState<T> needs a type argument: unions, empty arrays and "nothing yet" values
  • Update state from a snapshot or with an updater function, and copy objects and arrays instead of changing them
  • Lift shared state to the closest common parent, pass it down as props with callback props for changes, and derive everything else
  • Add search, a status filter and per-card details to the HQ's events page, plus readable dates with a formatDate helper
Key ideas
  • Local variables last one render. const [value, setValue] = useState(initial) keeps a value between renders; calling the setter stores the new value and schedules a re-render. Hooks run at the top level, in the same order every render.
  • Event props take a function: onClick={() => setOpen(true)}, never onClick={setOpen(true)}. Inline handlers are typed by the prop; named ones take ChangeEvent<HTMLInputElement> (or HTMLSelectElement, MouseEvent<HTMLButtonElement>...).
  • useState needs a type argument for a union (useState<StatusFilter>('all')), an empty array (useState<string[]>([])) and nothing-yet (useState<CleanupEvent | null>(null)).
  • Each render sees a snapshot: use an updater when the new value depends on the old one (setCount((c) => c + 1)); make NEW arrays and objects ([...ids, id], filter, { ...filters, query }).
  • Lift state to the closest common parent; pass values down and changes up with callback props (a controlled component). Derive whatever can be computed: stored copies fall a keystroke behind.
  • A select hands over a string: narrow it with a type guard (isEventStatus) before passing it up, no as.

Glossary

TermMeaning
keyReact's name tag for an item in a list: from the data, unique among siblings, stable
early returnif (...) return ... at the top of a component: draw something else and stop
the 0 trapcount && <p/> draws a 0 when count is 0; compare explicitly: count > 0 &&
lookup tableAn object with one entry per value of a union: Record<Terrain, string>
exhaustiveEvery possible value handled, checked by the compiler
discriminated unionA union whose members share a property (kind) with a different word in each
stateData React keeps for a component between renders (useState)
HookA function whose name starts with use, called at the top level of a component
setter, updaterThe function useState returns to change the state; a function passed to it: (current) => current + 1
snapshotThe state value for ONE render; the setter does not change it, it asks for a new render
ChangeEvent<T>React's type for a change event on element T (HTMLInputElement, HTMLSelectElement)
controlled componentA component that shows the value it is given and reports changes through callbacks
lifting state upMoving state to the closest common parent of everything that reads or changes it
derived valueWorked out from state and props during render, never stored
