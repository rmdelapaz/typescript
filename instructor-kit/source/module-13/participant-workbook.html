Lesson

5.2

Typed Context

By the end you can
  • Explain prop drilling, and decide when a value belongs in context and when a plain prop is clearer
  • Create a typed context with createContext, provide it with React 19's <Context value>, and read it with useContext
  • Avoid the "undefined context" trap: type the context as T | undefined and write a useAuth() Hook that fails loudly outside its provider and never returns undefined
  • Sign in against a real API with roles, keep the session in sessionStorage, and send the token with every request
  • Make data depend on who is asking: drafts, organizer-only buttons and a live roster that load again when someone signs in or out
Key ideas
  • Prop drilling = passing a value through components that only hand it on. Context sends one value to every component below a provider, wherever it sits: for values many distant components need and that change rarely. A direct child still gets a prop.
  • Three parts: createContext<T>(default); <SomeContext value={…}> (React 19; .Provider is the older spelling); useContext(SomeContext) reads the NEAREST provider above, or the default when there is none. When the value changes, every reader renders again.
  • The undefined trap: a fake default compiles and fails silently. When no default makes sense, type the context T | undefined with undefined as the default, and read it only through a Hook (useAuth()) that throws outside the provider and returns T.
  • Two files: the context, its type and its Hook in a .ts; the provider component in a .tsx (Fast Refresh and oxlint's only-export-components).
  • The session: sign-in = POST /api/auth/sign-in → a token and the user (role organizer or volunteer); sessionStorage (survives reloads, one tab), checked like API data on the way in, written only by the provider, sent as Authorization: Bearer … with every request.
  • Who asks is part of the question: the same URL answers 15 cleanups to a guest and 17 to an organizer, so useApi and caches key their data by the viewer. Hiding a button is convenience; the API decides (403).
Worked example: the type that tells the truth

The HQ's context says the truth: outside a provider there is no sign-in, so its type is AuthValue | undefined. A component in src/Scratch.tsx that reads it directly:

import { useContext } from 'react'
import { AuthContext } from './auth/AuthContext.ts'

export function OrganizerNote() {
  const { isOrganizer } = useContext(AuthContext)
  return isOrganizer ? <p>Drafts are listed below.</p> : null
}
npx tsc -b
src/Scratch.tsx:5:11 - error TS2339: Property 'isOrganizer' does not exist on type 'AuthValue | undefined'.

5   const { isOrganizer } = useContext(AuthContext)
            ~~~~~~~~~~~


Found 1 error in src/Scratch.tsx:5

"Does not exist on type AuthValue | undefined" means: this might be undefined, and undefined has no isOrganizer. Instead of ?. in every component, the project checks once, in a Hook:

shoreline-hq/src/auth/AuthContext.ts
// undefined is the value outside an AuthProvider: a mistake that useAuth() reports at once
export const AuthContext = createContext<AuthValue | undefined>(undefined)

/** The sign-in state. Only works inside <AuthProvider>. */
export function useAuth(): AuthValue {
  const auth = useContext(AuthContext)
  if (auth === undefined) {
    throw new Error('useAuth() must be used inside <AuthProvider>')
  }
  return auth
}

After the if, auth is an AuthValue, so every caller of useAuth() gets one. A missing provider is now a blank page with a console message that says exactly what to fix, instead of a sign-in button that silently does nothing.

Glossary

TermMeaning
prop drillingPassing a value down through components that do not use it, only to reach one that does
contextA value React sends to every component below a provider, whatever sits in between
createContext<T>(default)Makes a context object; the default is what a component gets with no provider above it
provider<SomeContext value={…}> (React 19): gives the value to the part of the tree inside it
useContextReads the value of the NEAREST provider above the component
the undefined trapA fake default that compiles and turns a missing provider into a silent bug
useAuth()The HQ's custom Hook: reads AuthContext, throws outside AuthProvider, returns AuthValue
Fast RefreshVite's update-in-place on save; keeps state only for files that export components only
session, tokenWho is signed in (the API's answer) / the opaque string that proves it on every request
Authorization: Bearer …The request header that carries the token
sessionStorageBrowser storage that survives reloads, belongs to one tab and ends when the tab closes
401 / 403Not signed in (or the sign-in ended) / signed in, but not allowed
RequestInitThe type of fetch's options object (method, headers, body, signal…)
weak typeA type whose properties are all optional; TypeScript wants at least one property in common
