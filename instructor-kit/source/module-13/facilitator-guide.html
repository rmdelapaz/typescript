Questions and answers
  1. EventDetails reads the cleanup with use(). Why does it go through eventPromises.ts instead of calling getEvent(id) itself? use() needs the SAME promise on every render; a new getEvent() call would suspend again and start over. The module keeps one promise per cleanup.
  2. On the event page, what does the ErrorBoundary catch that the Suspense boundary does not? A rejected promise (or any error while rendering): Suspense only shows a fallback while the promise is pending; the boundary shows EventProblem when it fails (404 → Cleanup not found).
  3. The desk dispatches { type: 'checkIn', signupId } for a row that is already marked attended. What should the reducer return, and why? The SAME state object: nothing changed, so React can skip the render, and Undo gets no empty step.
  4. What does assertNever(value: never) in a switch's default give you? A compile error the day someone adds an action or a union member without a case, and a loud error if an unexpected value arrives at run time.
Watch-outs
  • W1 is the bridge to today. Today's project changes eventPromise(id) to eventPromise(id, viewer): a guest's cached 404 for a draft must not be served to the organizer who signs in next. Plant it now: "remember: one promise per cleanup. Today, per cleanup AND per person."

Typed Context

Objectives (from the lesson page)

Mental model to say

Draw the tree from the board and ask: "EventCard needs to know whether an organizer is signed in. How does the answer get there with props?" Trace it: EventsPage → EventGroups → EventList → EventCard. "Two of those three never use it; they only hand it on. That is prop drilling. And UserMenu, in the header, needs the same answer through a completely different chain."

Then the lesson's picture: "Passing a message along a line of volunteers works for two or three people. For the whole beach, the crew lead uses the radio: one broadcast on a known channel, and anyone with a radio tuned to it hears the message, wherever they stand. A context is that channel; the provider is the transmitter, and it only reaches the part of the tree inside it; every component that calls useContext is a radio, and it hears the nearest transmitter above it."

Then the limit, before anyone overuses it: "Props are explicit: you read a component's interface and see what it needs. Context is for values many components at different depths need, and that change rarely: who is signed in, a chosen unit or language, a reducer's dispatch. EventGroups, one level down, still gets showDrafts as a prop."

Point at the three parts as you type them: create (createContext<WeightUnit>('kg'), the default for components with no provider), provide (<WeightUnitContext value={unit}>, React 19's spelling), read (useContext, typed from the context). 
    import { createContext, useContext, useState } from 'react'

type WeightUnit = 'kg' | 'lb'

// The default ('kg') is what components get when no provider is above them
const WeightUnitContext = createContext<WeightUnit>('kg')

function BagWeight({ kg }: { kg: number }) {
  const unit = useContext(WeightUnitContext)
  return <strong>{unit === 'kg' ? `${kg} kg` : `${Math.round(kg * 2.2)} lb`}</strong>
}

// Knows nothing about units: no prop passes through it
function DayTotal() {
  return <p>Collected today: <BagWeight kg={42} /></p>
}

export function UnitsDemo() {
  const [unit, setUnit] = useState<WeightUnit>('kg')

  return (
    <>
      <WeightUnitContext value={unit}>
        <button type="button" onClick={() => setUnit(unit === 'kg' ? 'lb' : 'kg')}>
          Show {unit === 'kg' ? 'pounds' : 'kilograms'}
        </button>
        <DayTotal />
      </WeightUnitContext>
      <DayTotal />
    </>
  )
}

Checks for understanding

Ask these out loud during the demo, the lab and the project:

  • When does a value belong in context, and when is a prop better? Answer: context for values many components at different depths need and that change rarely; a prop for a direct child (it is explicit).
  • What does a component get from useContext when no provider is above it? Answer: the context's default (for AuthContext: undefined, which useAuth() turns into a loud error).
  • Why sessionStorage and not React state alone? Answer: until Lesson 6.1 every link reloads the page; sessionStorage survives reloads, stays in one tab and ends when the tab closes.
  • Hiding the Cancel button from volunteers: is that security? Answer: no; the API enforces the rules (a volunteer's token gets 403 on the roster).
