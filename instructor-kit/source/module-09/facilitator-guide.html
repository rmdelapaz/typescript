Session 9: Part 1 Project Check-in and Assessment

How to run Session 9, the close of Part 1: a check-in on the Juniper Hill Community Garden project with short rubric conversations, the Part 1 assessment (a written part and a practical, 20 points, 14 to meet), three-minute project demos with peer feedback, and a review that bridges to Part 2 or closes the course when Part 1 runs alone.

0 new lessons 3 hrs session Review of Lessons 1.1–3.6 Session 9 of 26 · Part 1

How to Use This Guide

  • Session 9 teaches no new lesson. It closes Part 1 with three things: a check-in on the Part 1 project (studio time with short rubric conversations), the Part 1 assessment (a written part and a practical), and demos. When Part 1 runs as a course of its own, it is also the last session: the review block then closes the course.
  • The assessment and the rubric are defined once (the kit's final-assessment.html, Part 1 section, and labs/projects/part1-juniper-hill-garden/RUBRIC.md); this guide says how to run them. Part 1 met = the Plot Board project complete under its rubric (no row at 0) AND the Part 1 assessment met (14 or more of 20 points, 70 %).
  • Every output quoted here is real: the review snippets checked by tsc in a copy of the project's model solution (strict, like the course app), the practical and the project run by the kit's lab checker.
  • Teal blocks are hands-on, amber blocks are watch-outs. Lesson codes match the course site.
The #1 risk of Session 9: the assessment loses its conditions

The practical is open book but not open chat: a learner with an assistant in another window is no longer being assessed, and the result says nothing about Part 1. Neither is a practical that starts with ten minutes of npm install on venue Wi-Fi. Before: the practical's starter installed at home (Session 8's bring list; run npm test once: five TODO failures). In the room: at the break, ask everyone to close chat assistants and messaging, keep only the lesson pages, their own code and MDN open; walk the room once during the practical. A learner without a working install pairs with you for the written part's second half and takes the practical at the next opportunity. Demos run long: three minutes on a timer, questions only from the rubric.

Before the Session

  • ☐ Run the kit check once: python3 labs/check_labs.py module-09 and python3 labs/check_labs.py projects/part1-juniper-hill-garden (9 runs): the practical's starter fails its five tests, its solution passes them and tsc; the project's model passes the tests, tsc, lint and the build.
  • ☐ Print or share: the workbook's assessment pages (the written part is on paper: closed book), the scoring sheet (final-assessment.html, Part 1 section), RUBRIC.md for each learner, sticky notes for the exit ticket.
  • ☐ Projector machine: the practical's TASKS.md; a 15-minute and a 30-minute timer; the model solution of the project running (npm run dev) for the review block; lesson_12.html for the closing screenshots.
  • ☐ Demo order: a list of learners in four groups of the room's size; a peer reviewer for each demo (the next person on the list).
  • ☐ Board, before learners arrive: the agenda; the assessment rules (written: closed book, 15 minutes; practical: open book, no chat assistants, 30 minutes); the demo script (one plot from the data to its card; one request from the form to the status line; one decision you made).

The five-minute check-in (per learner or pair)
  1. "Show me npm test and npm run typecheck." (Where on the TODO list are they? A to D should be done or close.)
  2. "Which rubric row are you proudest of, and which one worries you?" Read that row with them.
  3. "Walk me through one plot, from the data file to its card." (Row 6's demo, rehearsed.)
  4. One concrete next step, written in their workbook's check-in box. Nothing more: the hand-in is a week away.
Common problems and the nudge
  • Most common problems, and the nudge. gardener not optional (tsc on plots.ts: "Property 'gardener' is missing"); the visible list or the count in useState (ask: can you work it out from the filters?); a select whose onChange passes event.target.value straight into state (TS2345: narrow it with isBedKind / a status guard); keys from the index; the form's messages in an alert() or the console; className="card" strings left after styling (search for className="); the checkbox's FormData value is null when it is not ticked (that is why readText returns '').
  • Stuck on TODO E. Open Lesson 3.5's project side by side: planCleanup is sendRequest with other fields; fieldProps is the same helper.
  • Styles in index.css. Ask where the card's padding belongs (its module); show the given Badge as the pattern.
  • A failing test they "fixed" by editing the test file. Restore it from the starter; the tests are the client's acceptance criteria.

Part 1 Assessment

A1

Part 1 Assessment

45 min
Rules (say them before you start)
  • Written part: 15 minutes, closed book, 10 points, in the workbook (pages handed out at the start, collected at the end).
  • Practical: 30 minutes, open book (lesson pages, their own code, MDN), no chat assistants, no classmates; 10 points; labs/module-09/part1-practical/starter, installed at home.
  • Total 20 points; 14 or more (70 %) = the Part 1 assessment met. Part 1 met = the Plot Board project complete under its rubric (no row at 0) AND the Part 1 assessment met (14 or more of 20 points, 70 %).
  • Below the line is not the end: one retake of the part that fell short, at a time you agree, with a different practical task order or written questions from the review.

Watch-outs
  • A learner finishes the written part in five minutes. Ask them to check W2 and W5 again: both are worth two points and need a reason.
  • Install problems in the practical. No live debugging: note the time, give them your laptop's copy, add the lost minutes.
  • Questions during the practical. Answer only about the task's wording, never about the code.

Part 1 Project Demos

D1

Project Demos

40 min
Protocol
  • Three minutes each, on the timer, from the learner's own machine (or yours with their folder): one plot from src/data/plots.ts to its card (types, props, the label tables), one request from the form to the status line (the action, the state, the messages), one decision they made and its alternative.
  • A peer reviewer (the next learner on the list) fills the workbook's peer-feedback box with the rubric: one row that is strong, one question.
  • You note the evidence for rows 5 and 6 (keyboard, names, the explanation). The other rows are scored on the hand-in.
  • More learners than minutes: demos in two rooms or in groups of four with you rotating; nobody demos for longer than three minutes.

Closing

Exit ticket (3 questions, no notes, 4 minutes)
  1. Which Part 1 idea did your project use most, and where? Answer: any idea with a place in their code (a union in types.ts, a Record table, derived visible, the action's state union).
  2. One rubric row you will improve before the hand-in, and how. Answer: their own; check it matches the check-in note.
  3. In one sentence: what can you build now that you could not at the start of Part 1? Answer: their own; use it for the course feedback.
Recording results
  • Part 1 met = the project complete (no rubric row at 0) AND the assessment met (14 or more of 20). Use the scoring sheet in final-assessment.html.
  • A learner below either line gets the "next step" in writing and one resubmission (project) or retake (assessment) within two weeks.
  • When Part 2 follows, nothing here blocks Session 10: its catch-up code lets every learner start from the same place.
Homework (about 2 to 3 hours)
  • Finish the Part 1 project to the hand-in, one week from today: the folder zipped without node_modules and dist (or a repository link), plus the journal entry from TASKS.md. Run npm test, npm run typecheck, npm run lint and npm run build before you hand in.
  • The 12 self-check items reviewing Part 1 (answers in the Answer Key).

If You Run Long or Short

Running long
  • Protect: the assessment's 45 minutes; the check-in conversations.
  • Cut first (saves 8m): the warm-up's map becomes homework; keep the three questions.
  • Cut second (saves 10m): demos in groups of four with peers scoring; you collect the peer boxes.
Running short
  • Self-check items 2, 8 and 10 live: tsc's message on the projector, the room proposes the fix, then run it.
  • A keyboard pass through two volunteers' projects on the projector: what works, what the rubric says.
