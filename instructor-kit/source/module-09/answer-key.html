Part 1 Assessment: Written Part, Model Answers and Marking

10 points. The two outputs are real: tsc on a copy of the project's model solution with the change the question describes.

W1
A teammate runs node plots.ts on a file that has a type error, and Node prints a result. Why does Node not complain, and which command finds the error? (1)
Node removes the types and runs the JavaScript that is left: it never checks them. npx tsc --noEmit (here npm run typecheck, or npm run build, which runs tsc first) reads the types and reports the error.
Marking: The point needs both halves: running is not checking, and a tsc command.
W2
A learner shows the gardener's name in capitals and tsc prints the error below. What does it mean, and how do you fix it? (2)
src/components/PlotCard.tsx:26:77 - error TS18048: 'plot.gardener' is possibly 'undefined'.
Found 1 error in src/components/PlotCard.tsx:26
gardener is optional in Plot (gardener?: string), so its type is string | undefined, and checking plot.status === 'assigned' does not tell TypeScript that the name is there. Fix: check the property itself, plot.gardener !== undefined && ... (or plot.gardener?.toUpperCase()).
Marking: 1 point for "possibly undefined because it is optional", 1 for a fix that narrows. A non-null assertion ! or as string scores 0 for the fix.
W3
The garden adds a fourth status, 'archived', to PlotStatus. What does npm run typecheck do next, and why is that useful? (1)
It reports every Record<PlotStatus, ...> table that has no entry for 'archived' (here statusLabels and statusTones in labels.ts, TS2741). The compiler lists every place the new status needs a decision, before anything runs.
src/utils/labels.ts:12:14 - error TS2741: Property 'archived' is missing in type '{ open: string; assigned: string; resting: string; }' but required in type 'Record<PlotStatus, string>'.
src/utils/labels.ts:18:14 - error TS2741: Property 'archived' is missing in type '{ open: "success"; assigned: "info"; resting: "neutral"; }' but required in type 'Record<PlotStatus, BadgeTone>'.
Found 2 errors in the same file, starting at: src/utils/labels.ts:12
Marking: The point needs "it lists the tables missing the new key".
W4
Why does the plot list use key={plot.id} and not the array index? (1)
A key tells React which item is which between renders. When the filters remove or reorder plots, an index key would point at a different plot, so state such as an open details toggle would jump to the wrong card. An id stays with its plot.
Marking: Accept any answer that ties the key to the item's identity when the list changes.
W5
A board keeps const [shown, setShown] = useState(0) and updates it in useEffect(() => setShown(visible.length), [visible]). What is wrong, and what do you write instead? (2)
The count can be worked out from state on every render: storing it adds a second render and a moment where the number and the list disagree (and visible is a new array each render, so the effect runs every time). Write const shown = visible.length (derived, never stored).
Marking: 1 point for "derived value kept in state", 1 for the one-line fix.
W6
What is the type of formData.get('email'), and how do you get a string from it without as? (1)
FormDataEntryValue | null (a string, a File, or null when there is no such field). Narrow it: typeof value === 'string' ? value : ''.
Marking: The point needs the narrowing.
W7
A card has className={${styles.card} ${styles.cardd}} (a typo). What does npx tsc -b say, and what does the browser's Elements panel show? (1)
Nothing: every key of a CSS Module is typed string | undefined, so the typo compiles. The class attribute shows the real card class followed by the word undefined, a class that matches no rule.
Marking: The point needs both: no error, and undefined in the class.
W8
<div onClick={toggle}>Show details</div> works with a mouse. Name two things <button type="button"> gives you that the div does not. (1)
Any two of: it can be reached with Tab; Enter and Space press it; screen readers announce it as a button with its name; it shows the focus ring; jsx-a11y stops warning.
Marking: Half a point each, rounded down.

spotsText, a switch with no default (tsc then knows every status returns):

import type { WorkDay } from './types.ts'

export function spotsText(day: WorkDay): string {
  switch (day.status) {
    case 'open':
      return day.spotsLeft === 1 ? '1 spot left' : `${day.spotsLeft} spots left`
    case 'full':
      return 'Full'
    case 'cancelled':
      return 'Cancelled'
  }
}

WorkDayList: one piece of state, the list and the count derived:

import { useState } from 'react'
import type { WorkDay } from './types.ts'
import { spotsText } from './workDays.ts'

interface WorkDayListProps {
  days: WorkDay[]
}

export function WorkDayList({ days }: WorkDayListProps) {
  const [openOnly, setOpenOnly] = useState(false)
  // Derived from the one piece of state: never stored
  const visible = openOnly ? days.filter((day) => day.status === 'open') : days

  return (
    <>
      <p>
        <input
          id="open-only"
          type="checkbox"
          checked={openOnly}
          onChange={(event) => setOpenOnly(event.target.checked)}
        />
        <label htmlFor="open-only">Hide full and cancelled days</label>
      </p>
      <p role="status">
        Showing {visible.length} of {days.length} work days
      </p>
      <ul>
        {visible.map((day) => (
          <li key={day.id}>
            {day.title}, {day.day}: {spotsText(day)}
          </li>
        ))}
      </ul>
    </>
  )
}

SignUpForm: the action returns the next state; the message is linked to the field:

import { useActionState } from 'react'
import type { WorkDay } from './types.ts'

type SignUpState = { kind: 'editing'; error?: string } | { kind: 'done'; name: string }

// The form's action: the previous state and what was submitted give the next state
function signUp(_previous: SignUpState, formData: FormData): SignUpState {
  const value = formData.get('name')
  const name = typeof value === 'string' ? value.trim() : ''
  return name === '' ? { kind: 'editing', error: 'Enter your name.' } : { kind: 'done', name }
}

interface SignUpFormProps {
  day: WorkDay
}

export function SignUpForm({ day }: SignUpFormProps) {
  const [state, formAction] = useActionState(signUp, { kind: 'editing' })
  const error = state.kind === 'editing' ? state.error : undefined

  return (
    <>
      <p role="status">
        {state.kind === 'done' && `Thanks, ${state.name}: you are signed up for ${day.title}.`}
      </p>
      <form action={formAction} noValidate>
        <label htmlFor="name">Your name</label>
        <input
          id="name"
          name="name"
          aria-invalid={error !== undefined}
          aria-describedby={error !== undefined ? 'name-error' : undefined}
        />
        {error !== undefined && <p id="name-error">{error}</p>}
        <button type="submit">Sign up</button>
      </form>
    </>
  )
}

Q1
Your page looks fine at localhost:5173, but the editor underlines a type error. Which command refuses to ship it?
A) npm run dev
B) npm run build
C) Reloading the browser
D) node server.ts
Why: npm run build is tsc -b && vite build: a type error stops it before anything is written. The dev server removes the types and serves the code without checking it (Lessons 1.1 and 1.2: running is not checking).
A is wrong: The dev server never checks types.
C is wrong: The browser only ever receives JavaScript.
D is wrong: That runs the API.
Q2
tsc prints this for a new line in the project. What happened, and what is the fix?
src/review.ts:3:14 - error TS2322: Type '"opne"' is not assignable to type 'PlotStatus'.
Found 1 error in src/review.ts:3
PlotStatus is a union of three words and 'opne' is not one of them; write 'open'
Why: A union of string literals allows exactly its words, so a misspelled status is an error before anything runs (Lessons 1.1 and 2.2; for a closer misspelling, such as Lesson 1.1's 'canceled', tsc adds a Did you mean). The Part 1 project's TODO A test checks exactly this with @ts-expect-error.
Q3
Plot declares gardener?: string. What is the type of plot.gardener?
A) string
B) string | null
C) string | undefined
D) any
Why: An optional property may be missing, and a missing property reads as undefined. Check it (plot.gardener !== undefined) before you use it as a string; the Part 1 written part asks about exactly this.
A is wrong: Only after narrowing.
B is wrong: null is a value someone sets on purpose; optional means it can be absent.
D is wrong: TypeScript never gives you any for a declared property.
Q4
With function first<T>(items: T[]): T | undefined, what does TypeScript infer for const plot = first(plots)?
import { plots } from './data/plots.ts'

function first<T>(items: T[]): T | undefined {
  return items[0]
}

const plot = first(plots)
console.log(plot?.notes)
A) Plot | undefined
B) Plot
C) unknown
D) T | undefined
Why: T is inferred from the argument (Plot[]), so the result is Plot | undefined (the list could be empty); hence plot?.notes. Run for real: tsc is silent and Node prints the first plot's notes.
B is wrong: The return type says it may be undefined.
C is wrong: Generics keep the type; unknown would throw it away.
D is wrong: T is replaced by the type of the argument at each call.
Q5
Data arrives from outside your code (a fetch, JSON.parse, localStorage). What do you do before treating it as a Plot?
A) Write as Plot
B) Nothing: the interface describes it
C) Annotate the variable as Plot
D) Keep it unknown and check it with a type guard
Why: Types are gone at run time and the data may not match. A guard (value is Plot) checks it once, at the edge, and narrows it for the rest of the code (Lesson 2.4; Module 8 does it with Zod).
A is wrong: An assertion is a promise nobody checks.
B is wrong: The interface describes what you expect, not what arrived.
C is wrong: An annotation on a JSON.parse result is the same unchecked promise.
Q6
A Card component should wrap any content between its tags. Which prop type does that?
A) children: string
B) children: ReactNode
C) content: JSX.Element[]
D) children: any
Why: ReactNode is anything React can render: text, numbers, elements, lists, null. Children are just a prop with a special syntax (Lesson 3.2).
A is wrong: Then no element could go inside.
C is wrong: Not how JSX passes what is between the tags.
D is wrong: any turns checking off.
Q7
Why key={plot.id} and not key={index} on the plot cards?
The key tells React which item is which between renders; when the filters change the list, an index points at a different plot (state such as an open toggle jumps cards), an id stays with its plot
Why: Keys come from the data's identity, stable and unique among siblings (Lesson 3.3).
Q8
A teammate adds a short-name table and tsc prints this. What does it tell you?
src/review.ts:3:14 - error TS2741: Property 'greenhouse' is missing in type '{ raised: string; ground: string; }' but required in type 'Record<BedKind, string>'.
Found 1 error in src/review.ts:3
A) The union BedKind has a typo
B) Records cannot hold strings
C) The table has no entry for 'greenhouse': a Record<BedKind, ...> needs one per member
D) The object must be declared with as const
Why: A Record over a union is a complete table: tsc lists the missing keys. Add a member to the union and every table that lacks it lights up (Lesson 3.3's statusBadges).
A is wrong: The union is fine; the table is incomplete.
B is wrong: The value type is string, which is what was given.
D is wrong: as const would not add the missing key.
Q9
The board shows "Showing 5 of 12 plots". Where should the 5 come from?
A) A useState updated in a useEffect when the filters change
B) A useState updated in each filter's onChange
C) visible.length, worked out on every render from the filter state
D) A global variable
Why: It can be derived from state, so it is never stored: the list and its count always agree, and there is nothing to keep in step (Lesson 3.4).
A is wrong: An extra render and a moment where list and count disagree.
B is wrong: Two places to update; one will be forgotten.
D is wrong: React does not re-render when a global changes.
Q10
A select passes event.target.value straight to setBed and tsc prints this. Which fix keeps the types honest?
src/review.tsx:7:53 - error TS2345: Argument of type 'string' is not assignable to parameter of type 'SetStateAction<BedFilter>'.
Found 1 error in src/review.tsx:7
A) Narrow it with a guard: isBedKind(value) ? value : 'all'
B) setBed(event.target.value as BedFilter)
C) Change the state to useState<string>
D) // @ts-ignore above the line
Why: A select hands over any string; the guard checks it is one of ours before it reaches state (the HQ's EventFilters does exactly this with isEventStatus).
B is wrong: An unchecked promise: a renamed option value would slip through.
C is wrong: Then every later use loses the union.
D is wrong: Silences the check and keeps the bug.
Q11
After a form action returns errors, why do the fields still show what the person typed?
React resets the form after every action, to each field's defaultValue; the action returns the typed values in its state and the fields use them as defaultValue (a select also needs a new key)
Why: Lesson 3.5: values + defaultValue keep the typing; without them every field empties after a failed submit.
Q12
In the HQ after Lesson 3.6, what lives in index.css and what lives in a CSS Module?
index.css: design tokens (with their dark-mode values), the base font, plain element rules and the :focus-visible ring. A module: each component's own classes (camelCase), or a shared look (Form, Button, Card)
Why: Page-wide rules where everyone looks for them; component rules next to their component, scoped. Custom properties cross module boundaries.

Exit Ticket

  1. Any idea with a place in their code. Weak answers name an idea without a file: ask "where?" at the hand-in.
  2. Their own; it should match the check-in's next step. If it does not, the check-in did not land: follow up in writing.
  3. Their own; collect them for the course feedback.

Common Wrong Answers and What They Reveal

  • Q1 A (npm run dev). Still trusts the dev server. Lesson 1.2's Exercise 1 again: the tagline as a number.
  • Q3 A (string). Has not connected ? with undefined. W2 of the written part tests exactly this.
  • Q5 A or C. Treats types as checks. Ask: what happens when the server sends "18"?
  • Q9 A or B. Stores derived values: the most common Part 1 project problem (rubric row 3).
  • Q10 B. Reaches for as: the rubric's row 1 scores it 0.
