Lesson

6.3

Data Loading and Protected Routes

By the end you can
  • Explain the difference between rendering then fetching and loading then rendering, and when each fits
  • Write typed route loaders and read their data with useLoaderData<typeof loader>()
  • Turn failures while loading into route answers with data(), and show them with useRouteError and isRouteErrorResponse
  • Protect routes with guard loaders that redirect to sign-in with a safe ?next= address, and answer 403 to people without the right role
  • Handle a form with a route action, <Form>, useActionData and a redirect
  • Keep a session that React and the router both read, with useSyncExternalStore, and sign out automatically on a 401
Key ideas
  • Load then render: a loader runs when someone navigates to its route; the router shows the page once it finishes, and the old page stays meanwhile. useNavigation().state is 'loading' (or 'submitting' for an action).
  • Typed data: useLoaderData<typeof loader>() with an import type; without the type argument the data is any. Loaders live in their own .ts files.
  • Route answers: throw data(message, { status, statusText }) for expected failures and redirect() to send people elsewhere; one errorElement reads them with useRouteError() (unknown) and isRouteErrorResponse.
  • Await or a promise: await what the page cannot do without; return a promise for what can follow, and use() it inside Suspense.
  • Guards are loaders: guests get a redirect with a safe ?next= (only paths inside the app), the wrong role gets a 403 answer; a pathless route guards many pages; parent and child loaders run at the same time. The API's 401 and 403 remain the lock.
  • A store outside React (readSession, saveSession, onSessionChange) read with useSyncExternalStore; a route action handles the sign-in <Form>, returns why a try failed, throws a redirect on success.

/** /sites: the six beach sites */
export function sitesLoader({ request }: LoaderFunctionArgs) {
  // request.signal: leaving the page before the answer arrives cancels the request
  return getSites(request.signal)
}

And the guard: a loader whose job is to throw. A redirect for guests (with the way back in ?next=), a 403 answer for the wrong role:

shoreline-hq/src/auth/guards.ts
/** For pages with contact details and planning tools: guests sign in first, volunteers are turned away */
export function organizersOnly({ request }: LoaderFunctionArgs) {
  const session = readSession()
  if (session === null) {
    // Remember the page (and its ?search) so the sign-in page can send people back to it
    const { pathname, search } = new URL(request.url)
    throw redirect(`/sign-in?next=${encodeURIComponent(pathname + search)}`)
  }
  if (session.user.role !== 'organizer') {
    const message = "This page has the crew's contact details and planning tools, so only organizers can open it."
    throw data(message, { status: 403, statusText: 'Organizers only' })
  }
  return null
}

// nextPath, copied from src/auth/guards.ts: it needs nothing but URL
export function nextPath(url: URL): string {
  const next = url.searchParams.get('next')
  if (next === null || !next.startsWith('/') || next.startsWith('//') || next.startsWith('/\\')) {
    return '/'
  }
  return next
}

Glossary

TermMeaning
render then fetch / load then renderThe page fetches after it appears ("Loading…") / the router fetches before it shows the page
loader, LoaderFunctionArgsA function on a route that the router calls on navigation, with params and the request (url, signal)
useLoaderData<typeof loader>()Reads the route's loader data, typed from the loader; any without the type argument
useNavigation()The navigation in progress: 'idle', 'loading' (loaders) or 'submitting' (an action)
data() (route answer)Thrown from a loader or action: a status, a status text and a message for the error page
redirect()Thrown from a loader or action: the router goes to another address before anything renders
useRouteError, isRouteErrorResponseWhat the error element reads (unknown), and the predicate that narrows it to a route answer
deferred dataA promise in loader data that the router does not wait for; the page use()s it inside Suspense
guard, protected routeA loader that decides who may open a page, and the routes below it
?next=, open redirectThe way back after sign-in; sending people to any address it names (never do it: only paths inside the app)
401 / 403"Who are you?" (sign in) / "I know who you are, and no"
shouldRevalidateTells the router when it may skip a route's loader (the HQ: when only the search changed)
action, <Form>, useActionDataA route function for a submitted form; the router's form; the action's last result
external store, useSyncExternalStoreA value outside React with a subscribe function; the Hook that reads it and re-renders on change
automatic sign-outrequest() forgets the session when the API answers 401 to a request that carried a token
