4.2 · Custom Hooks: self-check

Q1
Which of these should be a custom Hook?
A) formatDate(date): it turns a date string into words
B) LoadStatus: it returns the loading or error message
C) Code that calls useState and useEffect and returns a value to the component
D) The list of the six beach sites
Why: The lesson's table: calls no Hooks = a plain function; returns elements = a component; calls Hooks and returns values = a custom Hook, named use…
A is wrong: No Hooks inside: a plain function, like formatDate.
B is wrong: It returns elements: a component.
D is wrong: Data, not logic: it comes from the API.
Q2
npm run lint prints this (first lines). Which tool is it, how serious is it, and what is the fix?
  × react-hooks(rules-of-hooks): React Hook "useEffect" is called in function "setTabTitle" that is neither a React function component nor a custom React Hook function. …
   ╭─[src/Scratch.tsx:5:3]
oxlint's rules-of-hooks, an ERROR (tsc is silent); rename setTabTitle to useTabTitle
Why: The linter finds Hooks by their names: only components and functions named use… may call Hooks. With the use name it also checks the rules INSIDE the Hook (the early-return mistake).
Q3
A toggle Hook ends with return [on, toggle]. tsc reports this. Which change fixes it?
src/Scratch.tsx:12:48 - error TS2322: Type 'boolean | (() => void) | undefined' is not assignable to type 'MouseEventHandler<HTMLButtonElement> | undefined'.
Found 1 error in src/Scratch.tsx:12
A) return [on, toggle] as const
B) Annotate the caller: const [open, toggle]: boolean[] = useToggle(false)
C) Write onClick={toggle!}
D) Use useState<boolean>(initial) inside the Hook
Why: An array literal is inferred as an array of unions, so each destructured name is boolean | (() => void) | undefined. as const makes it a readonly tuple: a boolean first, a function second.
B is wrong: That would make toggle a boolean too.
C is wrong: ! removes undefined, not boolean.
D is wrong: The state was already boolean; the RETURN type is the problem.
Q4
The first try at useApi had load in its dependency array, and a page passed (signal) => getEvents(…). What happened?
A) npx tsc -b reported the function in the array
B) npm run lint reported an error
C) React warned in the console and stopped
D) Hundreds of requests, with both tools quiet: every render made a new function
Why: Two functions are never the same object (Object.is), so the effect ran after every render: render, new function, effect, answer, state, render… The lesson measured more than 700 requests in two seconds; the kit's run of the same file: 0 lint warnings, no type errors.
A is wrong: tsc has no opinion on dependencies.
B is wrong: load IS read by the effect, so the array is "right".
C is wrong: Nothing warns; only the Network tab shows it.
Q5
You type "pelican" in the events search with useDebouncedValue(query.trim(), 300). How many requests go out? And with the delay set to 0?
One (q=pelican) after the typing pauses; seven with delay 0, one per letter

oxlint prints this for useApi. What do you change?
  ⚠ react-hooks(exhaustive-deps): Functions returned from `useEffectEvent` must not be included in the dependency array.

4.2 · Custom Hooks: predict, then check

P1
The toggle Hook now ends with return [on, toggle] as const. What does npx tsc -b print?
import { useState } from 'react'

function useToggle(initial: boolean) {
  const [on, setOn] = useState(initial)
  const toggle = () => setOn((current) => !current)
  return [on, toggle] as const
}

export function DetailsButton() {
  const [open, toggle] = useToggle(false)
  return (
    <button type="button" aria-expanded={open} onClick={toggle}>
      Details
    </button>
  )
}
(no output: no errors)
Why: as const makes the return a readonly tuple, [boolean, () => void]: open is a boolean, toggle a function, and onClick accepts it.
P2
A Hook returns early when the title is empty. What does npm run lint say?
import { useEffect } from 'react'

export function useTabTitle(title: string) {
  if (title === '') return
  useEffect(() => {
    document.title = title
  }, [title])
}
  × react-hooks(rules-of-hooks): React Hook "useEffect" is called conditionally. React Hooks must be called in the exact same order in every component render.
   ╭─[src/Scratch.tsx:5:3]
 4 │       if (title === '') return
 5 │ ╭─▶   useEffect(() => {
 6 │ │       document.title = title
 7 │ ├─▶   }, [title])
   · ╰──── This Hook call is not reachable on every render path.
 8 │     }
   ╰────
  help: Move the Hook call before the condition, or call it unconditionally and branch inside the Hook/effect instead.

Found 0 warnings and 1 error.
Finished in …ms on 34 files with 150 rules using … threads.
Why: The name useTabTitle tells the linter it is a Hook, so it checks the Rules of Hooks inside it: an early return before a Hook is an ERROR. Call the Hook every time; put the condition inside the effect.

4.3 · Refs and the DOM: self-check

Q7
A Stop button needs the id of the running interval. Nothing on the screen shows it. Where do you keep it?
A) In useState, so React knows about it
B) In useRef: it survives renders and changing it renders nothing
C) In a module-level variable
D) In a prop from the parent
Why: The rule of thumb: if the screen should change when the value changes, it is state; otherwise it can be a ref (the pocket notebook, not the whiteboard). SweepTimer keeps its id in useRef<number | null>(null).
A is wrong: Works, but renders again for a value nobody sees.
C is wrong: Shared by every copy of the component.
D is wrong: The parent does not start the timer.
Q8
tsc reports this for a click handler. What is the smallest fix, and why is TypeScript right to ask?
src/Scratch.tsx:7:5 - error TS18047: 'noteRef.current' is possibly 'null'.
Found 1 error in src/Scratch.tsx:7
noteRef.current?.focus(): before the element is on the page (and after it leaves) current is null
Why: useRef<HTMLTextAreaElement>(null) is a RefObject<HTMLTextAreaElement | null>. In a click handler the element is there, but TypeScript cannot know; ?. costs nothing.
Q9
tsc rejects this callback ref (first lines). Why?
src/Scratch.tsx:18:11 - error TS2322: Type '(el: HTMLButtonElement | null) => () => boolean' is not assignable to type 'Ref<HTMLButtonElement> | undefined'.
  Type '(el: HTMLButtonElement | null) => () => boolean' is not assignable to type '(instance: HTMLButtonElement | null) => void | (() => VoidOrUndefinedOnly)'.
    Type '() => boolean' is not assignable to type 'void | (() => VoidOrUndefinedOnly)'.
      Type '() => boolean' is not assignable to type '() => VoidOrUndefinedOnly'.
        Type 'boolean' is not assignable to type 'VoidOrUndefinedOnly'.
A) A Map cannot hold buttons
B) Callback refs were removed in React 19
C) The ref must be created with useRef
D) The cleanup arrow returns delete's boolean; a ref cleanup must return nothing
Why: React 19 lets a callback ref return a cleanup function, which must return nothing (VoidOrUndefinedOnly). Without braces, () => map.delete(name) returns a boolean. Braces fix it; the same rule rejects the old ref={(el) => (refs.current[i] = el)}.
A is wrong: The Map is fine.
B is wrong: React 19 added the cleanup.
C is wrong: Callback refs are functions, not ref objects.
Q10
TextField renders a div, a label and an input, and takes a ref prop. Which element should the ref reach, who decides, and how is the prop typed?
The input (what a parent wants to focus); the component decides by putting ref on it; ref?: Ref<HTMLInputElement>
Why: In React 19, ref is an ordinary prop for function components (no forwardRef). Which element a parent may reach is part of the component's API, like its other props.
Q11
On /events (before this lesson's fix), you type pelican, Tab to Clear filters and press Enter. The button disappears. Where is the focus?
A) On the page's body: the next Tab starts again at the skip link
B) On the search box
C) On the first cleanup card
D) Still on the button, which React keeps hidden
Why: A focused element that disappears drops the focus to body (measured in the lesson). clearFilters now focuses the search box first: the search box is already there, only the button goes.
B is wrong: Only after the project's one-line fix.
C is wrong: Nothing moves it there.
D is wrong: The button is removed from the page.
Q12
The HQ's Dialog calls showModal() in an effect and focuses the opener in the cleanup. Which statement is true?
A) The cleanup is only for Strict Mode
B) The portal is what makes the page behind inert
C) Escape: the browser returns the focus itself; a button that removes the dialog: only the cleanup returns it
D) showModal() can be called during rendering
Why: Measured in the lesson: Escape closes the dialog natively and the browser restores the focus; unmounting does not, and without the cleanup the focus fell to body. The !dialog.open check is what Strict Mode needs.
A is wrong: Strict Mode needs the !dialog.open guard; the cleanup is for every close.
B is wrong: showModal() makes the page inert; the portal only places the element in body.
D is wrong: It is a DOM method on an element that exists only after rendering: an effect.

P4
A component takes ref as an ordinary prop (React 19). What does npx tsc -b print?
import { useRef, type Ref } from 'react'

interface TextFieldProps {
  id: string
  label: string
  /** React 19: ref is an ordinary prop */
  ref?: Ref<HTMLInputElement>
}

export function TextField({ id, label, ref }: TextFieldProps) {
  return (
    <div>
      <label htmlFor={id}>{label}</label>
      <input id={id} ref={ref} />
    </div>
  )
}

export function MeetingPointForm() {
  const meetingRef = useRef<HTMLInputElement>(null)

  return (
    <>
      <TextField id="meeting" label="Meeting point" ref={meetingRef} />
      <button type="button" onClick={() => meetingRef.current?.focus()}>
        Edit the meeting point
      </button>
    </>
  )
}
(no output: no errors)
Why: ref?: Ref<HTMLInputElement> in the props, put on the input: no forwardRef needed. The parent writes ref={meetingRef} as with any element.

The Lesson Pages' Own Quick Quizzes

Lesson 4.2 · Custom Hooks
  1. A Each component sends its own request and keeps its own state: A custom Hook shares logic, not state. Each call has its own useState and its own effect, so each component sends its own request and keeps its own result. Sharing one answer needs a cache, which TanStack Query adds in Lesson 7.1.
  2. C npm run lint, with a rules-of-hooks error that says Hook names must start with use: oxlint's rules-of-hooks check sees useEffect in a function that is neither a component nor a Hook, and reports an error. Renaming it useTabTitle fixes it, and makes the linter check the rules inside it too.
  3. D boolean | (() => void) | undefined: Without as const the return type is an array of boolean or function, so each destructured name gets the union, plus undefined because noUncheckedIndexedAccess is on. as const makes it a readonly tuple: a boolean first, then a function.
  4. B Every render created a new function, so the dependency changed every time: Each render creates a new arrow function, and Object.is says two functions are never equal. So every render changed a dependency, the effect ran, set state, and rendered again. useApi now reloads only when the key string changes, and reads the function through useEffectEvent.
  5. C One, for q=pelican, after the typing pauses: Each new value clears the previous timer in the effect's cleanup, so the settled value only changes once the typing pauses for 300 ms. The key then becomes perPage=50 and q=pelican, and useApi sends one request.
Lesson 4.3 · Refs and the DOM
  1. C Nothing changes: the ref holds the new value, but React does not render again: Changing a ref does not render the component again. The new value is there for any code that reads it later, but the screen does not change. If the screen should show it, it belongs in state.
  2. A HTMLInputElement | null: Passing null picks the overload for DOM refs: RefObject of HTMLInputElement or null. Before React attaches the input, and after it is removed, there is no element, so TypeScript makes you check, for example with searchRef.current?.focus().
  3. D Declare ref?: Ref<HTMLInputElement> in its props and put it on the input: React 19 passes ref to function components as an ordinary prop. EventFilters declares ref as an optional Ref of HTMLInputElement, destructures it and puts it on the input; the page writes ref equals searchRef.
  4. B The arrow returns the assigned value, and a callback ref may only return nothing or a cleanup function: An arrow without braces returns its expression, and an assignment has a value: the element or null. A React 19 callback ref may only return nothing or a cleanup function. Braces around the body fix it.
  5. A The components above it in React's tree, such as EventCard, even though the element is in body: React events bubble through React's tree, where the dialog is still inside EventCard. The DOM position only decides where the element sits in the HTML. The PortalBubble demo measured exactly this.

Exit Ticket

  1. Two pages, one Hook: two requests (four on the dev server, half of them aborted by Strict Mode), two separate states. Sharing one answer needs lifting state, context (5.2) or a cache (7.1).
  2. Key and load: the key says what is loaded, so a new key loads again; load is a new function on every render and would run the effect every time, so the effect reads it through useEffectEvent.
  3. Ref vs state: refs: the dialog element, its opener, the search input, a timer id; state: the search text, confirming, the LoadState.

Common Wrong Answers and What They Reveal

  • Q1 A or B. Thinks "reusable" means Hook. Back to the table: does it call Hooks?
  • Q3 B. Tries to fix the caller; the Hook's return type is the problem. Hover the Hook's name.
  • Q4 A or B. Trusts the tools for the flood. Both are quiet; only the Network tab (or a test that counts requests) shows it.
  • Q7 A. Puts everything in state. The pocket notebook: nobody needs to see the timer id.
  • Q11 B. Believes the browser finds a sensible place for the focus. It does not: body, then the skip link.
  • Q12 A or B. Mixes up the jobs: the portal places, showModal makes inert, the cleanup returns the focus, the guard handles Strict Mode.
