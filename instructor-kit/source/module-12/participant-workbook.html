4.4

Suspense, use() and Error Boundaries

By the end you can
  • Explain what Suspense does and where a <Suspense> boundary belongs in a component tree
  • Read a promise while rendering with use(), typed, and keep the promise stable so it is not requested again on every render
  • Write a typed error boundary as a class component, and say which errors it catches and which it does not
  • Design fallbacks that help people: a clear message, "not found" told apart from "could not load", and a Try again that really tries again
  • Judge where Suspense belongs in a single-page app today, and what React Router (Module 6) and TanStack Query (Module 7) take over later
Key ideas
  • Suspense: a component that reads data that is not there yet suspends; the nearest <Suspense> shows its fallback; everything outside stays.
  • use(promise) returns the resolved value (use<T>(usable: Usable<T>): T). The promise must be the same on every render: a cache. Never in try/catch.
  • Error boundaries catch errors thrown while rendering (a rejected use() too), not handlers or async code. A class: typed union state, static getDerivedStateFromError, a retry arrow.
  • Fallbacks that help: not found is not retried; could not load gets Try again, which forgets the failed promise first.
Worked example: the cleanup page
shoreline-hq/src/pages/EventPage.tsx
export function EventPage({ eventId }: EventPageProps) {
  return (
    <>
      <p>
        <a href="/events">← All cleanups</a>
      </p>
      <ErrorBoundary fallback={EventProblem} onRetry={() => forgetEvent(eventId)}>
        <Suspense fallback={<LoadStatus state={{ kind: 'loading' }} what="the cleanup" />}>
          <EventDetails eventId={eventId} />
        </Suspense>
      </ErrorBoundary>
    </>
  )
}

Read it from the outside in: the back link is outside both boundaries (always there); the ErrorBoundary's fallback is EventProblem and its onRetry forgets the failed promise; the Suspense fallback is the familiar LoadStatus box; EventDetails inside only handles the happy path.

5.1

useReducer with Discriminated Unions

By the end you can
  • Recognize state whose updates follow rules, and explain why useReducer suits it better than several useState calls
  • Describe every state change as an action, typed as a discriminated union, and read the errors TypeScript gives for a wrong action
  • Write a pure reducer that returns new state instead of changing the old one, and type useReducer and dispatch by letting TypeScript infer them
  • Use the never type and an assertNever helper so the compiler reports every switch that misses a case
  • Build a check-in desk with undo for today's cleanup, and say which parts of it later lessons keep
Key ideas
  • Reducer: (state, action) => newState; pure, never changes what it got, no side effects, the same state when nothing changed.
  • Actions are a discriminated union on type; a wrong action is a compile error.
  • useReducer infers its types from the annotated reducer; useReducer<S, A> is TS2344 in React 19. dispatch is stable; Strict Mode runs reducers twice.
  • never / assertNever: the default that only accepts nothing: tsc names any member no case handles. default: return state swallows it.
  • useState or useReducer: several values that change together by rules → a reducer; server data → neither.
Worked example: rosterReducer
shoreline-hq/src/reducers/rosterReducer.ts
export function rosterReducer(state: RosterState, action: RosterAction): RosterState {
  switch (action.type) {
    case 'checkIn':
      return setMark(state, action.signupId, 'attended')
    case 'markNoShow':
      return setMark(state, action.signupId, 'no-show')
    case 'clear':
      return setMark(state, action.signupId, undefined)
    case 'undo': {
      const last = state.history.at(-1)
      if (last === undefined) {
        return state
      }
      return {
        marks: withMark(state.marks, last.signupId, last.before),
        history: state.history.slice(0, -1),
      }
    }
    default:
      return assertNever(action)
  }
}

One line per action, plus undo: the newest history entry, its before mark put back, the entry dropped. The default is the exhaustive check.

P3
A reducer ends with default: return state and the union has a removed member with no case. What does npx tsc -b print?
import { useReducer } from 'react'

interface Tally {
  bags: number
  weightKg: number
}

type TallyAction =
  | { type: 'added'; weightKg: number }
  | { type: 'removed'; weightKg: number }
  | { type: 'reset' }

function tallyReducer(tally: Tally, action: TallyAction): Tally {
  switch (action.type) {
    case 'added':
      return { bags: tally.bags + 1, weightKg: tally.weightKg + action.weightKg }
    case 'reset':
      return { bags: 0, weightKg: 0 }
    default:
      return tally
  }
}

export function BagTally() {
  const [tally, dispatch] = useReducer(tallyReducer, { bags: 0, weightKg: 0 })

  return (
    <section>
      <p role="status">
        {tally.bags} bags, {tally.weightKg} kg
      </p>
      <button type="button" onClick={() => dispatch({ type: 'added', weightKg: 4 })}>
        Add a 4 kg bag
      </button>
      <button type="button" onClick={() => dispatch({ type: 'reset' })}>
        Reset
      </button>
    </section>
  )
}
