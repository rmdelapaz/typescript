4.1

Effects and Fetching

By the end you can
  • Explain what a side effect is, why it does not belong in rendering, and when you do not need an effect at all
  • Write useEffect with the right dependency array and a cleanup function, and explain why Strict Mode runs effects twice in development
  • Fetch typed data in an effect, reading Promise<T>, Response and AbortSignal in TypeScript's messages
  • Model loading, error and ready states with a generic discriminated union, and turn API errors into messages people understand
  • Cancel requests with AbortController, and practice slow and failing answers with the API's --latency and ?_status switches
Key ideas
  • Side effect: anything a function does besides returning its result (a request, a timer, the tab title, a window listener). Rendering stays pure; effects run after the screen is updated.
  • useEffect(effect, deps): the effect may return a cleanup (void | Destructor); React runs the cleanup before the next run and when the component goes away. [] = once, [x] = when x changed, no array = after every render (almost never).
  • Strict Mode (development only) starts, cleans up and starts every effect again to prove the cleanup works. Fix the cleanup, never remove StrictMode.
  • Fetching: getSites(): Promise<Site[]>; .then knows the type. useEffect(async …) is TS2345: start the async work inside the effect. fetch resolves on a 500 (ok false) and rejects only with no answer.
  • States: LoadState<T> = loading | failed (message) | ready (data); empty is ready with zero items. ApiError (the API answered with an error status) vs TypeError (no answer): two messages. Annotate .catch((error: unknown) => …).
  • Canceling: an AbortController per run; its signal goes to fetch; abort in the cleanup; ignore an aborted request in the catch. The latest run wins.
Worked example: the sites page's effect

The sites page loads its sites in an effect. This is the finished Lesson 4.1 code (Step 3):

shoreline-hq/src/pages/SitesPage.tsx
export function SitesPage() {
  const [state, setState] = useState<LoadState<Site[]>>({ kind: 'loading' })

  // After the first render: ask the API for the sites, and cancel the request if the page goes away
  useEffect(() => {
    const controller = new AbortController()
    getSites(controller.signal)
      .then((sites) => setState({ kind: 'ready', data: sites }))
      .catch((error: unknown) => {
        if (controller.signal.aborted) return
        console.error(error)
        setState({ kind: 'failed', message: describeError(error) })
      })
    return () => controller.abort()
  }, [])

Read it in four moves. Start in the right state: useState<LoadState<Site[]>>({ kind: 'loading' }), so a slow screen never looks empty. Ask after the first render: the array is [], so the effect runs once (twice on the dev server: Strict Mode). Two endings: .then makes it ready with the data; .catch ignores a request the cleanup canceled, logs the details for you and shows a message for people (describeError). Sign off: the cleanup aborts the request if the page goes away first.

Glossary

TermMeaning
side effectAnything a function does besides returning its result: a request, a timer, the tab title, a listener
useEffectRuns code after React has updated the screen, to keep something outside React in step
cleanup functionWhat an effect returns: undoes the effect before the next run and when the component goes away
dependency arrayThe values from the component the effect reads; a change runs the effect again
exhaustive-depsoxlint's rule that lists the dependencies an effect forgot
Strict ModeDevelopment-only checks: effects start, clean up and start again
Promise<T>An answer that is not here yet, typed by what it will hold
EffectCallback / DestructorReact's types: an effect returns void or a cleanup function
response.oktrue for statuses 200 to 299; fetch resolves on any answer, rejects only with none
LoadState<T>loading | failed (message) | ready (data): a generic discriminated union on kind
ApiErrorThe HQ's error class for an answer with an error status (status, code, fieldErrors)
AbortController / AbortSignalThe browser's way to cancel a fetch: pass the signal, call abort()
race conditionAn older, slower answer arriving last and overwriting the newer one
X-Total-CountThe response header with the total number of items in a paged list
role="alert"A message screen readers announce at once (LoadStatus's failure)
