Components and TSX

By the end you can
  • Explain how React turns your component functions into what the browser shows, and why rendering must be pure
  • Write TSX: one parent element, closed tags, className and other camelCase attributes, and {expressions} in braces
  • Read the errors TypeScript reports for TSX, including attributes that do not exist and values React cannot draw
  • Write components as typed functions with named exports, one per file, and compose them into a tree
  • Import an image into a component and explain how TypeScript knows its type
  • Give Shoreline Crew HQ its shell: AppLayout, Header, Footer, a HomePage, the brand colors and the favicon
Key ideas
  • Declarative: a component says what the page should look like for today's data; React compares and changes only what differs (the tide chart). createRoot(...).render(<App />) starts it.
  • TSX becomes function calls (jsx('h1', { className, children })) that return plain-object elements: tags are values, attributes are object properties.
  • Rules: JavaScript's names (className, htmlFor, maxLength; aria-*/data-* keep dashes); one parent or a fragment <>…</>; close every tag; braces hold expressions, not statements; comments in {/* */}; {' '} keeps a space at a line end.
  • What React draws: strings, numbers, elements, arrays; true/false/null/undefined draw nothing; an object is TS2322 (not a ReactNode).
  • Components are capitalized functions returning TSX (inferred JSX.Element; no return annotation), one per file, named exports, function declarations. Lowercase = an HTML tag.
  • Pure rendering: same inputs, same TSX; no new Date() in the body (oxlint react(purity)); Strict Mode renders twice in development. Images: import logoUrl from '../assets/logo.svg' is a string (Vite's declaration); alt="" for decoration.
Worked example: an object in braces

The lesson's summary card with one line changed to <p>{site}</p>. The type check says:

src/Scratch.tsx:11:10 - error TS2322: Type '{ name: string; town: string; }' is not assignable to type 'ReactNode'.

11       <p>{site}</p>
            ~~~~~~

  node_modules/@types/react/index.d.ts:2361:9 - The expected type comes from property 'children' which is declared here on type 'DetailedHTMLProps<HTMLAttributes<HTMLParagraphElement>, HTMLParagraphElement>'
    2361         children?: ReactNode | undefined;
                 ~~~~~~~~


Found 1 error in src/Scratch.tsx:11

ReactNode is everything React can draw: text, numbers, elements, the nothing-values (true, false, null, undefined) and arrays of these. An object is not one of them: say which property to show, {site.name}, {site.town}. In the browser, without the check, this is a blank page and "Objects are not valid as a React child".

Glossary

TermMeaning
declarative / imperativeDescribe the result and let React work out the steps / give the browser step-by-step instructions
React elementA plain object describing a tag, its attributes and children: what TSX evaluates to
rendering, re-renderReact calling components and updating the DOM to match / doing it again after data changes
TSXHTML-like tags inside TypeScript, in .tsx files; compiled to jsx() calls
fragment<>…</>: groups elements without adding one to the page
className, htmlForTSX's names for HTML's class and for
ReactNodeReact's type for anything it can draw
JSX.ElementThe type a component's TSX return is inferred as
JSX.IntrinsicElementsTypeScript's list of HTML tags and their attributes
componentA capitalized function that returns TSX; used like a tag
pure componentSame inputs, same TSX; changes nothing outside itself while rendering
Strict ModeA development helper that renders components twice to expose impure ones
skip linkA link, visible on focus, that jumps past the header to <main>
CSS custom property--deep-tide: #0b3954: a named value in CSS, read with var(--deep-tide)
