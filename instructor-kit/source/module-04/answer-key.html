Q1
You switched App to a named export, and tsc prints this for main.tsx. What is the fix?
src/main.tsx:4:8 - error TS2613: Module '"/Users/you/shoreline/shoreline-hq/src/App"' has no default export. Did you mean to use 'import { App } from "/Users/you/shoreline/shoreline-hq/src/App"' instead?
A) Add export default App back to App.tsx as well
B) Change the import to import { App } from './App.tsx'
C) Rename App.tsx to App.ts
D) Remove the .tsx extension from the import
Why: TS2613: import App from asks for a DEFAULT export, and App.tsx now has a NAMED one. The message's "Did you mean" is the fix. The course uses named exports for everything it adds: the import must use the real name (Lesson 3.1, Step 5).
A is wrong: Two exports for one component is exactly the mix-up the convention avoids.
C is wrong: A component file holds TSX: .tsx.
D is wrong: The HQ imports keep their extensions since Lesson 1.2.
Q2
On the dev server, a console.log('HomePage rendered') at the top of HomePage prints twice for one page load. Why?
A) HomePage is rendered by two parents
B) A bug: the component re-renders forever
C) <StrictMode> calls each component twice in development to expose impure ones; the build does not
D) The browser loaded main.tsx twice
Why: Strict Mode, development only, calls each component twice and throws one answer away, so an impure component shows its problem early. A pure component gives the same TSX both times (Lesson 3.1, Rendering must be pure).
A is wrong: AppLayout places it once.
B is wrong: It would print forever, not twice.
D is wrong: One module load; two calls.
Q3
Why does npx tsc -b reject this component, and what is the fix that adds nothing to the page?
export function SiteHeading() {
  return (
    <h2>Pelican Point Beach</h2>
    <p>Port Marisol</p>
  )
}
TS2657: JSX expressions must have one parent element (a function returns one value); wrap the two in a fragment, <>…</>
Why: Tags are values: two side-by-side tags would be two return values. A fragment groups them without adding a box to the page (Lesson 3.1, Rule 2).
Q4
tsc prints this for <p>Today's lead: {leader}</p>. What do you write instead?
src/Scratch.tsx:4:27 - error TS2322: Type '{ name: string; phone: string; }' is not assignable to type 'ReactNode'.
A) {leader.toString()}
B) {JSON.stringify(leader)}
C) {leader as ReactNode}
D) {leader.name}: the property you want to show
Why: React can draw text, numbers, elements and arrays of these, never a plain object. Say which property to show. Without TypeScript the browser shows a blank page and "Objects are not valid as a React child" (Lesson 3.1, Rule 4; Lab 3.1 Task 2).
A is wrong: Draws [object Object].
B is wrong: Draws raw JSON: valid, but not what a user should read.
C is wrong: An assertion silences the check and brings back the crash.
Q5
In Header.tsx, import logoUrl from '../assets/logo.svg'. What is the type of logoUrl, and where does it come from?
A) string, from Vite's declare module '*.svg' (loaded by "types": ["vite/client"])
B) SVGElement, because the file is an SVG
C) any: TypeScript cannot read SVG files
D) HTMLImageElement, from the DOM library
Why: A declaration file says that any import ending in .svg has a default export that is a string: the file's address after the build. <img src={logoUrl} /> always points at the right place (Lesson 3.1, Images and Their Types).
B is wrong: An import gives an address, not an element.
C is wrong: The declaration gives it a precise type; there is no any.
D is wrong: That is what querySelector('img') returns (Lesson 2.3).
Q6
The crew's logo sits right next to the words "Shoreline Crew HQ" in the header. Which alt is right?
A) alt="logo"
B) alt="Shoreline Crew HQ logo"
C) No alt at all, since the text is there
D) alt="", so screen readers skip a decorative picture
Why: Describe what the picture tells the user, or write alt="" when the text next to it already says it: otherwise a screen reader announces the name twice. A missing alt is not the same as an empty one (Lesson 3.1, Step 3; the checks count img[alt='']).
A is wrong: Says nothing useful and repeats.
B is wrong: Reads the name twice.
C is wrong: Without alt, screen readers may read the file name.

// Checkpoint 1: model answer (instructor copy)

export type Zone = 'high' | 'middle' | 'low'

export interface Survey {
  id: string
  site: string
  animal: string
  zone: Zone
  count: number
  note?: string
  verifiedBy: string | null
}

export function surveyLine(survey: Survey): string {
  const verified = survey.verifiedBy === null ? 'not verified yet' : `verified by ${survey.verifiedBy}`
  const note = survey.note === undefined ? '' : ` (${survey.note})`
  return `${survey.animal} at ${survey.site} (${survey.zone} zone): ${survey.count}, ${verified}${note}`
}

export type SurveyFormatter = (survey: Survey) => string

export function formatAll(surveys: Survey[], format: SurveyFormatter = surveyLine): string[] {
  return surveys.map(format)
}

export function maxBy<T>(items: T[], valueOf: (item: T) => number): T | undefined {
  let best: T | undefined
  for (const item of items) {
    if (best === undefined || valueOf(item) > valueOf(best)) {
      best = item
    }
  }
  return best
}

const zones: Zone[] = ['high', 'middle', 'low']

function isRecord(value: unknown): value is Record<string, unknown> {
  return typeof value === 'object' && value !== null && !Array.isArray(value)
}

export function isSurvey(value: unknown): value is Survey {
  return (
    isRecord(value) &&
    typeof value.id === 'string' &&
    typeof value.site === 'string' &&
    typeof value.animal === 'string' &&
    zones.some((zone) => zone === value.zone) &&
    typeof value.count === 'number' &&
    (value.note === undefined || typeof value.note === 'string') &&
    (value.verifiedBy === null || typeof value.verifiedBy === 'string')
  )
}

export function readSurveys(json: string): Survey[] {
  const data: unknown = JSON.parse(json)
  if (Array.isArray(data) && data.every(isSurvey)) {
    return data
  }
  throw new Error('Unexpected survey data')
}

export type SurveyEdit = Partial<Omit<Survey, 'id'>>

Scoring notes: Task 1 with ?? (survey.note ? … : '' is fine too) or a template with two small ifs both meet the row; || for the note is fine (an empty note adds nothing), ! on verifiedBy is "Partly". The Lesson Page's Own Quick Quiz

Lesson 3.1 · Components and TSX
  1. D A call to React's jsx functions that returns a plain object describing the h1: The compiler turns the tag into a jsx call with the tag name, the attributes as an object and the contents as children. The call returns a plain object describing the h1, and React later makes the page match it.
  2. A TSX attributes use JavaScript's names, and React's types for label call this one htmlFor: TSX attributes become properties of an object, and for is a reserved word in JavaScript, so React uses the DOM property name htmlFor. React's types list every attribute a label accepts, which is how TypeScript can suggest the right one.
  3. C The tag is the HTML footer element, so the page gets an empty footer and tsc reports the function as unused: Lowercase tags are HTML elements, and footer is a real one, so the page gets an empty HTML footer. The function is never used, which noUnusedLocals reports as TS6133. Components are always capitalized.
  4. B One that returns a heading built from crewName, a constant defined at the top of its file: It only reads values that do not change and returns TSX built from them, so every call gives the same result and changes nothing else. That is all purity asks.
  5. A Its return is alone on a line, so the TSX below it never gets returned: With return alone on its line, the function returns nothing, so its inferred type is a function returning void. Starting the TSX on the return line with return ( fixes it, and the linter points at the unreachable TSX.

Exit Ticket

  1. render to the page: React calls the component functions, gets elements (plain objects) and creates or changes the real DOM to match; after data changes it renders again and changes only what differs.
  2. Two TSX rules: any two of className/htmlFor and camelCase attributes, one parent or a fragment, every tag closed, braces for expressions, comments in braces.
  3. Named, capitalized, one per file: the import uses the real name (no TS2613 mix-ups; renames reach every file); lowercase tags are HTML; one component per file is easy to find.

Common Wrong Answers and What They Reveal

  • Q1 A. Wants both kinds of export. Explain the one-rule habit: named exports for everything the course adds.
  • Q2 A or B. Reads Strict Mode as a bug. Show that the build logs once.
  • Q4 A or B. Draws an object as text. Show [object Object] on the page.
  • Q7 B. Expects inference to keep literals in arrays. Hover zones together.
  • Q8 A or B. Mixes optional and nullable. Write note?: string and verifiedBy: string | null side by side.
  • Q12 A or D. Writes a claim instead of a check. Feed it {"surveys": []}.
