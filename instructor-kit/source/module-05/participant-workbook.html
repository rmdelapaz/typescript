Lesson

3.2

Props, Children and Composition

By the end you can
  • Explain props as the single object React passes to a component, and destructure it in the parameter list
  • Type props with an interface, and read the errors TypeScript gives for missing, misspelled and mistyped props
  • Make props optional with ? and give them defaults, the same way you did for options objects in Lesson 2.3
  • Accept content between a component's tags with children: ReactNode, and choose composition over a long list of props
  • Reuse the API's domain types in props, including a part of a type such as Site['image']
  • Build the HQ's sites page from a typed Site[] with Card, Badge, SitePicture and SiteCard, and give AppLayout its children
Key ideas
  • Props are one object. <SiteName name="Driftwood Cove" town="Port Marisol" /> calls SiteName({ name, town }). Destructure it in the parameter list and describe it with an interface (SiteNameProps) right above the component.
  • Strings in quotes, everything else in braces: town="Port Marisol", capacity={18}, site={site}, icon={<span>⭐</span>}.
  • Every use is checked: TS2741 for a missing prop, TS2322 for an unknown prop or a wrong type, each pointing back at the interface.
  • Optional props use ? plus a default in the destructuring (label = 'Low tide'); without the default the prop is string | undefined inside (TS18048). A boolean prop without a value is true. No defaultProps.
  • children: ReactNode lets a component wrap any content; a component that does not declare children accepts none. Compose small components instead of adding props for every case.
  • Reuse the API's types: site: Site, a part with Site['image'], a few properties with Pick<Volunteer, 'name' | 'phone'>. Props are read-only: react(immutability) warns when you change one.

Glossary

TermMeaning
propsThe one object React passes to a component: every attribute, plus children
destructuringUnpacking an object in the parameter list: ({ name, town }: SiteNameProps)
IntrinsicAttributesReact's own props every element accepts (such as key), joined with yours in error messages
optional prop, defaultlabel?: string may be left out; label = 'Low tide' fills it in, so inside it is a plain string
boolean shorthand<TideTime highlight /> means highlight={true}
childrenThe content between a component's tags, passed as a prop
ReactNodeThe type for anything React can draw: elements, text, numbers, arrays of nodes, null, undefined, booleans
compositionBuilding bigger components by putting small ones inside each other, instead of one component with many props
indexed access typeSite['image']: the type of one property of a type
Pick<T, K>A type with only some properties of T: Pick<Volunteer, 'name' | 'phone'>
keyReact's name tag for an item in a list (Session 6); never reaches the component
react(immutability)oxlint's warning when code changes a prop or a hook argument
defaultPropsAn old way to give defaults; React 19 ignores it on function components written in TSX
