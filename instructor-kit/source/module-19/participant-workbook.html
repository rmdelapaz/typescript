Lessons

7.2

Mutations

By the end you can
  • Send typed POST and PATCH requests and check what comes back
  • Write mutationOptions factories and run them with useMutation, mutate and mutateAsync
  • Invalidate the cache by key after a change, and explain which entries a change makes out of date
  • Show an API's 400 fieldErrors under the fields they belong to
  • Decide when an update should be optimistic, and write one with onMutate, a rollback in onError and a refetch in onSettled
Key ideas
  • A mutation changes server data (POST, PATCH, DELETE). It runs only when you call it, its answer is not cached, and it is not retried by default (a retried POST could save twice).
  • mutationOptions factories (the twin of queryOptions) carry the types: mutate takes the mutation function's parameter, data is its promise's value. mutate starts and moves on; mutateAsync returns a promise to await (and catch).
  • Invalidation: after a change, ask "what could this have changed?" and call invalidateQueries with the general key (['events']); entries on screen refetch now, the others when needed. Return the promise from onSuccess.
  • When the API says no: a 400 with fieldErrors keyed by the form's field names goes straight under the fields; other failures become one sentence (describeError).
  • Wait or optimistic: big or hard to take back → wait; small, frequent, easy to undo → optimistic: onMutate (cancelQueries, write the cache, return the old value), onError (roll back), onSettled (refetch the truth).
  • Server state leaves the reducer: the marks live in the API (read through the cache); the desk's reducer keeps only the undo history of accepted changes.
Worked example: a rollback TypeScript insists on

The rollback in markMutation, written as if onMutate always answered:

onError: (_error, { signupId }, saved) => {
  setStatus(signupId, saved.before)
},

npx tsc -b on the finished Lesson 7.2 code with that line:

src/api/mutations.ts:68:27 - error TS18048: 'saved' is possibly 'undefined'.

68       setStatus(signupId, saved.before)
                             ~~~~~

src/api/mutations.ts:68:27 - error TS2345: Argument of type 'SignupStatus | undefined' is not assignable to parameter of type 'SignupStatus'.
  Type 'undefined' is not assignable to type 'SignupStatus'.

Found 2 errors in the same file, starting at: src/api/mutations.ts:68

Two errors at the same spot. saved is possibly undefined: onError also runs when onMutate itself failed, before it returned anything. before may be undefined: the sign-up was not in the cached roster. The fix answers both: if (saved?.before !== undefined) { setStatus(signupId, saved.before) }. The types turned a rare failure into a line you cannot forget.

7.3

Client State

By the end you can
  • Decide where a piece of state belongs: the query cache, the URL, a component, a reducer, or an app-wide store
  • Create a typed Zustand store with state and actions, and read it with selectors that re-render only what changed
  • Keep a store across reloads with the persist middleware, and check the saved data before trusting it
  • Use a store outside React (getState, subscribe) for page-wide effects like a theme
  • Read Redux Toolkit code (slices, typed hooks, a Provider) and compare it with Zustand on size, code and tooling
Key ideas
  • Where state lives: server data → the query cache; what a link should reproduce → the URL; one component's business → useState or a reducer; the session → the session store; app-wide preferences that outlive the tab → an app store. Keep state as close as possible to where it is used (colocation).
  • Zustand: create<UiState>()(…) makes a store of values and actions outside React; set merges and never changes the old object. The extra () lets you give the type while TypeScript infers the middleware's.
  • Selectors decide re-renders: a component re-renders when its selector's answer changes (Object.is). Select one value or a derived boolean; a selector that builds an object needs useShallow (or React gives up).
  • persist saves to localStorage under a name; what comes back is unknown: a merge checks each field and falls back to the default.
  • Outside React: useUiStore.getState() and subscribe((state, previous) => …): the theme goes on <html data-theme> from main.tsx.
  • Redux Toolkit (slices, PayloadAction, typed Hooks, a Provider) solves the same problem with named actions and DevTools; reach for it when the codebase already uses it.
Worked example: typed selectors

The lesson's Scratch.tsx reads two values from the display store with no type arguments, then makes two mistakes:

import { useUiStore } from './state/uiStore.ts'

export function Scratch() {
  const density = useUiStore((state) => state.density)
  const setTheme = useUiStore((state) => state.setTheme)
  const small = density === 'cozy'
  return <button onClick={() => setTheme('purple')}>{small ? 'Small' : 'Large'}</button>
}

Glossary

TermMeaning
mutationA change to server data (POST, PATCH, DELETE), run when you call it, not cached
mutationOptionsThe mutation twin of queryOptions: one factory per kind of change, with its types
useMutationRuns a mutation in a component: mutate, mutateAsync, status flags, data, error, variables
invalidationMarking cached entries stale after a change (invalidateQueries by key prefix)
optimistic updateShowing a change before the API answers, and rolling it back if it says no
onMutate / onError / onSettledBefore the request (return what to put back) / after a failure / after either
cancelQueriesStops refetches already on their way, so they cannot overwrite an optimistic change
setQueryDataChanges a cache entry by hand (typed through the factory's key)
client state, colocationState only this browser knows / keep state as close as possible to where it is used
Zustand, store, selectorA small app-wide state library / its values and actions / a function from the state to the part a component needs
useShallowCompares an object selector's values instead of the object itself
persist, mergeZustand middleware that saves to localStorage / where you check what comes back
light-dark(), color-schemeA CSS function that picks a light or dark value / the property that decides which
Redux Toolkit, sliceThe official modern Redux / one part of the store with its reducers and actions
