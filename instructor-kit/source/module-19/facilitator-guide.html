Frame and mental model (10m)
  • Hook (2m). Publish says "Ready to save" and nothing reaches the API; marks vanish on reload.
  • Query versus mutation (3m). A query runs whenever a component needs it and is cached; a mutation runs when you call it, is not cached, is not retried. "What a mutation leaves behind is a cache that is out of date."
  • The change forms (5m). The clerk sends each form to head office; head office accepts it or sends it back with notes in the margin (fieldErrors); once accepted, the clerk crosses out every logbook entry it affects (invalidation); for small everyday forms, the clerk pencils the change in at once and rubs it out if head office says no (optimistic).

  2. The optimistic flow (5m). Draw the lesson's diagram (tap → onMutate: stop refetches → write the cache → PATCH → onError: old status back → onSettled: invalidate). Then the code:
    shoreline-hq/src/api/mutations.ts
        onMutate: async ({ signupId, mark }) => {
      // A refetch already on its way would overwrite the new mark with the old answer
      await queryClient.cancelQueries({ queryKey })
      const before = queryClient.getQueryData(queryKey)?.find((entry) => entry.id === signupId)?.status
      setStatus(signupId, markStatus(mark))
      return { before }
    },
    // The API said no (or could not be reached): put the old status back
    onError: (_error, { signupId }, saved) => {
      if (saved?.before !== undefined) {
        setStatus(signupId, saved.before)
      }
    },
    Three reasons, one per callback: cancelQueries (a refetch on its way would overwrite the new mark), { before } for THIS person only (other marks made meanwhile stay), onSettled asks for the truth either way.

Three mistakes to expect, and how to coach each
  • Saving without invalidating. "It saved, but the list didn't change." Coach: "which keys could this have changed?" (Item 3; Lab 7.2 Task 2.)
  • An optimistic update for a big change. Someone makes Cancel optimistic "because it feels faster". Coach with the table: what would 18 volunteers be told if the request then failed? (Item 4.)
  • mutateAsync without a catch. The alert works but the console shows an uncaught error. Coach: mutate when you only need the status; mutateAsync + try/catch when the next line depends on the answer.

          return current
        }
        return {
