11.2

Next Steps

By the end you can
  • Read the advanced TypeScript you will meet in libraries and team code (satisfies, mapped types, template literal types, conditional types with infer, branded types) and write a small example of each
  • Give an untyped package a declaration file instead of silencing the error, and choose satisfies over as when you want a value checked
  • Explain what a framework such as Next.js adds to a Vite single-page app, and what carries over to React Native and the volunteers' phone app on the same API and types
  • Work on a team with short-lived branches, a pull request template, CI and helpful code review, and keep a project current with release notes and npm outdated
  • Look back over the whole course and write a learning plan for the months after it
Key ideas
  • Library types compute types from types: Partial and Record are mapped types, ReturnType a conditional type with infer. Read them from the outside in, one level at a time.
  • satisfies checks a value against a type and keeps the value's own, more precise type; as trusts you and checks almost nothing; an annotation replaces the value's type.
  • Mapped types build a type from another's keys (as renames them), template literal types give strings a pattern, conditional types with infer take types apart, brands keep look-alike strings apart.
  • An untyped package gets @types/... or a small declaration of what you use, with real types; never an empty declare module.
  • Frameworks such as Next.js add server rendering and server components; React Native reuses your React, TypeScript, data layer and the shared core/types.ts.
  • Teams: short branches, pull requests with a template, CI and labeled, kind review (blocking, suggestion, nit); upgrades one major at a time after the release notes, with CI deciding.
