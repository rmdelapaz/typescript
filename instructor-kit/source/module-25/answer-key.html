Q3
What does this print, and how does the final project store prices because of it?
node -p "1.10 + 2.20"
3.3000000000000003; prices are whole cents (a Cents type), formatted only for display
Why: JavaScript numbers are binary fractions, so most decimal prices are not stored exactly. In cents the same sum is exact (node -p "110 + 220" prints 330). Divide by 100 only when you format, with Intl.NumberFormat.
Q4
A repair ticket has no promised day until a mechanic has looked at the bike. Which property fits?
A) promisedFor: DateString | null
B) promisedFor?: DateString
C) promisedFor: string, empty until known
D) promisedFor: Date | undefined
Why: null says "known to be empty": the API sends the property, with no value yet. An optional property means "not sent", a different thing; an empty string hides the state from the type checker (Lesson 11.1, Types First).
B is wrong: Optional means the property may be missing from the answer altogether.
C is wrong: An empty string is still a string: nothing forces the code to handle "no day yet".
D is wrong: JSON has no Date objects, and undefined is not a JSON value: the API sends strings and null.
Q5
Which Bramblekey rule (Lab 11.1) must the mock API's handler check, and not only the booking form?
A) The request text is at most 500 characters
B) The day looks like YYYY-MM-DD
C) The piano kind is one of three
D) A day holds at most three visits
Why: Only the server knows every visit, so only it can count a day's visits; the form cannot. Field rules (length, format, one of a list) belong in a schema the form and the API share, and the server checks them again (Lesson 11.1, Step 5; Lesson 8.1).
A is wrong: A field rule: in the shared schema, checked on both sides.
B is wrong: A format rule: the same.
C is wrong: A union of three values: the type and the schema hold it.

Q10
Read it from the outside in: what is the type of store.setDensity?
interface Settings {
  theme: 'system' | 'light' | 'dark'
  density: 'roomy' | 'compact'
}

type Setters<T> = {
  [K in keyof T & string as `set${Capitalize<K>}`]: (value: T[K]) => void
}
(value: "compact" | "roomy") => void
Why: For each string key K of Settings, a property named set + K with a capital letter, whose value is a function taking T[K]: density becomes setDensity, taking 'roomy' | 'compact'. TypeScript 7 prints a literal union sorted, so the hover shows "compact" first (Lesson 11.2, Step 2).
