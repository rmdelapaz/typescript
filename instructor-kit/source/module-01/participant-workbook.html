Lessons

1.1

Why React + TypeScript

By the end you can
  • Explain in your own words what React does and what TypeScript does, and why teams use them together
  • Describe when TypeScript's checks happen (while you write and build) and what they cannot catch (data that arrives while the app runs)
  • Read a TypeScript error message and find the line, the cause and the suggested fix
  • Write an interface for a piece of real API data and use it to type a function
  • Connect the screens of Shoreline Crew HQ to the API data each one needs
Key ideas
  • React turns data into screens with components and keeps them up to date: you describe what the screen should be (declarative), React works out the changes.
  • TypeScript is JavaScript plus types: short descriptions of what a value may be. interface CleanupEvent { ... } describes a shape; : CleanupEvent, event: CleanupEvent and : number are annotations.
  • Checking happens before running: in your editor as you type and when tsc runs. The types then disappear: browsers and Node run plain JavaScript.
  • Running is not checking: node file.ts and Vite's dev server strip the types and run the code without checking it.
  • Reading an error: file:line:column, the code (TS2551, TS2322, TS2741), the message (often with a suggestion), the line, then the indented follow-up that says where TypeScript's knowledge came from.
  • What TypeScript cannot do: see data that arrives while the app runs (Lesson 2.4, Module 8), check logic (tests, Module 9), check anything typed any. A union of string literals ('draft' | 'scheduled' | ...) allows exactly those words.
Worked example: one file, two tools

The lesson's cleanup script with one typo (capcity), handled by two tools. Node runs it:

node spots.ts
Weekend Cove Cleanup: NaN spots left

The TypeScript compiler checks it:

npx tsc --noEmit spots.ts
spots.ts:18:16 - error TS2551: Property 'capcity' does not exist on type 'CleanupEvent'. Did you mean 'capacity'?

18   return event.capcity - event.spotsTaken
                  ~~~~~~~

  spots.ts:5:3 - 'capacity' is declared here.
    5   capacity: number
        ~~~~~~~~


Found 1 error in spots.ts:18

Read it in four moves. Where: spots.ts:18:16 = file, line 18, column 16. What: the code TS2551 and the message, with a suggestion (Did you mean 'capacity'?). The line: printed with ~~~~ under the problem. Why it knows: the indented follow-up, spots.ts:5:3 - 'capacity' is declared here: the interface you wrote. Node printed NaN because it removed the types and ran what was left; nobody checked.

1.2

Your Workspace

By the end you can
  • Install the current long-term-support version of Node.js and VS Code, and check that they work from a terminal
  • Run the Shoreline Crew API locally and read its answers in a browser
  • Create a Vite react-ts project, install its packages and run its dev server
  • Explain what each file in a new project does and how index.html, main.tsx and App.tsx connect
  • Tell running apart from checking: use your editor, tsc -b, npm run lint and npm run build to find mistakes the dev server lets through
Key ideas
  • Two things on your computer: Node.js LTS (24 or newer, with npm) and VS Code. Every other tool is installed per project by npm install, at the versions in package.json.
  • One course folder, shoreline: shoreline-api (downloaded, never edited), shoreline-hq (your app) and later ts-lab. Not in OneDrive, iCloud or Dropbox.
  • Two terminals while you work: the API (node server.ts in shoreline-api, http://localhost:4000) and the dev server (npm run dev in shoreline-hq, http://localhost:5173). Start the API first.
  • How the page starts: index.html (div id=root) loads src/main.tsx, which calls createRoot(...).render(<App />); App.tsx is the first component.
  • The scripts: dev runs (no checking); build = tsc -b && vite build (a type error stops it); lint = oxlint (suspicious code, warnings do not fail it); preview serves the build.
  • Three places that check: the editor (red underline, Problems panel), npx tsc -b (silence = no errors) and npm run build. Aim for 0 lint warnings and a clean build at the end of every lesson.
Worked example: one typo, three places

One typo in App.tsx, {crewName.toUppercase()}, seen three ways. Your editor underlines it as you type. The dev server serves the page anyway, and the browser goes blank (the Console says crewName.toUppercase is not a function). The compiler names it before anything runs:

npx tsc -b
src/App.tsx:7:21 - error TS2551: Property 'toUppercase' does not exist on type 'string'. Did you mean 'toUpperCase'?

7       <h1>{crewName.toUppercase()} HQ</h1>
                      ~~~~~~~~~~~

  node_modules/@typescript/typescript-linux-x64/lib/lib.es5.d.ts:506:5 - 'toUpperCase' is declared here.
    506     toUpperCase(): string;
            ~~~~~~~~~~~~~~~~~~~~~~


Found 1 error in src/App.tsx:7

And npm run build stops at its first step, because the script is tsc -b && vite build: no vite build line ever appears. Fixed, npx tsc -b prints nothing at all, and the build ends like this (times and hashes differ on every machine):

> tsc -b && vite build

Glossary

TermMeaning
ReactA library that draws the screen from your data with components and keeps it up to date
componentA function that returns what a part of the screen should look like (App, later CleanupCard)
TypeScriptJavaScript plus types, checked before the code runs; the types are removed afterwards
type, annotationA description of what a value may be / writing one after a name (capacity: number)
interfaceA named description of an object's shape (interface CleanupEvent { ... })
tscThe TypeScript compiler; npx tsc -b checks the project, --noEmit checks a file without writing JavaScript
static checkingChecking code before it runs (editor, tsc), as opposed to while it runs
union of string literalsA type that allows only some words: 'draft' | 'scheduled' | 'completed' | 'cancelled'
any"Stop checking this value": the course avoids it
Node.js / npmJavaScript outside the browser / its package manager and script runner
LTSLong-term support: the Node release line tools test against (24 or newer)
shoreline-apiThe course's mock back end with sample data, at http://localhost:4000/api
Vite, dev serverThe build tool that creates, serves (:5173) and builds the app; the dev server runs code without checking it
npm run buildtsc -b && vite build: check every file, then write the finished site to dist/
oxlint, linterA tool that flags suspicious code (npm run lint); warnings do not fail it
HMRHot module replacement: Vite swaps the changed piece of the running page when you save
portThe number that says which running program a request is for (4000 the API, 5173 the dev server)
