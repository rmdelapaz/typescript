1.1 · Why React + TypeScript: self-check

Q1
What does node spots.ts do with the types in spots.ts?
A) Checks them, then runs the file if they are right
B) Removes them and runs the JavaScript that is left
C) Turns them into runtime checks that stop on a wrong value
D) Refuses to run the file until you install tsc
Why: Node 24 runs a .ts file by stripping the types. That is why the typo printed NaN instead of an error: only tsc (or your editor) reads the types (Lesson 1.1, the same file twice).
A is wrong: Nothing checks types while the code runs; that was the whole point of the NaN.
C is wrong: Types disappear completely: they cost nothing at run time and protect nothing at run time.
D is wrong: Node 24 runs .ts files directly; older Node versions are the ones that refuse.
Q2
Predict both: what does node p1.ts print for this file, and does npx tsc --noEmit p1.ts accept it?
const capacity = 18
const spotsTaken = '12'
console.log(capacity - spotsTaken)
Node prints 6; tsc rejects it with TS2363
Why: JavaScript turns the text '12' into a number for -, so Node prints 6 and looks fine. TypeScript refuses arithmetic on a string: error TS2363: The right-hand side of an arithmetic operation must be of type .... Item 4 is the case it cannot see.

Why: The first location (9:7) is where the problem shows up: the object is missing a required property. The indented follow-up (6:3) is where TypeScript's knowledge came from: the interface says every cleanup has one. Fix the data, not the description (Lesson 1.1, Step 3).

Q4
Which of these mistakes can TypeScript NOT catch on its own?
A) Reading event.capcity instead of event.capacity
B) Writing capacity: '18' where the interface says number
C) Writing capacity + spotsTaken where you meant capacity - spotsTaken
D) Leaving spotsTaken out of a cleanup
Why: Both expressions are perfectly typed numbers; only tests (Module 9) and you can tell which one is right. TypeScript also cannot see data that arrives while the app runs (Lesson 2.4, Module 8).
A is wrong: TS2551, with a Did you mean.
B is wrong: TS2322.
D is wrong: TS2741.
Q5
What does npx tsc --noEmit statuses.ts report for the last line?
type EventStatus = 'draft' | 'scheduled' | 'completed' | 'cancelled'

let current: EventStatus = 'scheduled'
current = 'canceled'

console.log(current)
A) Nothing: 'canceled' is a string, and EventStatus is made of strings
B) error TS2820: 'canceled' is not assignable to EventStatus. Did you mean 'cancelled'?
C) error TS2551: Property 'canceled' does not exist
D) Nothing at build time; the browser throws later
Why: A union of string literals allows exactly those four words, so the misspelling is caught, with a suggestion: statuses.ts:4:1 - error TS2820: Type '"canceled"' is not assignable to type 'EventStatus'. Did you mean '"cancelled"'?. Statuses, roles and screen states use this all course (Lesson 2.2).
A is wrong: That would be true for type EventStatus = string; the union is the point.
C is wrong: TS2551 is about properties of an object; here a value is assigned.
D is wrong: The check happens before anything runs.
Q6
Name the two places where TypeScript checks your code, and the one place it never does.
In the editor while you type, and when tsc runs (npm run build); never while the app runs in the browser
Why: Static checking: the editor's red underline and the compiler both read the types before the code runs; the browser only ever receives JavaScript (Lesson 1.1, three facts to keep).

1.2 · Your Workspace: self-check

Q7
npm run dev is running. You change const tagline: string to const tagline: number and save. What does the page at localhost:5173 show?
A) A blank page
B) Vite's error overlay with TS2322
C) The tagline, as before
D) NaN where the tagline was
Why: The dev server removes the types and serves the code without checking it; once the types are gone the line is ordinary, working JavaScript. Your editor and npx tsc -b still report TS2322, and npm run build refuses it (Lesson 1.2, Exercise 1).
A is wrong: The page goes blank when the code crashes while drawing (toUppercase), not on a wrong annotation.
B is wrong: Vite's dev server does not run tsc.
D is wrong: The value is still the text; only its annotation is wrong.
Q8
In shoreline-hq with no mistakes in it, what does this print?
npx tsc -b
Nothing at all: no output means no errors
Why: tsc speaks only when something is wrong. The silence is the success message; npm run build then goes on to vite build.
Q9
While you work on Shoreline Crew HQ, which two programs run, each in its own terminal?
A) The API (node server.ts, port 4000) and the dev server (npm run dev, port 5173)
B) VS Code and tsc -b
C) npm install and npm run build
D) The API and npm run preview (port 4173)
Why: The API answers with the data; the dev server serves the app; the browser talks to both. Start the API first (Step 5's start-of-session card).
B is wrong: VS Code is the editor; tsc is a check you run when you want it.
C is wrong: Both finish and stop; neither keeps running.
D is wrong: preview serves a finished build; while you work, it is the dev server.
Q10
A learner's node server.ts stops with ERR_UNKNOWN_FILE_EXTENSION and Node.js v20.20.2. What do you tell them?
A) Install the current LTS (24 or newer), then open a NEW terminal
B) Run npm install in shoreline-api first
C) Rename server.ts to server.js
D) Start it with npx tsc server.ts
Why: Node 20 cannot run TypeScript files; the API needs Node to strip the types itself (Lesson 1.2, An old Node.js). A terminal opened before the install still finds the old Node.
B is wrong: The API has no dependencies: there is nothing to install.
C is wrong: It is TypeScript; renaming does not remove the types.
D is wrong: tsc checks types; it does not run a server.
Q11
npm run build prints error TS2551 and Found 1 error. What happened to vite build?
A) It built the site anyway, with the error inside
B) It printed a warning and continued
C) It built only the files without errors
D) It never ran: the build script is tsc -b && vite build
Why: && runs the second command only when the first one succeeded, so a type error stops the build before anything broken is written to dist/ (Lesson 1.2, The scripts).
A is wrong: Nothing is built when tsc fails.
B is wrong: A type error is an error here, not a warning.
C is wrong: There is no partial build: vite build does not start.

The Lesson Pages' Own Quick Quizzes

Lesson 1.1 · Why React + TypeScript
  1. C The script runs and prints NaN, with no warning: Node only strips the types and runs the JavaScript that is left. The misspelled property is undefined, undefined minus a number is NaN, and nothing warns you. Only the TypeScript compiler (or your editor) checks the types.
  2. A Updating the screen when a cleanup's number of sign-ups changes: React draws the screen from your data and updates it when the data changes. TypeScript checks that your code uses the data the way its types describe; it never touches the screen.
  3. D Never, unless your code checks the data itself: TypeScript only checks code before it runs and believes whatever type you declare for incoming data. Data from the outside must be checked while the app runs, which Lesson 2.4 and Module 8 teach.
  4. B At the line that uses the component with the string: Props are a contract. The error appears at the line that breaks it, where the component is used with a string, and it points back to the props type that declares a number.
  5. C It is a local back end with sample data that both course apps talk to: shoreline-api is a small mock back end that runs on your computer with sample data around today's date. Shoreline Crew HQ talks to it over HTTP, and the React Native course's phone app uses the same API and types.
Lesson 1.2 · Your Workspace
  1. B The page goes blank, because the browser fails while running code Vite never checked: Vite strips the types and serves the file unchecked. The browser fails when it calls a method that does not exist, React has nothing to draw, and the page is blank, with the error only in the developer tools console. The editor and tsc would have caught it before.
  2. D npm run build: The build script is tsc -b and then vite build, joined by and-and: vite build only runs when the type check passes, so a type error stops the build.
  3. A The API is already running in another terminal: Only one program can listen on a port. Another copy of the API is almost certainly running in a terminal you opened earlier: use it, or stop it with Ctrl+C first.
  4. C Changing into shoreline-hq first, then running the command: npm looks for package.json in the current folder. The app's package.json is in shoreline-hq, so cd shoreline-hq and run the command there.
  5. B In src/main.tsx, which calls createRoot on the root element and renders App: index.html loads src/main.tsx, which calls createRoot on the element with the id root and renders the App component into it. The exclamation mark tells TypeScript that element is not null.

Opening: Reading the Room

There is no retrieval warm-up in Session 1. The opening's two checks have their answers above: the environment check output (what READY looks like) and the diagnostic D1 to D6. Learners who end the clinic still NOT READY leave with a numbered plan in their workbook's Start Here box.

Exit Ticket

  1. Who does what: React draws the screen from the app's data and keeps it up to date (components, declarative); TypeScript checks before the code runs that the code treats the data the way its types describe.
  2. NaN versus the error: Node removes the types and runs the JavaScript, so undefined - 12 quietly becomes NaN; tsc reads the types and reports TS2551 with a suggestion. Running is not checking.
  3. Two terminals: shoreline-api running node server.ts (the API, http://localhost:4000) and shoreline-hq running npm run dev (the app, http://localhost:5173). The API first.

Common Wrong Answers and What They Reveal

  • Q1 A ("checks them, then runs"). Believes running includes checking. Rerun the NaN demo: who would have printed an error?
  • Q2 "Node prints NaN" or "612". Mixes - and + with strings. Run P1 and P2 side by side: - converts, + joins.
  • Q3 A (delete it from the interface). Fixes the description to match broken data. Ask which screens need spots taken.
  • Q4 A, B or D. Has not separated type errors from logic errors. Write capacity + spotsTaken on the board: which rule does it break? None.
  • Q7 A or B. Expects the dev server to check. Do Lesson 1.2's Exercise 1 live: the tagline stays.
  • Q11 A or C. Does not know what && does in the build script. Read "build": "tsc -b && vite build" together.
