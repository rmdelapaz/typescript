Forms and Actions

By the end you can
  • Explain the difference between controlled and uncontrolled inputs, and choose the right one for a field
  • Pass a function to a form's action and read the submitted FormData safely, narrowing FormDataEntryValue | null without as
  • Use useActionState to turn each submit into typed state, and isPending to show that a submit is in progress
  • Keep what people typed when a submit fails, and know why React resets a form after an action
  • Write field messages that say how to fix the problem, and connect them to their fields with aria-invalid and aria-describedby
  • Build the HQ's "Plan a cleanup" form, with checks that agree with the API's own rules
Key ideas
  • Controlled inputs keep their value in React state (value + onChange): for values the screen needs while typing. Uncontrolled inputs keep it in the browser (name, defaultValue) and are read through FormData when the form is sent.
  • A function in a form's action receives the FormData; React prevents the page load and RESETS the form afterwards (fields go back to their defaultValue).
  • formData.get() returns FormDataEntryValue | null (string, File or null): narrow with typeof value === 'string'. Every field needs a name; the submitting button's name and value are sent too.
  • useActionState(action, initialState) returns [state, formAction, isPending]; the action gets the previous state first, then the FormData, and returns the new state (a union on kind works well).
  • Messages that help say how to fix the problem, sit under their field, and are linked with aria-invalid and aria-describedby. noValidate keeps every message in one place. The API checks everything again.
  • The select quirk (React 19.3): a select reads its defaultValue only when it is created; key={values.siteId} makes a new one after the reset.

P2
Predict what npx tsc -b says, then put it in src/Scratch.tsx and run it. (useActionState with one argument.)
import { useActionState } from 'react'

function addBags(previous: number, formData: FormData): number {
  const bags = formData.get('bags')
  return typeof bags === 'string' ? previous + Number(bags) : previous
}

export function BagCount() {
  const [total, formAction] = useActionState(addBags)
  return (
    <form action={formAction}>
      <input aria-label="Bags" name="bags" type="number" />
      <button type="submit">Add</button>
      <p>{total} bags so far</p>
    </form>
  )
}

Glossary

TermMeaning
controlled inputReact state holds the value (value + onChange)
uncontrolled inputThe browser holds the value; you read it from FormData (name, defaultValue)
defaultValueThe starting text of an uncontrolled field (what the reset goes back to)
form actionA function in <form action={...}>: React calls it with the FormData and resets the form after it
FormData, FormDataEntryValueThe browser's collection of named fields; one value is File | string
submitterThe button that submitted the form; its name and value are sent too
useActionStateTurns each submit into state: [state, formAction, isPending]
isPendingTrue from the submit until the action's promise settles
noValidateTurns off the browser's own check bubbles so your messages are the only ones
aria-invalid, aria-describedbyTell assistive technology that a field is wrong and where its message is
fieldErrorsThe API's error shape: field name to a list of messages
SubmitEventReact's type for submit events in an onSubmit handler (FormEvent is deprecated)
