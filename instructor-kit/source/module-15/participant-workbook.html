Lessons

6.1

React Router 8

By the end you can
  • Explain what client-side routing changes compared with following plain links, and why the server must still answer every address
  • Describe an app's pages as typed route objects with createBrowserRouter, including a layout route, an index route and a catch-all * route
  • Navigate with Link and NavLink, style the current link through aria-current, and pass Link to a polymorphic component
  • Read URL parameters with useParams, narrow their string | undefined type, and reset a component's state with a key when only the parameter changes
  • Choose between a route's errorElement and your own error boundary, and keep the layout on screen when a page crashes
  • Move the focus and the scroll position after a page change so every visitor knows where they are
Key ideas
  • A router changes the address with the History API and renders the matching page without loading the app again. The server must still answer every address with index.html (a SPA fallback, Lesson 10.2).
  • Data mode: the routes are an array of typed route objects passed to createBrowserRouter, rendered by RouterProvider from react-router/dom. One package: react-router (never react-router-dom 7).
  • A layout route renders <Outlet /> where the child page goes; an index route is the page at its parent's address; a pathless route groups children (the HQ's errorElement); * catches the rest.
  • Link takes to and renders a real <a href>; NavLink adds aria-current="page", which is also what to style; Button as={Link} works with the polymorphic Button.
  • useParams values are string | undefined: narrow them; when only the parameter changes, the route stays the same, so key the page's state by the parameter.
  • After a navigation the app moves the focus to <main> and <ScrollRestoration /> handles the scroll; the title comes from useDocumentTitle.

6.2

Search Params, Nested Routes and Typed Navigation

By the end you can
  • Decide which state belongs in the address and which belongs in components
  • Read search params with useSearchParams and turn their string | null values into your own types with a type predicate
  • Change search params without losing the others, and choose between a new history entry and replace (plus flushSync for a text box)
  • Nest routes so a child page renders inside its parent's <Outlet />, with an index route for "nothing chosen yet"
  • Build relative links that keep the current search, and page through a list with links instead of buttons
  • Type route parameters with useParams<'name'>() and explain what href() and generatePath() check in data mode
Key ideas
  • State people want to keep, share or go Back to (filters, a search, a page number, the open item) belongs in the address; private or temporary state stays in components; secrets never.
  • useSearchParams() returns a URLSearchParams and a setter. Every value is string | null: narrow it with a type predicate (readParam), never with as.
  • Writing: change one name on a COPY of the current params (withParam), leave defaults out of the address; choices push (Back undoes them), typing replaces; a text box needs flushSync: true.
  • Nested routes: a route's children render at that route's <Outlet />; an index child is "nothing chosen yet"; the parent stays mounted (no list refetch).
  • Links resolve relative to their route. { pathname, search } keeps the query, { search } keeps the path. Pages of a list are links, so they can be shared and Back works.
  • Typed navigation: useParams<'name'>() checks the names you read, generatePath the names you build with; in data mode href() checks nothing. Hiding a page is courtesy; the API's 401 and 403 are the protection.

So the HQ checks the text with a generic helper that takes a type predicate. T is inferred from the predicate (isEventStatus gives EventStatus), and ?? 'all' supplies the default:

shoreline-hq/src/utils/searchParams.ts
export function readParam<T extends string>(
  params: URLSearchParams,
  name: string,
  isT: (value: string) => value is T,
): T | undefined {
  const value = params.get(name)
  return value !== null && isT(value) ? value : undefined
}

Its partner withParam changes one name on a COPY and removes an empty value, so defaults stay out of the address. Run on awkward values:

"" -> 1
"page=2" -> 2
"page=zero" -> 1
"page=2.5" -> 1
"page=0" -> 1
q=pelican | q=pelican&status=completed

Glossary

TermMeaning
router, client-side routingThe piece that changes the page when the address changes, without loading the app again
History APIThe browser's way to change the address and the Back/Forward list without a page load
data modeReact Router with route objects in createBrowserRouter([...]); needed for loaders and actions (Lesson 6.3)
route object, RouteObjectOne { path, element, children, errorElement, index } entry; a union of an index and a non-index route
layout route, <Outlet />A route whose element frames its children; the child page renders at the Outlet
index routeThe page at its parent's own address ("nothing chosen yet" in a nested route)
pathless routeA route with no path: it groups children so they share something (the HQ's error element)
catch-all route *Matches any address no other route matches: the not-found page
URL parameter, useParamsA :name segment of a path and the Hook that reads it (string | undefined)
Link, NavLink, aria-currentA router link (to); one that marks itself current with aria-current="page"
errorElementWhat a route renders instead of its page when something inside throws while rendering
SPA fallbackA host rule that answers every address with index.html (Lesson 10.2)
query string, search paramsEverything after the ?: name and value pairs, read with URLSearchParams
useSearchParams, setSearchParamsThe Hook that returns the current search params and a function that navigates to new ones
push, replaceAdd a history entry (Back undoes it) / overwrite the current one (Back skips it)
flushSync (router option)Apply this one update right away instead of as a transition: needed for a text box
nested routeA child route that renders inside its parent page, at the parent's Outlet
generatePath, href()Build a path from a pattern and values; generatePath checks the names in every mode, href only in framework mode
