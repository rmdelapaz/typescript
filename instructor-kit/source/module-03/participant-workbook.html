Lessons

2.3

Functions and Generics

By the end you can
  • Annotate a function's parameters and return type, and decide when an explicit return type is worth writing
  • Use optional, default and rest parameters and an options object, and read the errors for missing or misplaced arguments
  • Describe a function as a value with a function type, such as (event: CleanupEvent) => string, and pass typed callbacks
  • Write generic functions and types (first<T>, Page<T>) and let TypeScript infer the type arguments
  • Constrain a type parameter with extends so a generic function can use the properties it needs
  • Read overloaded and generic declarations in TypeScript's own library, such as querySelector and find
Key ideas
  • A function's contract: a type after each parameter, one after the parentheses for the return. TS2554 counts arguments; TS2345 checks each one. Write return types on functions other code relies on; void for functions that only print or save.
  • Optional x? (inside: T | undefined), default x = 'spots' (optional for the caller, never undefined inside), rest ...counts: number[]. Optional parameters go last (TS1016).
  • An options object destructured with defaults ({ showStatus = false }: LineOptions = {}) handles many options; a misspelled option is TS2561. React props work exactly like this.
  • Function types: type EventFormatter = (event: CleanupEvent) => string. Callbacks get their parameter types from the context; a function with fewer parameters fits.
  • Generics: first<T>(items: T[]): T | undefined; T is inferred from the argument. Generic types: Page<T>, Array<T>, Map<K, V>, later Promise<T> and useState<T>.
  • Constraints: T extends { id: string } lets the body use id and refuses items without one. TypeScript's own declarations (querySelector, find) read the same way.
Worked example: a generic and its constraint

first<T> reads its type from the argument, and keeps every check. With any, the misspelled .nmae passed the check and printed undefined; with the generic:

interface Site {
  id: string
  name: string
}

const sites: Site[] = [{ id: 'driftwood-cove', name: 'Driftwood Cove' }]
const bagCounts = [14, 9, 22]

function first<T>(items: T[]): T | undefined {
  return items[0]
}

const site = first(sites)
const count = first(bagCounts)
const nobody = first<string>([])

2.4

Typing Real Data

By the end you can
  • Share types between files with export and import type, and explain what verbatimModuleSyntax asks of you
  • Write type predicates (value is EventStatus) that turn unknown data into checked, typed data
  • Build new types from existing ones with Pick, Omit, Partial and Record, and read them in the API's real types
  • Read every line of the tsconfig files Vite created, and switch on noUncheckedIndexedAccess
  • Configure and type an environment variable (VITE_API_URL) and explain why front-end variables are never secret
  • Fetch cleanups from shoreline-api through a reusable, generic, checked client
Key ideas
  • Modules: export once, import type { … } from './shapes.ts' everywhere. verbatimModuleSyntax requires import type for types (TS1484): Node strips them, so there is nothing to import at run time.
  • Type guards: a return type value is EventStatus says what true means; TypeScript narrows with it like with typeof, and filter(guard) narrows the array. A guard is a promise TypeScript cannot check.
  • Object guards: isRecord(value) (an object, not null, not an array), then one check per property, chained with &&. Missing is not null.
  • Utility types: Pick<T, Keys>, Omit<T, Keys>, Partial<T>, Record<Keys, V> (every key required: lookup tables).
  • tsconfig: strict is the default in TypeScript 7; noUncheckedIndexedAccess makes items[0] a T | undefined (loops unaffected).
  • Environment variables: .env.example (in Git) and .env.local (yours); only VITE_ names reach the code, as text pasted into the build: nothing in the front end is secret. vite-env.d.ts types them.
Worked example: a boolean versus a type predicate

A type guard says what true means. With a plain boolean return type, the value inside the if is still unknown:

scratch.ts:11:25 - error TS18046: 'value' is of type 'unknown'.
Found 1 error in scratch.ts:11

With value is EventStatus, the same code checks clean and runs:

a status: SCHEDULED
not a status: finished
not a status: 42
[ 'draft', 'scheduled' ]

The last line is filter(isEventStatus): the result's type is EventStatus[]. The guard is a promise TypeScript cannot check: it must check every property its type promises.

TermMeaning

function type(event: CleanupEvent) => string: the type of a function value

generic, type parameterA function or type with a placeholder type T, filled in (usually inferred) at each use

environment variable, .env.localA setting that changes between machines / Vite's file for this machine's values
