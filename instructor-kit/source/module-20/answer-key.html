Session 20 12 self-check items Confidential

Warm-up

  1. **W1.** Lesson 7.3's homework: how many places in the HQ describe a valid cleanup? Name them. **Answer:** Four: eventForm.ts's types (EventField, EventFormValues), its rules (validateEvent, toNewEvent), client.ts's isCleanupEvent (the shape coming back), and the API's own checks. The first two are today's problem.
  2. **W2.** In Lesson 3.5's form, what kept a field's message linked to its box for screen readers? **Answer:** aria-invalid on the box and aria-describedby pointing at the message's id (FieldError).
  3. **W3.** After the API answers 400 with fieldErrors, where did Lesson 7.2 put the messages? **Answer:** Under the matching fields (the API uses the form's field names), plus "Some fields need attention." in the status line.

8.1 · React Hook Form + Zod: self-check

Q1
Lesson 7.3 asked you to count the places that describe a valid cleanup. What does a Zod schema change?
A) Nothing for the types: you still write EventFormValues by hand
B) The rules and their messages are written once, and the form's types are read from the same schema
C) The API no longer needs to check anything
D) The client's response guards (isCleanupEvent) disappear
Why: One value that runs (the checks) and gives types (z.input, z.output): add a field and both follow. The API still checks everything (some rules only it can), and the HQ keeps its hand-written response guards for a measured bundle reason.
A is wrong: z.input<typeof eventFormSchema> IS the form's values type now.
C is wrong: The form is a courtesy; the API is the lock.
D is wrong: Exercise 2 shows how; the lesson keeps them, because guests would download Zod.
Q2
The lesson puts the wrong thing in each of the schema's two types. What are capacity's input and output types?
src/Scratch.ts:4:14 - error TS2322: Type 'number' is not assignable to type 'string'.
src/Scratch.ts:5:14 - error TS2322: Type 'string' is not assignable to type 'number'.
Found 2 errors in the same file, starting at: src/Scratch.ts:4
Input string (what the box holds), output number (what the checked data holds)
Why: z.coerce.number<string>() turns the text into a number before the rules run. Fields hold the input; the submit function gets the output.
Q3
What does the when option on the end-time refine do?
A) Runs the rule only on the first submit
B) Skips the rule when the times are empty
C) Runs the rule as soon as the two times have no problem, whatever the other fields say
D) Turns the rule into a warning
Why: Zod normally runs an object's refine only when every field is valid, so the end-time message would wait until the title and capacity were fixed. when says which issues matter to this rule.
A is wrong: Timing is React Hook Form's mode, not Zod's.
B is wrong: Empty times have their own field rules.
D is wrong: Zod has no warnings: a failed refine is an issue.
Q4
Where does the list of eight names in this error come from? Nobody wrote a type argument.
src/Scratch.tsx:7:19 - error TS2345: Argument of type '"titel"' is not assignable to parameter of type '"capacity" | "date" | "description" | "endTime" | "meetingPoint" | "siteId" | "startTime" | "title"'.
Found 1 error in src/Scratch.tsx:7
From the schema: zodResolver(eventFormSchema) carries its input and output types, useForm infers them, and register accepts only the input type's keys
Why: In Lesson 3.5 EventField had to be written by hand to catch the same typo; now it comes from the schema.
Q5
Why does EditEventForm check isEventField(name) before setError, instead of writing name as EventField?
A) setError is slower with a cast
B) The cast does not compile
C) Object.entries returns numbers
D) The API could send a key the form does not have, and its message would vanish into an error nobody displays
Why: The API's fieldErrors keys are plain strings (JSON from outside). A type predicate checks them for real; a cast only silences tsc.
A is wrong: Speed has nothing to do with it.
B is wrong: as EventField compiles: that is the danger.
C is wrong: Object.entries gives string keys (hence the TS2345 without the check).
Q6
Why does the HQ keep its hand-written response guards in client.ts instead of Zod schemas?
A) Zod would add about 25 kB gzip to every visitor's download, while only organizers open the forms
B) Zod cannot check API responses
C) The guards are faster at run time
D) TypeScript cannot compare a schema with types.ts
Why: Measured in the lesson: Zod's full API about 103 kB (25 kB gzip). Kept with the organizer forms, Lesson 10.1 can load it only for them. The build already went from 431.11 to 561.81 kB and warns about a chunk over 500 kB.
B is wrong: Exercise 2 does exactly that.
C is wrong: Not the reason given or measured.
D is wrong: z.ZodType<CleanupEvent> makes tsc compare them (Exercise 2).

8.1 · React Hook Form + Zod: predict, then check

P1
Weekend Cove Cleanup is full (18 of 18). An organizer saves capacity 10. The schema accepts it: what does the API answer?
PATCH http://localhost:4000/api/events/e08   {"capacity": 10}
HTTP/1.1 400 Bad Request
content-type: application/json; charset=utf-8

{
  "error": "validation_failed",
  "message": "Some fields need attention.",
  "fieldErrors": {
    "capacity": [
      "18 volunteers already hold a spot: capacity cannot be lower."
    ]

Why: 400 with a capacity message only the API can give: it knows 18 people hold a spot. setError puts it under the capacity box and focuses it; typing a new value clears it (the schema has no objection), and the next save asks the API again.

8.2 · Complex Forms: self-check

Q7
The lesson runs this comparison with Node. Why do the impact report's counts not use z.coerce.number()?
0
Enter a whole number.
12
Coercion turns an empty box into 0, a valid count, so a skipped box would quietly report "zero"; checking the text first gives a message
Why: For capacity, 0 failed the 1-to-200 rule anyway; for a count, 0 is a real answer. Regex, then transform(Number): input string, output number.
Q8
Row 3 repeats Plastic bottles. Which path does the superRefine give its issue, so the message lands on the right box?
A) ['items']
B) ['items', 'category']
C) ['items', 2, 'category'] (the path relative to the list is [2, 'category'])
D) ['plastic-bottles']
Why: addIssue's path is relative to the array the refine sits on: [index, 'category']. The resolver turns it into items.2.category, the repeated row's menu.
A is wrong: That would be a message about the whole list, under no box.
B is wrong: No row index: which row?
D is wrong: Paths name places in the data, not values.
Q9
A keyboard user presses Remove on row 1 and the code does nothing about focus. Where is the focus afterwards?
A) On the next row's Remove button
B) On the page's body: the next Tab starts again from the top
C) On the error summary
D) Still on the removed button
Why: Measured in the lesson: document.activeElement was <body>. Whenever a click removes the element that was clicked, decide where the focus goes (the HQ: Add a row).
A is wrong: Browsers do not move focus to a sibling by themselves.
C is wrong: Nothing focuses the summary on a removal.
D is wrong: It is gone from the page.
Q10
The photo box has accept="image/jpeg,image/png,image/webp". Why does the HQ still check the file before uploading?
A) accept makes the request slower
B) The API does not check files
C) TypeScript requires it
D) accept is only a hint to the picker: "All files", drag and drop and a 40 MB photo all get past it
Why: The browser's check saves a pointless request and gives a message at once; the API checks again anyway (its answer to a GIF: 415, "Photos must be JPEG, PNG or WebP images.").
A is wrong: accept changes nothing about the request.
B is wrong: It does: 413 and 415.
C is wrong: Types say nothing about a file's content.
Q11
saveImpactMutation writes the PUT's answer with setQueryData before invalidating ['events'] and ['impact']. What does that buy?
A) The Impact tab shows the new numbers at once, instead of the old ones for a moment
B) It saves the PUT
C) It stops the dashboard from updating
D) Nothing: invalidation alone does the same
Why: Measured with --latency=1000: invalidation only showed "Volunteers: 10." then 12 a second later; with the answer written first, 12 at once. Use an answer you already have.
B is wrong: The PUT is the mutation itself.
C is wrong: ['impact'] is invalidated so the dashboard updates.
D is wrong: The measured flash says otherwise.
Q12
The error summary's links focus their field with a click handler instead of a plain href="#bags". Why?
A) Plain # links do not work in any browser
B) A # link adds #bags to the address and a history entry, so Back first undoes the jump
C) Click handlers are faster
D) TypeScript cannot type href
Why: Measured in Chromium: href="#bags" does focus the box, but writes #bags into the URL. The handler focuses and keeps the address clean.
A is wrong: Chromium did focus the box.
C is wrong: Not the point.
D is wrong: href is a string; nothing to do with it.

8.2 · Complex Forms: predict, then check

P2
A GIF sent to the photo endpoint as a raw body. Predict the status code and the message.
POST http://localhost:4000/api/photos   Content-Type: image/gif
{
  "error": "unsupported_media_type",
  "message": "Photos must be JPEG, PNG or WebP images."
}
HTTP 415
Why: 415 with a sentence written for people: the HQ shows the API's message for 413 and 415.
P3
The same endpoint, with a hand-written Content-Type: multipart/form-data header (no boundary). Predict the status and which field the API says is missing.
POST http://localhost:4000/api/photos   Content-Type: multipart/form-data
{
  "error": "validation_failed",
  "message": "Some fields need attention.",
  "fieldErrors": {
    "photo": [
      "Attach an image in a field named photo."
    ]
  }
}
HTTP 400
Why: 400: without a boundary the API cannot split the body into parts, so it never finds the photo field. Trying again would not help: leave the header to fetch.

The Lesson Pages' Own Quick Quizzes

Lesson 8.1 · React Hook Form + Zod
  1. B string in, number out: The type argument makes the input string (what the box holds), and coerce turns it into a number before the rules run, so the output is number. tsc showed both with TS2322.
  2. D Drop the type argument, or write useForm<EventFormValues, unknown, EventFormData>: z.infer is the output type, but the fields hold the input. Either let zodResolver infer both (no type argument) or give all three: input, context, output.
  3. A setError('capacity', …) shows the API's message under the field and moves the focus there: save catches the ApiError, checks each key with isEventField, and calls setError, which shows the message under the capacity field and focuses it. The root error fills the status line.
  4. C The title and capacity messages; the end-time message waits until they are fixed: An object's refine runs only when every field is valid, so the end-time rule waited behind the title and capacity. Measured with the test file: two messages. when lets the rule run as soon as both times are valid.
  5. B The shared schema already removed the duplicated rules, and the form needs nothing more that RHF adds: The duplicated rules were the real problem, and safeParse with the shared schema fixed that. The action form works, has no dependency, and needs none of RHF's extras such as defaultValues from saved data or dirty fields.
Lesson 8.2 · Complex Forms
  1. C field.id: useFieldArray gives every row an id that stays with its data when rows are added or removed, which is what a key is for. The index still goes in the field paths, because it says where the value is now.
  2. A So every failed Save creates a new summary, which takes the focus again, while fixing fields does not: A new key makes React create a new summary on every Save, so its effect runs again and the focus moves to it, while typing between saves only changes its list and leaves the focus alone.
  3. D The API answers 400: without the boundary it cannot find the photo field: The hand-written header has no boundary, so the API cannot split the body into parts, finds no photo field, and answers 400. With a FormData body, fetch writes the header with the boundary itself.
  4. B A union including template literal types such as `items.${number}.count`: React Hook Form builds every path from the form's input type with template literal types, so one type covers every row index and only the real field names. tsc listed them in TS2345.
  5. B A volunteer application where the questions depend on the role chosen first, ending with a review before sending: Separate tasks, later questions that depend on earlier answers, and a review before a commitment are the signs that steps help. The impact report has none of them.

Exit Ticket

  1. Capacity: string in (the box), number out (the checked data).
  2. Duplicate row: under the repeated row's menu, via addIssue with path: [index, 'category'] in the array's superRefine.
  3. No Content-Type: fetch writes multipart/form-data with the boundary; a hand-written header has none.

Common Wrong Answers and What They Reveal

  • Item 1 C. Thinks the schema replaces the server. Ask who can know that 18 people are signed up.
  • Item 3 B or D. Confuses Zod's when with RHF's mode. Run try-schema with and without when.
  • Item 5 B. Thinks the cast does not compile: it does, which is the danger.
  • Item 10 B. Believes the API trusts the browser. Show the 415.
  • Item 11 D. Expects invalidation to be instant. Show the measured flash.
