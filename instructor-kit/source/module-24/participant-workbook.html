Lesson

10.2

Deploying

By the end you can
  • Explain the HQ's environments (development, tests, preview, demo, deployed) and how Vite modes and import.meta.env decide what each build contains
  • Build a demo version that runs shoreline-api's own code in the browser through MSW's service worker, without a byte of it reaching the normal build
  • Make deep links work on a static host with a _redirects fallback, and set caching and security headers with _headers
  • Write a GitHub Actions workflow that runs the type check, lint, unit tests, both builds and the Playwright suite against the real API on every push
  • Choose a host by reading its current terms, deploy a draft and then production with the Netlify CLI, and check the live site from the outside
Key ideas
  • Environments are builds: development, unit tests, e2e, demo, deployed. Vite replaces import.meta.env.MODE and every VITE_ value with text at build time; a branch that is always false disappears with its imports.
  • The demo build (npm run build:demo, mode demo) runs shoreline-api's own core in the browser through MSW's service worker: works on any static host, private sample data per visitor, resets on reload, a banner that says so.
  • A build decision belongs in the build: MODE, never the hostname.
  • Static hosts: public/_redirects /* /index.html 200 for deep links; public/_headers: /assets/* immutable for a year, index.html checked every visit, three security headers.
  • CI (GitHub Actions): one repository (the course folder), two jobs; npm ci, tsc -b, lint --deny-warnings, Vitest, both builds; then e2e against the real API with needs: checks.
  • Hosts' terms: Netlify Free 300 credits a month, 15 per production deploy: deploy by hand after green checks (draft, look, --prod).

Glossary

TermMeaning
environmentOne place the code runs, with its own settings (and, for a front end, its own build)
Vite mode, import.meta.env.MODEdevelopment, production, test or any --mode name; replaced with text at build time
demo buildnpm run build:demo: the API's code runs in the visitor's browser through MSW
service workerA script the browser installs for a site; it can answer the site's requests
static host, CDNServes a folder of files over HTTPS from servers around the world; runs none of your code
SPA fallback/* /index.html 200: every address without a file gets the app's page
Cache-Control: immutableKeep this file; it never changes (safe for hashed file names)
continuous integration (CI)A computer runs the checks on every push and marks the change green or red
workflow, job, step, runnerGitHub Actions' YAML file / a group of steps on one machine / one command or action / the machine
needsOne job waits for another and is skipped if it fails
artifactA file a run keeps for download (the Playwright report on failure)
draft / production deployA temporary address to look at / the live address (15 credits on Netlify Free)
launch-readiness checklaunch_check.mjs: Git, repository, workflow, host files, remote, Netlify link, and the by-hand list
