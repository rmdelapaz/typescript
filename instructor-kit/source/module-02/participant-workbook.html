Lessons

2.1

Types and Inference

By the end you can
  • Set up a TypeScript workbench (ts-lab) with its own package.json, tsconfig.json and a check script
  • Predict the type TypeScript infers for a value, including the difference between let and const
  • Decide when to write a type annotation: parameters, values that arrive later, and empty arrays
  • Use the basic types (string, number, boolean, null, undefined) and typed arrays
  • Explain why unknown is safer than any for data from outside your program, and check an unknown value with typeof
  • Read the errors TS2322, TS2345, TS7006, TS18046 and TS18047 and know what each one is asking you to fix
Key ideas
  • ts-lab is a small Node project next to the app: its own TypeScript (--save-dev --save-exact), a strict tsconfig, npm run check = tsc --noEmit. node file.ts runs; npm run check checks every .ts file in the folder.
  • Inference: TypeScript reads the value. let gets a general type (number); const gets a literal type (18, "Shoreline Crew"). Inferred types are checked as strictly as written ones.
  • Annotate the edges: parameters (TS7006 otherwise), values that arrive later, empty arrays, outside data. Return types and callback parameters are usually inferred.
  • Basic types are lowercase: string, number, boolean, null, undefined; arrays string[] (= Array<string>). With strict checks, null is its own type.
  • any vs unknown: both accept anything; any checks nothing (and spreads), unknown must be narrowed (for example typeof x === 'string') before use. Outside data is unknown.
  • Errors are questions: TS2322 (value does not fit), TS2345 (argument does not fit), TS7006 (parameter needs a type), TS18046 (check the unknown), TS18047/18048 (handle nothing).

2.2

Shaping Data

By the end you can
  • Describe objects with object types and interfaces, including nested objects, and read the errors for missing, misspelled and extra properties
  • Choose between interface and type, and build one shape on another with extends or &
  • Mark properties optional (?) or read-only (readonly) and say what each promise means for the code that uses them
  • Model "one of these" with unions and literal types, such as a cleanup's four statuses
  • Narrow a union with typeof, equality, in and a discriminant property, and check an unknown value that should be an object
  • Handle null and undefined with an if, ?? and ?., and know when the ! assertion is honest
Key ideas
  • Object types and interfaces: list each property and its type. Object literals are checked for missing (TS2741), misspelled (TS2561, with a suggestion) and extra (TS2353) properties.
  • interface or type: both describe objects; only type names a union. Build on shapes with extends (interface) or & (type). Course convention: interface for objects, type for the rest.
  • Optional ? reads as T | undefined everywhere; readonly forbids changing a property after creation (a check, not a lock).
  • Unions: A | B is "one of these"; a union of literal types ('sand' | 'rocky' | 'marsh' | 'mixed') is a fixed list. Annotate objects where you create them, or their properties widen to string.
  • Narrowing: typeof, ===/switch, a discriminant property (kind), in, and the object check typeof x === 'object' && x !== null && 'name' in x.
  • Maybe nothing: if, ?? (not ||: 0 and '' are real values), ?. (then ??); ! only for what your own project guarantees.
Worked example: the widening trap

The widening trap: the object is built first and typed later.

type Terrain = 'sand' | 'rocky' | 'marsh' | 'mixed'

interface Site {
  name: string
  terrain: Terrain
}

function describeSite(site: Site) {
  return `${site.name} (${site.terrain})`
}

const flats = { name: 'Sandpiper Flats', terrain: 'marsh' }
console.log(describeSite(flats))

Glossary

TermMeaning
ts-labThe course's TypeScript workbench: a small Node project next to the app (Module 2)
type inferenceTypeScript working out a type from a value, an expression or the context
literal typeA type that is one exact value: 18, "Shoreline Crew", 'draft'
annotationA type you write after a name: capacity: number
any / unknownAccepts anything and checks nothing / accepts anything but must be checked before use
narrowingA check (typeof, ===, in, a discriminant) that makes a type more precise inside its branch
strict modeThe full set of strict checks (no implicit any, strict null); on by default in TypeScript 7
object type, interfaceA description of an object's properties / a named one
type aliastype Name = …: a name for any type, unions included
optional propertycheckInCode?: string: may be absent; reads as string | undefined
union typeA | B: a value that is one of the members
discriminated unionA union of object types told apart by one shared literal property (the discriminant, kind)
?? / ?.Nullish coalescing (a fallback for null/undefined) / optional chaining (stop at null/undefined)
! (non-null assertion)A promise that a value is not null or undefined, which TypeScript does not check
excess property checkTypeScript's check for properties an object literal has but its type does not (TS2353, TS2561)
