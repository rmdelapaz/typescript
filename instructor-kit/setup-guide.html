Set Up Your Workspace for the Course

About 45 to 60 minutes to do before the first session: install Node.js and VS Code, make your course folder, start the course's small Shoreline Crew API on your own computer, create the Shoreline Crew HQ app with Vite, and run a short check that tells you (and your instructor) whether your laptop is ready. These are the same steps as Lesson 1.2 on the course site (rays-typescript.netlify.app, lesson "Your Workspace"), which shows each one with pictures. Session 1 then spends its time on React and TypeScript instead of installers. Joining for Part 2 or Part 3 only? Do Steps 1 and 2, then see Joining Part 2 or Part 3 near the end.

⏱ 45–60 min Windows · Mac · Linux Free software only No accounts needed until Session 24
Please do this at home, not in class

Each install is quick on its own, but twenty laptops downloading Node.js, VS Code and a new project's packages at once over venue Wi-Fi can fill most of a session. If a step fails, do the others and bring the exact error message (a screenshot is fine) to Session 1: it opens with the environment check, and Lesson 1.2's time in the room is an install clinic.

What You Need

  • A laptop and its charger: Windows 10 or 11, a recent macOS, or a 64-bit Linux, with a few gigabytes of free disk space (each project installs its packages into its own node_modules folder). You need permission to install software. Chromebooks, tablets and locked work laptops cannot run the course comfortably: talk to your instructor first.
  • Node.js, the current long-term-support (LTS) version, 24 or newer, with npm (Step 1). The course was checked on Node 24; its API also on Node 26.
  • VS Code (free), with TypeScript 7 support (Step 2).
  • A web browser with developer tools: a current Chrome or Edge, or Firefox. The course's instructions follow these; Safari works for viewing pages.
  • The course's labs/ folder, which your instructor sends with this guide. Its file labs/module-01/l1_0-orientation/check_environment.mjs is the environment check in Step 5.
  • A learning journal: a file or a notebook. Every lesson ends with a journal prompt.
  • Later, not now: Git and two free accounts, GitHub and Netlify, for the launch in Session 24 (Lesson 10.2) and your final project. See Accounts for the Launch below.

Am I Ready for This Course?

This course is for people who know JavaScript and are new to TypeScript and React. It teaches TypeScript and React from the start, but it does not teach JavaScript from scratch. You are ready if you can:

  • ☐ Write a JavaScript function, with const and let, an if and a loop, and call it
  • ☐ Read an array of objects, such as [{ title: 'Weekend Cove Cleanup', capacity: 18 }], and get one value out of it, including from an object inside an object
  • ☐ Say what map and filter do to an array (or look it up and use it)
  • ☐ Explain what fetch returns and what await does with it
  • ☐ Write a small HTML page with a stylesheet, and change a page with the DOM (document.querySelector)
  • ☐ Open a terminal, move between folders with cd, and run a command someone gives you

Two or more unchecked? Come anyway and tell your instructor. Session 1 includes a short, ungraded JavaScript diagnostic on these same skills, so your instructor knows where to help, and a practice file for anything you miss.

Set Up in 5 Steps

1

Install Node.js (the current LTS, 24 or newer)

~10 min

Node.js runs JavaScript (and, from version 24, TypeScript files) outside the browser. Almost every tool in the course is a Node program: the course's API, Vite, the TypeScript compiler, the linter and the test runners. npm, the package manager, comes with it.

  • Windows: on nodejs.org, download the LTS Windows installer (.msi) and run it, keeping the defaults (they add Node and npm to your PATH). You do not need the extra "tools for native modules". With the Windows package manager, winget install OpenJS.NodeJS.LTS does the same.
  • macOS: the same site, the LTS macOS installer (.pkg). Homebrew or a version manager is fine too if you already use one.
  • Linux: your distribution's own Node is often too old. Use the Node.js download page's instructions for a version manager such as nvm, open a new terminal, then nvm install --lts.

Then open a new terminal (Windows: PowerShell or Command Prompt; macOS: Terminal) and run:

node -v
npm -v

The first number after the v must be 24 or higher (for example v24.22.2), and npm must answer (for example 11.19.1). Older versions do not work: the course's API needs a Node that runs TypeScript files directly, and Node 20 stops with ERR_UNKNOWN_FILE_EXTENSION. If you have an older Node, install the current LTS over it.

2

VS Code and its TypeScript support

~10 min
  1. Download VS Code from code.visualstudio.com and install it with the defaults. On Windows, keep Add to PATH ticked so the code command works in a terminal.
  2. In VS Code's Extensions view (Ctrl+Shift+X, Mac ⌘ Cmd+Shift+X): if your VS Code does not already use TypeScript 7, install TypeScript (Native Preview) (identifier TypeScriptTeam.native-preview). Optionally install Oxc (identifier oxc.oxc-vscode), which shows the linter's warnings as you type. Check the publisher before you click Install: copycat extensions exist.
  3. Hold off on other extensions (formatters, snippet packs): the course explains why in Lesson 1.2.

Four things you will use all course: File › Open Folder… (open a folder, not a file), the built-in terminal (View › Terminal, Ctrl+`; the + button adds a second one), the Problems panel (Ctrl+Shift+M) and the Command Palette (Ctrl+Shift+P; ⌘ Cmd on a Mac).

3

Your course folder and the Shoreline Crew API

~10 min

Every lesson builds Shoreline Crew HQ, the organizers' web app of a fictional volunteer beach-cleanup group. Its data comes from a small API the course gives you: no install, no accounts, it runs on your own computer.

  1. Create a folder called shoreline somewhere easy to find, such as Documents, but not in a folder synced by OneDrive, iCloud or Dropbox (npm writes thousands of small files and syncing makes it crawl).
  2. Download shoreline-api.zip from the course site (Lesson 1.2, or rays-typescript.netlify.app/downloads/shoreline-api.zip), or take the copy your instructor gives you, and unzip it into shoreline (Windows: right-click › Extract All…; Mac: double-click).
  3. Check: shoreline/shoreline-api/server.ts must exist. Some unzip tools add a folder level (shoreline-api/shoreline-api/): move the inner folder up one level.
  4. In VS Code, File › Open Folder… (Mac: File › Open…), open shoreline, and answer Yes, I trust the authors.
  5. Open the terminal (View › Terminal) and start the API:
cd shoreline-api
node server.ts
Shoreline Crew API running at http://localhost:4000/api
  sample sign-in: maya.okafor@example.com (organizer) or theo.nakamura@example.com (volunteer), password shoreline-demo
Press Ctrl+C to stop.

There is no npm install: the API has no dependencies. This terminal now belongs to the server; leave it running. Open http://localhost:4000/api in your browser: it answers with JSON. The API keeps its data in memory, so a restart brings the sample data back fresh.

4

Create Shoreline Crew HQ with Vite

~10 min

Open a second terminal (the + button in the terminal panel). It starts in shoreline; if its prompt says shoreline-api, type cd .. first. Then:

npm create vite@latest shoreline-hq -- --template react-ts
  • Ok to proceed? (y): press Enter (npm asks before it downloads the project creator).
  • Which linter to use?: keep Oxlint and press Enter.
  • Install with npm and start now?: press → to select No, then Enter.

Then follow the three lines it prints:

cd shoreline-hq
npm install
npm run dev

Open http://localhost:5173/: the template's starter page with a Count is 0 button. Stop the dev server with Ctrl+C (Windows may ask Terminate batch job (Y/N)?: type Y). Lesson 1.2 in Session 1 turns this page into Shoreline Crew HQ.

5

Put labs/ in place and run the environment check

~5 min

Copy the labs/ folder from your instructor into your course folder:

shoreline/
  shoreline-api/
  shoreline-hq/
  labs/        <- here

With the API still running in its terminal, go to the other terminal, move back to shoreline (cd ..) and run:

node labs/module-01/l1_0-orientation/check_environment.mjs

It asks Node, npm and VS Code for their versions, looks for shoreline-api and shoreline-hq in the folder you run it from, asks the API a few questions, runs the type checker and the linter in shoreline-hq, and starts the dev server for a moment on a spare port. It changes nothing. Each line says OK, CHECK (works; read the note) or FIX (do this next). Output on a ready laptop (your versions will differ):

Environment check for React + TypeScript: Build a Modern Web App
Course folder: shoreline
OK    Node.js v24.22.2 (24 or newer)
OK    npm 11.19.1
OK    VS Code 1.146.0
OK    shoreline-api is in the course folder
OK    shoreline-hq: React 19.3.1, TypeScript 7.0.2, Vite 8.3.8, oxlint 1.93.0
OK    the API answers at http://localhost:4000/api: "Many hands, cleaner sands.", 15 public cleanups
OK    tsc -b: no type errors
OK    oxlint (npm run lint): Found 0 warnings and 0 errors.
OK    the dev server starts (npm run dev) and serves the app
READY for React + TypeScript: Build a Modern Web App
✅ Done when the last line says READY (or READY WITH NOTES)

Send that line to your instructor. READY WITH NOTES is fine: read the CHECK lines (for example "no code command", which only means VS Code's command-line launcher is not on the PATH). NOT READY? Fix the FIX lines from the top (each says what to do), run the check again, and if you are stuck, send the whole output.

Finally, write a short "My workspace" entry in your journal: your Node version, where your shoreline folder is, and the routine to start work (terminal 1: cd shoreline-api, node server.ts; terminal 2: cd shoreline-hq, npm run dev).

Common Install Problems

You see…Try this
'node' is not recognized… or command not found: nodeThe terminal was opened before Node was installed. Close every terminal, VS Code included, and open a new one. Windows: run the installer again and keep "Add to PATH". nvm: open a new terminal.
PowerShell: npm.ps1 cannot be loaded because running scripts is disabledA Windows safety setting, not a broken install. Use Command Prompt, or allow your own scripts: Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
node server.ts stops with ERR_UNKNOWN_FILE_EXTENSION and Node.js v20…An old Node is first on your PATH. Install the current LTS; with nvm: nvm install --lts and nvm alias default lts/*, then a new terminal.
The check says FIX nothing answers at http://localhost:4000The API is not running. Terminal 1: cd shoreline-api, node server.ts, and leave that terminal open.
port 4000 is already in useThe API is already running in another terminal. Use that one, or stop it with Ctrl+C first.
FIX no shoreline-api/server.ts here, or shoreline-api/shoreline-apiRun the check from shoreline (cd into it); if the unzip tool added a level, move the inner shoreline-api up one.
FIX no shoreline-hq hereStep 4 was skipped or ran in the wrong folder: in shoreline, npm create vite@latest shoreline-hq -- --template react-ts, then cd shoreline-hq and npm install.
npm error enoent Could not read package.jsonAn npm command in shoreline instead of shoreline-hq. Read the prompt before every command: cd shoreline-hq.
The check says this folder is synced to the cloud, or npm is very slowMove shoreline out of OneDrive, iCloud or Dropbox.
Vite says Local: http://localhost:5174/Port 5173 is taken by another dev server: use the address Vite prints, or stop the other one.

More cases, each with the exact error text: Lesson 1.2's Common Mistakes section and the course's Troubleshooting page, rays-typescript.netlify.app/troubleshooting.html (sections "Could not read package.json", "running scripts is disabled", "ERR_UNKNOWN_FILE_EXTENSION", "port 4000 is already in use", "Failed to fetch", and, later, "CI" and "The live site says it can't reach the server").

Accounts for the Launch (Session 24)

Nothing in Sessions 1 to 23 needs an account. In Session 24 (Lesson 10.2) you make a demo build of Shoreline Crew HQ (its API runs inside the browser, so the site works without your computer), put the course folder on GitHub with automatic checks (GitHub Actions) and publish the demo on Netlify's free plan. Session 23's homework suggests creating the two free accounts beforehand; you can also create them in class, with your instructor. Install Git before Session 24: git-scm.com on Windows (Git for Windows), xcode-select --install on macOS, your package manager on Linux; git --version checks it. Signing up for Netlify with your GitHub account is fine. Session 24 opens with a launch-readiness check that tells you what is still missing.

  • No real deployment is required to pass Session 24. Your final project does go public, though (its rubric asks for a link on a free static host): you need a GitHub account by its first milestone and a Netlify account by its second.
  • Never type your GitHub password into the terminal: the first push asks you to sign in through a browser window, GitHub's gh auth login, or a personal access token (Lesson 10.2 points to each).
  • Credits: on Netlify Free, a production deploy uses 15 of the plan's 300 monthly credits. Look at a draft deploy first. Vercel is compared in Lesson 10.2; its free Hobby plan is for personal, non-commercial projects only.

Frequently Asked

Do I need to know TypeScript or React?

No. Module 2 teaches the TypeScript you need before React, and React starts from the first component in Module 3. You need JavaScript.

Can I use pnpm, Yarn or Bun instead of npm?

They work with Vite projects, but the course uses npm because it comes with Node.js, so every command in the lessons and the downloads matches exactly. If you use another one, translate the commands yourself.

Does stopping the API lose my work?

Your code is just files in your course folder and stays. The API's data lives in memory: a restart brings the sample data back fresh, which is a feature when your app has changed it. Start the API before you work, every time.

Is the course data real?

No. Shoreline Crew, its beaches, cleanups, volunteers and email addresses are invented for the course, and so are the clients of the part projects. The sample password shoreline-demo is public on purpose: it only works on the practice API.

What if a step fails and I cannot fix it?

Come anyway, with the output of the environment check. Session 1 opens with the check and has an install clinic, and you can pair with a neighbor until your laptop is ready.
