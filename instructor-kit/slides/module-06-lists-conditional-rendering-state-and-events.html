Lists and Conditional Rendering

Data in, elements out, nothing changed along the way.

3.3 · Mental model

Name tags at check-in

  • A key tells React which new item is which old item
  • From the data (event.id), unique among siblings, stable
  • On the element map returns: the <li>
  • An index is "third from the left": wrong after an insert
WATCH Neither tsc nor oxlint flags index keys. Only the data's id is safe.

3.4

State and Events

Give components a memory, and decide where it lives.

3.4 · Mental model

The roster on the clipboard

  • React keeps the clipboard between renders: state
  • You read it each render, and change it with one pen: the setter
  • A local variable is writing on your palm
  • Calling the setter asks for a new render

3.4 · useState types

Annotate the edges

  • useState(''): inferred string
  • useState<StatusFilter>('all'): one word of a union
  • useState<string[]>([]): not never[]
  • useState<CleanupEvent | null>(null): nothing yet
3.4 · Snapshots

Copy, don't change

  • Depends on the old value? setBags((current) => current + 1)
  • [...ids, id] not push · filter not splice
  • toSorted() not sort · { ...filters, query }
  • push + set the same array: no redraw, and no tool warns
WATCH React compares with Object.is: same array, nothing changed.
3.4 · Where state lives

Lift it, then derive the rest

  • Can it be worked out? Then it is not state
  • Who reads it and who changes it? Closest common parent
  • Children get values as props, report changes through callbacks
  • A stored filtered list is one keystroke behind
