7.1 · Mental model

The harbor office's logbook

  • Each entry: a label, a reading, when it was taken
  • Recent: you get it at once
  • A bit old: at once, and someone walks to the station
  • No entry: someone walks, you wait
  • Label = key · walk = query function · recent = staleTime
7.1 · Live demo

The client and its two defaults

shoreline-hq/src/api/queries.ts
export const queryClient = new QueryClient({
  defaultOptions: {
    queries: {
      // An answer counts as fresh for 30 seconds: no new request for it in that time
      staleTime: 30_000,
      // Try again after a network or server failure, but never after 401, 403 or 404:
      // asking again will not change those answers
      retry: (failureCount, error) =>
        !(error instanceof ApiError && error.status < 500) && failureCount < 2,
    },
  },
})
WHY Fresh for 30 seconds; a 401, 403 or 404 is never retried.
7.1 · Live demo

A factory: key and function together

shoreline-hq/src/api/queries.ts
export function eventsQuery(search: string, viewer: string) {
  return queryOptions({
    queryKey: ['events', 'list', search, viewer],
    queryFn: ({ signal }) => getEvents(search, signal),
  })
}
RULE The key holds everything the answer depends on: general → specific, viewer last.

7.1 · Fresh, stale, retried

Which rule sent this request?

  1. In the cache? No: fetch, show Loading
  2. Fresh (younger than staleTime)? Show it, no request
  3. Stale? Show it, and refetch behind it
  4. gcTime: when an unused entry is forgotten (5 min)
WHY Stale controls requests; gcTime controls memory.
7.1 · A 404 is an answer

7.1 · Loaders on the cache

The loader fills, the page reads

shoreline-hq/src/pages/loaders.ts
/** /sites: the six beach sites */
export async function sitesLoader() {
  // staleTime 'static': cached sites (however old) are good enough to show at once
  await queryClient.query({ ...sitesQuery(), staleTime: 'static' })
  return null
}
WHY staleTime: 'static': any cached copy is good enough. ensureQueryData is deprecated in 5.107.
