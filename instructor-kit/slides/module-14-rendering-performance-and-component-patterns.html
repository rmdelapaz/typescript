5.3 · Mental model

Three reasons a component renders

  • Its own state changed: typing calls setQuery
  • Its parent rendered: EventsPage renders, so every card renders
  • A context it reads changed: sign-out, every useAuth() reader
  • Render = call the function · commit = change the DOM that differs
WATCH Typing pelican: 560 component calls, 80 per key, and nothing inside the cards changed.
5.3 · Mental model

The tide chart

  • Each render redraws the whole chart from the latest readings
  • Then compares it with the one on the wall
  • Only the lines that moved get repainted
  • Performance work: skip redrawing what cannot have changed
RULE Re-rendering is not a bug. Expensive re-rendering for nothing is.

5.3 · memo and useCallback

memo needs props that stay the same

const removeSupply = useCallback((supply: string) => {
  setSupplies((current) => current.filter((item) => item !== supply))
}, [])
WHY A function made in the body is new every render; memo sees a changed prop. useCallback + the updater form keeps it.
5.3 · The pair rule

memo, useCallback, useMemo

  • memo(Component): skip a component when every prop is the same
  • useCallback(fn, deps): the same function until a dependency changes
  • useMemo(() => value, deps): the same value until a dependency changes
  • Alone, useCallback does nothing: someone must compare it
MEASURED Report screen, 100,000 entries: 30 ms per key without useMemo, 0.5 ms with it.
5.3 · Context

memo never blocks a context update

function UnitProvider({ children }: { children: ReactNode }) {
  const [unit, setUnit] = useState<WeightUnit>('kg')

  const toggleUnit = useCallback(() => {
    setUnit((current) => (current === 'kg' ? 'lb' : 'kg'))
  }, [])
  // A new object only when unit changes, so readers skip renders that change nothing
  const value = useMemo(() => ({ unit, toggleUnit }), [unit, toggleUnit])

  return <UnitContext value={value}>{children}</UnitContext>
}
MEASURED DayTotal: memo, no props, five renders for five keys. With a stable value: zero.

5.4 · Polymorphic

One Button, any element

shoreline-hq/src/components/Button.tsx
export function Button<C extends ElementType = 'button'>({
  as,
  variant = 'secondary',
  ...props
}: ButtonProps<C>) {
  const Component = as ?? 'button'
  // A <button> in a form submits unless told otherwise: make "button" the default type
  const type = Component === 'button' ? 'button' : undefined
  return <Component type={type} {...props} className={styles[variant]} />
WHY ComponentPropsWithRef<C>: the props of whatever as names.

A list that draws anything

interface DataListProps<T> {
  items: T[]
  /** A key for each item: unique in the list and the same on every render */
  getKey: (item: T) => string
  /** What one item looks like: a render prop, called once per item */
  renderItem: (item: T) => ReactNode
  /** Shown instead of an empty list */
  emptyMessage: string
  /** 'grid': cards side by side (the default); 'plain': a simple bulleted list */
  layout?: 'grid' | 'plain'

5.4 · Compound

A private context for the parts

shoreline-hq/src/components/Tabs.tsx
// Not exported: only the parts below can read it
const TabsContext = createContext<TabsValue | undefined>(undefined)

function useTabs(part: string): TabsValue {
  const value = useContext(TabsContext)
  if (value === undefined) {
    throw new Error(`<${part}> must be used inside <Tabs>`)
  }
  return value
WHY The 5.2 pattern again: T | undefined and a Hook that names the part.
5.4 · Accessible tabs

Tabs people can use

  • role="tablist" + a label · role="tab" + aria-selected
  • aria-controls / aria-labelledby connect tab and panel
  • One tab stop: tabIndex 0 on the selected tab, -1 on the others
  • Arrow keys, Home, End; panels hidden, never removed
RULE Hidden panels keep their state: the check-in marks survive a tab switch.
