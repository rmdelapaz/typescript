4.1

Effects and Fetching

Plan first, then the radio, and always sign off.

4.1 · Mental model

The radio check-in

  • The plan on the board: rendering, what should be
  • The radio check-in: the effect, talking to the outside
  • "Signing off": the cleanup, so nobody waits for calls
  • Rendering stays pure; effects run after the screen updates
RULE Is there an outside system? No: a calculation or a handler, not an effect.
4.1 · Live demo

A clock that needs an effect

import { useEffect, useState } from 'react'

export function TideClock() {
  const [now, setNow] = useState(() => new Date())

  useEffect(() => {
    // Start a timer when the clock appears on the screen...
    const timer = setInterval(() => setNow(new Date()), 1000)
    // ...and stop it when the clock goes away
    return () => clearInterval(timer)
  }, [])

  return <p>Crew time: {now.toLocaleTimeString('en-US')}</p>
}
WHY Effect · cleanup · array. The effect returns void | Destructor.

An async function inside the effect

    async function load() {
      setSites(await getSites())
    }
    load()
  }, [])

4.1 · Loading, error and empty

LoadState<T>, generic

shoreline-hq/src/utils/loadState.ts
// What a screen that loads data can be doing (the LoadState of Lesson 2.2, for any kind of data)
export type LoadState<T> =
  | { kind: 'loading' }
  | { kind: 'failed'; message: string }
  | { kind: 'ready'; data: T }
WHY Only ready has data. Empty is ready with zero items.
4.1 · Errors you can tell apart

Two errors, two messages

500ApiError · "The server had a problem (500). Try again in a moment."
no APITypeError · "Could not reach the server. Check that shoreline-api is running…"
WHY Annotate .catch((error: unknown) => …): then instanceof narrows it.
4.1 · Canceling requests

The sites page's effect

shoreline-hq/src/pages/SitesPage.tsx
  // After the first render: ask the API for the sites, and cancel the request if the page goes away
  useEffect(() => {
    const controller = new AbortController()
    getSites(controller.signal)
      .then((sites) => setState({ kind: 'ready', data: sites }))
      .catch((error: unknown) => {
        if (controller.signal.aborted) return
        console.error(error)
        setState({ kind: 'failed', message: describeError(error) })
      })
    return () => controller.abort()
  }, [])
MEASURED Dev server: two requests, the first aborted (Strict Mode). Preview: one.
4.1 · Common mistake

setState at the top of an effect

  ⚠ react(set-state-in-effect): Calling setState synchronously within an effect can trigger cascading renders
