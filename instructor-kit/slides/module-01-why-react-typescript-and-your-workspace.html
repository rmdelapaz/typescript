Why React + TypeScript

Describe the data first, then let the tools hold you to it.

1.1 · Mental model

React: a tide chart that redraws itself

  • You keep the data right: times and heights
  • The chart is drawn from the data, every time it changes
  • Components say what a part of the screen should be
  • You never tell React how to change the page: declarative
1.1 · Mental model

TypeScript: a spell-checker for your data

  • Its dictionary is your own description of the data
  • It underlines what does not match, while you type
  • It does not stop you printing a letter full of typos
  • The better your descriptions, the more it catches
RULE Describe the data first, then let the tools hold you to it.

1.1 · Three facts

Checking versus running

  • TypeScript checks before the code runs: editor and tsc
  • The types disappear: browsers and Node run JavaScript
  • Running is not checking: node file.ts and Vite's dev server never check
  • If you never look at the errors, you get none of the protection

1.1 · The limits

What TypeScript cannot do

  • See data that arrives while the app runs (Lesson 2.4, Module 8)
  • Check logic: capacity + spotsTaken is perfectly typed (Module 9)
  • Check anything typed any: the smoke alarm without batteries
  • Make the app faster or slower: the types are gone
WATCH A green build is not a working app.
