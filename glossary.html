📖 Glossary

🧭 How to Use This Glossary

Every word below is used in the course and explained the way the lessons use it: TypeScript 7, React 19, React Router 8, TanStack Query 5, Zod 4, Vitest 5 and Playwright. Jump to a letter, or press Ctrl+F (⌘ Cmd+F on a Mac) to search the page. Each entry ends with a link to the lesson that teaches it; a second link means a later lesson goes deeper. Names that start with a symbol (.env, @ts-expect-error, <dialog>) are filed under their first letter. For code patterns, see the TypeScript cheat sheet and the React cheat sheet; for the mock back end, the shoreline-api reference; for error messages, Troubleshooting.

#

204 No Content
An HTTP success answer with no body, such as shoreline-api's answer to DELETE /api/events/:id for a draft. Code that always calls response.json() fails on it, so check the status first. Lesson 7.2.
401 vs 403
401 Unauthorized means "I don't know who you are" (not signed in, or the session ended); 403 Forbidden means "I know who you are, and you may not do this" (a volunteer asking for organizer data). Lesson 5.2. Lesson 6.3.
413 Payload Too Large
The HTTP status shoreline-api answers when an uploaded photo is bigger than 5 MB (error code payload_too_large). Lesson 8.2.
415 Unsupported Media Type
The HTTP status shoreline-api answers when an upload is not a JPEG, PNG or WebP image (error code unsupported_media_type). Lesson 8.2.

A

AbortController
A browser object that can cancel work: its signal is passed to fetch, and controller.abort() in the effect's cleanup cancels a request nobody is waiting for any more. Lesson 4.1.
AbortSignal
The signal of an AbortController. The HQ's API functions take signal?: AbortSignal and pass it to fetch, so a canceled request rejects with an AbortError instead of updating the screen. Lesson 4.1.
accept (file input)
The attribute that tells the file picker which types to offer: accept="image/jpeg,image/png,image/webp". It is only a hint (most pickers can still choose "All files"), so the HQ checks the type and size itself. Lesson 8.2.
Access-Control-Expose-Headers
A CORS header that lists which response headers a page from another origin may read. shoreline-api exposes its paging headers, so response.headers.get('X-Total-Count') works from localhost:5173. Lesson 4.1.
Accessibility (a11y)
Making the app usable by everyone, including people who use a keyboard, a screen reader or zoom. "a11y" is short for the 11 letters between a and y. Lesson 3.6.
Accessibility tree
The version of the page that assistive technology gets: each element's role, name and state. DevTools' Accessibility pane shows it. Lesson 3.6.
act()
Tells React to finish an update before the next line of a test. Testing Library wraps renders and user-event in it; you wrap things it cannot see, such as advancing fake timers that set state. Lesson 9.2.
Action
An object that describes what happened, such as { type: 'checkIn', signupId: 's088' }. The HQ types its actions as a discriminated union on type, so a misspelled or incomplete action is a compile error. Lesson 5.1.
Action (store)
A function kept inside a store that changes its state, such as setTheme. Components call actions instead of writing state directly. Lesson 7.3.
Action type / payload
The type field names what happened and is the union's discriminant; the other fields (the payload) carry only the data that action needs, like signupId. Lesson 5.1.
ActionDispatch
React's type for the dispatch function useReducer returns, such as ActionDispatch<[action: RosterAction]>. Lesson 5.1.
actionlint
A free checker for GitHub Actions workflow files that catches mistakes such as wrong indentation or action versions too old for today's runners before you push. Lesson 10.2.
allowArbitraryExtensions
A tsconfig option (on in the Vite template) that lets you import other file types when a matching declaration file exists, such as Badge.module.d.css.ts for a CSS Module with typed class names. Lesson 2.4. Lesson 3.6.
Alt text
The text alternative of an image (alt). Informative images describe what matters; decorative ones get alt="" so screen readers skip them. Lesson 3.6.
Ambient module declaration
A declare module 'name' { … } in a .d.ts file that describes a JavaScript package with no types. Describe what you use; an empty declare module 'name'; just makes everything any. Lesson 11.2.
any
The type that switches checking off: anything goes in and anything comes out, so mistakes slip through. Avoid it; reach for unknown instead. Lesson 2.1.
API
Application programming interface: a set of addresses and rules that lets one program ask another for data or actions. Shoreline Crew HQ talks to the shoreline-api over HTTP and gets JSON back. Lesson 1.1.
ApiError
The HQ's own error class (class ApiError extends Error) with the status, code and fieldErrors from shoreline-api's error body, so code can tell a 404 from a 500 with instanceof. Lesson 4.1.
ApiResult&lt;T&gt;
The exported interface describing what useApi returns: { state: LoadState<T>; reload: () => void }. Naming the return type gives callers and error messages a readable name. Lesson 4.2.
App-wide store
State that lives outside the component tree so any component can read it without passing props, such as the HQ's theme and list density. Zustand and Redux are libraries for app-wide stores. Lesson 7.3.
append / remove (field array)
useFieldArray's functions that add a row (append(row, { focusName }), which can move the focus into the new row) and delete one by index. After remove, the HQ moves the focus to the Add button itself. Lesson 8.2.
applyAccept
A user-event option: by default user.upload respects the input's accept attribute and skips other files. userEvent.setup({ applyAccept: false }) uploads them anyway, to test the app's own type check. Lesson 9.2.
ARIA (first rule)
Accessible Rich Internet Applications: attributes (role, aria-*) that tell assistive technology what an element is or does. The first rule of ARIA: do not use it when a native HTML element already does the job. Lesson 3.6.
aria-busy
Tells assistive technology that a region is being updated (aria-busy={true}) and should be read once it is done. Lesson 6.3.
aria-controls
Points from a control to the element it controls by id, such as a tab to its panel. Lesson 5.4.
aria-current
aria-current="page" marks the link to the page you are on; screen readers announce "current page", and the HQ styles the same attribute. Lesson 3.6. Lesson 6.1.
aria-describedby
An attribute that links a field to the id of the text that describes it, such as its error message, so a screen reader reads both together. Lesson 3.5.
aria-disabled
Marks a control as unavailable while keeping it focusable and announced, unlike the disabled attribute; the click handler must then ignore it. The desk's "Undo last change" uses it. Lesson 5.1.
aria-expanded
An attribute that tells assistive technology whether the content a button controls is shown (true) or hidden (false), as on the event cards' "Show details" buttons. Lesson 3.4.
aria-haspopup
Tells assistive technology that a button opens something, such as aria-haspopup="dialog" on the HQ's "Cancel cleanup" button. Lesson 4.3.
aria-invalid
An attribute that marks a field as having an error, so screen readers announce it and CSS can style it ([aria-invalid='true']). Lesson 3.5.
aria-keyshortcuts
An attribute that tells assistive technology about a keyboard shortcut, like aria-keyshortcuts="/" on the HQ's search box, which / focuses. Lesson 4.3.
aria-pressed
Makes a button a toggle button: aria-pressed={true} is announced as "pressed". The check-in desk's "Check in" and "No-show" buttons use it. Lesson 5.1.
aria-selected
Says which tab in a tab list is the selected one (aria-selected={true}). Lesson 5.4.
Arrange, Act, Assert
The three parts most tests have: set up the input, run the code, check the result. The first HQ test labels each part with a comment. Lesson 9.1.
Array type
A list whose items share a type, written string[] (or Array<string>). TypeScript infers it from the items: ['Gloves', 'Bags'] is a string[]. Lesson 2.1.
Arrow function
A function written (param) => result. The course uses function declarations for named helpers and components and arrows for callbacks. In a .tsx file a generic arrow needs <T,>. Lesson 2.3.
Artifact (CI)
A file a workflow keeps after the run. The HQ's workflow uploads Playwright's report with actions/upload-artifact when a test fails, for a week. Lesson 10.2.
as const (return value)
Written after an array a Hook returns (return [open, toggle] as const), it makes a readonly tuple, so each position keeps its own type instead of an array of unions. Lesson 4.2.
as prop
The prop that picks what a polymorphic component renders: <Button as={Link} to="/events/new" variant="primary">. Lesson 5.4. Lesson 6.1.
asChild
Another way to make a component polymorphic, used by Radix UI and others: <Button asChild><a href=…> merges the button's behavior into the child element instead of taking an as prop. Lesson 5.4.
assertNever
The HQ's helper assertNever(value: never): never, which throws. Called in a default case, it turns "I forgot a case" into a compile error that names the missing member. Lesson 5.1.
Assignability
Whether a value of one type may be used where another type is expected. Most TypeScript errors say a type "is not assignable to" another: read the last line of the message first, it names the exact mismatch. Lesson 2.1.
Assistive technology
Software or hardware people use to reach the web: screen readers, screen magnifiers, switch devices, voice control. Lesson 3.6.
Authorization header
The request header that carries credentials. The HQ's client adds Authorization: Bearer … from the session to every request. Lesson 5.2.
Auto-waiting
Playwright waits for an element to be visible, enabled and steady before clicking or typing, up to the test's timeout, so there is no findBy or waitFor to remember. Lesson 9.3.
Automated test
A small program that runs a piece of your app and checks the result, such as "formatDate('2026-07-04') is 'Sat, Jul 4, 2026'". You write it once and run it as often as you like. Lesson 9.1.
Automatic activation
Tabs that select a tab as soon as the focus moves to it with the arrow keys (the HQ's choice), instead of waiting for Enter or Space. Lesson 5.4.
Automatic sign-out
When the API answers 401 to a request that carried a token (for example after shoreline-api restarted), the HQ clears the session itself, so people sign in again instead of seeing errors. Lesson 6.3.
axe DevTools
A free browser extension from Deque that scans a page with the axe-core rules. Lesson 9.3 runs the same rules automatically in Playwright tests. Lesson 3.6. Lesson 9.3.
axe-core
The open-source accessibility engine behind axe DevTools. In Lesson 9.3 the HQ's end-to-end tests run it on seven pages in both themes and expect no WCAG A/AA violations. Lesson 9.3.
@axe-core/playwright
The package that runs axe-core inside a Playwright page: new AxeBuilder({ page }).withTags([…]).analyze(). The HQ wraps it in expectNoAxeViolations(page). Lesson 9.3.

B

::backdrop
The CSS pseudo-element drawn behind a modal dialog, which you can style (for example a translucent dark layer). Lesson 4.3.
Batching
React grouping several state updates from one event into a single re-render. Lesson 3.4.
Bearer token
A token sent with each request as proof of sign-in: Authorization: Bearer <token>. shoreline-api's tokens are opaque strings kept in memory, so restarting the API ends every session. Lesson 5.2.
Blob
Raw bytes with a content type. A File is a Blob with a name; Lesson 10.1's CSV download builds one with new Blob([csv], { type: 'text/csv;charset=utf-8' }). Lesson 8.2. Lesson 10.1.
Boolean shorthand (attribute without value)
Writing a prop with no value, such as <Card wide />, which means wide={true}, as HTML's disabled does. Lesson 3.2.
Branded type
A string (or number) with an invisible tag, such as string & { readonly __brand: 'EventId' }, so TypeScript keeps look-alike values such as event ids and volunteer ids from being swapped. The HQ does not adopt them. Lesson 11.2.
Build (npm run build)
Making the production version of the app. In the template, npm run build is tsc -b && vite build: check every type first, then bundle into dist/. A type error stops the build. Lesson 1.2.
Build mode (--mode)
A name Vite builds under, such as vite build --mode demo. It picks which .env.[mode] files load, and defineConfig(({ mode }) => …) lets the config change with it. Lesson 10.1. Lesson 10.2.
Bundle
The JavaScript and CSS files a build produces for the browser, from your code and the libraries it imports. Lesson 10.1 measures what a visitor downloads and splits the HQ's bundle. Lesson 10.1.

C

Cache (query cache)
TanStack Query's shared store of every answer from the API, each one filed under a query key. Components that ask for the same key share one entry and one request, which is why going back to a page shows its data at once. Lesson 7.1.
Cache-Control
The HTTP header that tells browsers how long they may keep a file. public, max-age=31536000, immutable on the hashed assets means "keep it for a year, it never changes". Lesson 10.2.
Callback
A function you pass to another function to be called later, such as the arrow inside events.filter((event) => …) or an onClick handler. Lesson 2.3.
Callback prop
A function passed as a prop so a child can tell its parent something happened: onQueryChange, onClear. Name them on…. Lesson 3.4.
Callback ref
A function passed as ref: React calls it with the element when it arrives. In React 19 it may return a cleanup function, and must return nothing else (use braces, not an arrow's value). Lesson 4.3.
cancelQueries
queryClient.cancelQueries({ queryKey }) stops requests running for a key. An optimistic update calls it first, so an answer already on its way cannot overwrite the new value with the old one. Lesson 7.2.
Catch-all route (*)
A route with path: '*' that matches any address no other route matched; the HQ's shows NotFoundPage. Lesson 6.1.
Cents (money in minor units)
Storing money as a whole number of cents (1999 is $19.99), as the worked example's Cents type does, so sums never drift the way decimal fractions can. Lesson 11.1.
ChangeEvent
React's type for an input's change event: ChangeEvent<HTMLInputElement>, whose event.target.value is the field's text. Lesson 3.4.
Charter
The first section of the final-project worksheet: the client, the people who use the app, the must-haves and what is out of scope, agreed before any code. Lesson 11.1.
children
The special prop holding whatever is written between a component's opening and closing tags. Type it children: ReactNode, as the HQ's Card and AppLayout do. Lesson 3.2.
Chrome for Testing
The Chrome build Playwright downloads for its Chromium tests (npx playwright install chromium), made for automated testing. Lesson 9.3.
Chunk
One JavaScript file of a build. Vite prints each chunk with its size and gzip size, and warns when one is larger than 500 kB after minification. Lesson 10.1.
Class component
A component written as class X extends Component<Props, State> with a render() method. The course writes function components; an error boundary is the one place React still needs a class. Lesson 4.4.
className / htmlFor
TSX's names for HTML's class and for attributes (both are reserved words in JavaScript). Most other attributes are camelCase too, such as tabIndex; aria-* and data-* keep their dashes. Lesson 3.1.
Cleanup function
The function an effect returns. React calls it before the effect runs again and when the component leaves the screen; the HQ aborts its request there. In React 19 a callback ref may return one too. Lesson 4.1. Lesson 4.3.
cleanup()
Testing Library's function that takes rendered components off the page. The HQ's setup file calls it after every test, or the next test finds two of everything ("Found multiple elements"). Lesson 9.1.
Client brief
A short description of an app someone wants: who they are, the must-haves, the data they have and what is out of scope. Lesson 11.1 offers seven briefs for the final project. Lesson 11.1.
Client state
State only this browser knows, such as an open dialog, a search box or the chosen theme. The app owns it, so it never goes out of date. Lesson 7.3 decides where each kind belongs. Lesson 7.1. Lesson 7.3.
Client-side routing
Changing pages inside a single-page app: the router updates the address with the History API and renders the matching page, without asking the server for a new document. Lesson 6.1.
Code review labels
Prefixes that say how much a review comment matters: blocking (must change before merge), suggestion (better, but your call) and nit (tiny, style). Lesson 11.2.
Code splitting
Dividing the build into a basic chunk every visitor loads plus chunks fetched only when a page or widget needs them, such as the organizer pages a guest never opens. Lesson 10.1.
codegen (Playwright)
npx playwright codegen http://localhost:4173 opens a browser and writes test code while you click through the app: a quick first draft of a test. Lesson 9.3.
codeSplitting groups
The Rolldown option build.rolldownOptions.output.codeSplitting.groups that names which modules go into which chunk, such as the HQ's vendor and forms groups. It replaces the deprecated manualChunks. Lesson 10.1.
Coerce (z.coerce)
A Zod schema that converts the input before checking it: z.coerce.number<string>() turns the text '12' from a number box into 12 (and '' into 0, so a separate rule is needed). Lesson 8.1.
Colocation
Keeping state as close as possible to where it is used, and moving it up or out only when something forces you to. Lesson 7.3's questions: does the server own it (Query)? should a link keep it (URL)? does one component need it? only then a store. Lesson 7.3.
Color scheme
Whether an element is drawn light or dark (the CSS color-scheme property). The HQ follows the device unless the data-theme attribute on <html> says light or dark. Lesson 7.3.
Commit
The step after rendering where React changes the real DOM, only where the new output differs. Rendering is calling component functions; committing is updating the page. Lesson 5.3.
Compiler (TypeScript)
The program (tsc) that reads your TypeScript, checks every type and reports errors before the code runs. In a Vite project it only checks (noEmit); Vite turns the files into JavaScript. Lesson 1.1. Lesson 2.4.
Component
In React, a function that returns a piece of user interface written in TSX. Screens are built by putting components inside other components; component names start with a capital letter. Lesson 1.1. Lesson 3.1.
Component test
A test that renders one component (or a few) into a pretend page and checks what a person would see, such as "a guest's header has no Volunteers link". Lesson 9.1.
ComponentProps
ComponentProps<'section'>: every prop a built-in element (or another component) accepts. Extending it lets a component pass id, aria-label and the rest through. Lesson 3.2. Lesson 5.4.
ComponentPropsWithRef
ComponentPropsWithRef<C> is the props an element or component C accepts, including ref. The Button's props are built from it, so href is allowed only when as="a". Lesson 5.4.
ComponentType
React's type for "any component that takes these props": the HQ's ErrorBoundary takes fallback: ComponentType<FallbackProps>, so a function or class component fits. Lesson 4.4.
Composition
Building bigger components by putting smaller ones inside them (through children or other props) instead of adding options to one big component. Lesson 3.2.
Compound component
A component split into parts that are written as ordinary JSX and work together, like <Tabs>, <TabList>, <Tab> and <TabPanel>. The parent shares its state with the parts through a private context. Lesson 5.4.
Conditional rendering
Showing parts of a component only when they apply, with if and early returns, the ternary ? :, &&, or returning null. Lesson 3.3.
Conditional type
A type that chooses: T extends U ? X : Y, "if T fits U, then X, else Y". Libraries use them to work out types from your arguments; ReturnType is one. Lesson 11.2.
configureStore
The Redux Toolkit function that creates the store from the slices' reducers (and options such as preloadedState), with the Redux DevTools connection built in. Lesson 7.3.
Constraint (extends)
A limit on a type parameter: findById<T extends { id: string }> accepts any type that has an id, so the function may read item.id. Lesson 2.3. Lesson 5.4.
Context (React)
A way to send one value to every component below a provider, however deep, without passing props through the middle. Use it for values many distant components need and that change rarely, such as the signed-in session. Lesson 5.2.
Contextual typing
TypeScript typing a function's parameters from where the function is used: the arrow passed to events.filter knows its parameter is a CleanupEvent without an annotation. Lesson 2.3.
Continuous integration (CI)
A computer running the project's checks every time code reaches the shared repository, marking each change with a green tick or a red cross that the whole team can see. Lesson 10.2.
Contrast ratio
How much a text color stands out from its background, from 1:1 to 21:1. WCAG AA asks for at least 4.5:1 for normal text; DevTools' color picker shows it. Lesson 3.6.
Controlled input
A form field whose value comes from React state (value={query}) and changes only through its onChange handler, so state and screen always agree. Lesson 3.4. Lesson 3.5.
Controller
React Hook Form's component (or useController Hook) that connects inputs that are not native form elements, such as a date-picker library that only offers value and onChange. Lesson 8.1.
Coverage
The share of your code's lines that tests ran. Lesson 9.1's advice: test what would hurt if it broke, rather than aiming for 100%. Lesson 9.1.
CPU throttling
A Chrome DevTools setting (Performance panel, CPU: 4x slowdown) that slows the page down to imitate a slower device, so performance problems show up on a fast computer. Lesson 5.3.
createBrowserRouter
Creates the HQ's router from its route list once, at module level; RouterProvider then renders it. Lesson 6.1.
createContext
createContext<T>(defaultValue) makes a context. The HQ's AuthContext is createContext<AuthValue | undefined>(undefined): no fake default. Lesson 5.2.
createMemoryRouter
React Router's twin of createBrowserRouter that keeps its history in memory instead of the address bar. Tests use it to start at any address. Lesson 9.1.
createRoot
The function from react-dom/client that main.tsx uses to connect React to the #root element: createRoot(…).render(<App />). Lesson 3.1.
createSlice
The Redux Toolkit function that builds a slice from a name, an initial state and reducer functions, and generates an action creator for each reducer (uiSlice.actions). Lesson 7.3.
CSS custom property
A CSS variable such as --link: #1f6f8b, set on :root and used as var(--link). The HQ keeps its brand colors (design tokens) this way and swaps the values for dark mode. Lesson 3.1. Lesson 3.6.
CSS Modules
CSS files named Name.module.css whose class names are made unique per file at build time. A component imports them as an object, styles.card, so two components' .card classes never clash. Lesson 3.6.
CSSModuleClasses
The type Vite gives a CSS Module import: { readonly [key: string]: string }. With noUncheckedIndexedAccess, styles.card is string | undefined, and a misspelled class gives class="undefined" instead of an error. Lesson 3.6.
CSV
Comma-separated values: a plain-text table that spreadsheets open. The HQ's Impact page downloads its monthly totals as CSV, built by the generic toCsv in utils/csv.ts. Lesson 10.1.
CSV injection
A spreadsheet treating a cell that starts with =, +, - or @ as a formula when the file is opened. The HQ puts a ' in front of such text cells so they show as plain text. Lesson 10.1.
current (ref)
The one property of a ref. A DOM ref's current is null until the element is on the page, so it is typed HTMLInputElement | null and read with ?.. Do not read it while rendering. Lesson 4.3.
Custom error class
A class that extends Error to carry extra fields, like ApiError. Its fields are written out in the class body because erasableSyntaxOnly forbids parameter properties. Lesson 4.1.
Custom Hook
A function whose name starts with use and that calls other Hooks, to share logic between components (never state: each component that calls it gets its own). The HQ's are useApi, useDebouncedValue and useDocumentTitle. Lesson 4.2.

D

Data mode
React Router's mode where routes are objects passed to createBrowserRouter, which also enables loaders, actions and error elements. Declarative mode uses <Routes>/<Route>; framework mode is a full framework with generated types. Lesson 6.1.
data() (route response)
throw data(message, { status: 404, statusText: 'Cleanup not found' }) ends a loader with an expected failure that the error element can read, without a stack trace. Lesson 6.3.
data-theme
The attribute the HQ sets on <html> from the display store (light or dark; none for System). The CSS sets color-scheme from it, and light-dark() colors follow. Lesson 7.3.
DataList
The HQ's generic list component: items, getKey, renderItem, emptyMessage and a layout. One component draws cleanups, sites and debris counts. Lesson 5.4.
DataRouter
React Router's type for a router made by createBrowserRouter or createMemoryRouter. The HQ's render helpers return it so tests can read router.state.location. Lesson 9.2.
Debounce
Waiting until a value stops changing for a moment before using it. useDebouncedValue(query, 300) sends one search request per pause in typing instead of one per key. Lesson 4.2.
Declaration file (.d.ts)
A file with only types, describing JavaScript that lives elsewhere: how TypeScript knows the DOM, Vite's extras and every npm package. Go to Definition opens them. Lesson 2.3. Lesson 2.4.
Declarative / imperative
Imperative code gives the browser step-by-step instructions (createElement, appendChild); declarative code describes what the page should look like for the current data, and React works out the steps. React is declarative. Lesson 3.1.
Default parameter
A parameter with a value used when the caller leaves it out: pluralize(count, word, plural = word + 's'). TypeScript infers its type from the default. Lesson 2.3.
Default prop value
A value used when a prop is not passed, written in the destructuring: { tone = 'info' }: BadgeProps. The prop is optional in the interface (tone?:). Lesson 3.2.
defaultProps (old pattern)
The way old components declared default prop values. Function components ignore it in React 19; use default values in the destructuring. Lesson 3.2.
defaultValue
The starting value of an uncontrolled field. The HQ's form passes the last submitted values back as defaultValue, so a failed submit keeps what people typed. Lesson 3.5.
defaultValues
The values a React Hook Form form starts with, such as the cleanup's current details on the edit page. isDirty compares against them. Lesson 8.1.
Deferred data
A promise returned from a loader without awaiting it, so the page shows before that part arrives; the component reads it with use() inside <Suspense>, like the impact report on a cleanup's page. Lesson 6.3.
DefinitelyTyped
The community project that publishes type declarations for thousands of JavaScript packages under the @types/ scope, such as @types/react. Look there first when a package has no types (error TS7016). Lesson 11.2.
Demo build
The HQ's npm run build:demo (vite --mode demo): a version that runs shoreline-api's own code in the browser through MSW, so the deployed site works with sample data and no server. Lesson 10.2.
Dependency array
The second argument of useEffect (and of useMemo/useCallback): every value from the component that the code reads. [] runs once, [siteId] follows a value, and leaving it out runs after every render. Lesson 4.1. Lesson 5.3.
Derived value
A value computed from props or state during render (filtered lists, counts) instead of stored in its own state, so it can never get out of step. Lesson 3.4.
describe / it / expect
Vitest's building blocks: describe groups tests, it (or test) is one test with a name that reads as a fact, and expect(value) starts a check. Lesson 9.1.
describeError
The HQ's function that turns any caught value (unknown) into words people understand: an ApiError becomes "The server had a problem (500)…", a TypeError "Could not reach the server…". Lesson 4.1.
Design system
A team's shared set of components, styles and rules (buttons, tabs, colors, spacing) so every screen looks and behaves alike. Compound, render-prop and polymorphic components are how such libraries are built. Lesson 5.4.
Design token
A named design value (a color, a size, a font) kept in one place and used everywhere. The HQ keeps its tokens as custom properties in index.css, the only global CSS left. Lesson 3.6.
Dev server
The development server npm run dev starts (Vite, at http://localhost:5173). It serves your app while you work and updates the page when you save; it does not check types. Lesson 1.2.
Development dependency (--save-dev)
A package needed only while you build and check the code, such as TypeScript or a linter, not by the running app. npm install --save-dev lists it under devDependencies. Lesson 2.1.
Discriminant
The shared property that tells the members of a discriminated union apart. The course uses kind ({ kind: 'loading' }, { kind: 'ready'; data }) so it is never confused with an event's status. Lesson 2.2. Lesson 3.3.
Discriminated union

The Hook that reads a route's URL parameters. Values are string | undefined, so narrow them; useParams<'eventId'>() also catches misspelled names. Lesson 6.1. Lesson 6.2.
useQuery

useQueryErrorResetBoundary
A TanStack Query Hook that returns a reset function telling the queries below "the next render may try again". The HQ passes it to its ErrorBoundary's onRetry, so Try again really asks the API again. Lesson 7.1.
user-event
The Testing Library package that acts like a person: await user.click(…), user.type, user.tab, user.upload, each with the pointer, focus and keyboard events around it. Every action is awaited. Lesson 9.2.
useReducer
const [state, dispatch] = useReducer(reducer, initialState): state whose updates follow rules or change several values together. Type the reducer, not the Hook; the old useReducer<State, Action> generics no longer compile (TS2344). Lesson 5.1.
useRef
The Hook that creates a ref: useRef(0) for a value, useRef<HTMLInputElement>(null) for a DOM element. React 19's types require an initial value (TS2554 without one). Lesson 4.3.
useRevalidator
A Hook that runs the current loaders again on demand (revalidator.revalidate()). Lesson 6.3.
userEvent.setup()
Creates the user object for one test; call it before rendering. The HQ's render helpers call it and hand you user. Lesson 9.2.
useRouteError
The Hook an errorElement uses to read what was thrown; it returns unknown, so narrow it. Lesson 6.3.
useSearchParams
React Router's Hook that returns the current URLSearchParams and a setter. Every value is string | null, so the HQ narrows it with a type predicate (readParam). Lesson 6.2.
useShallow
A Zustand helper that compares a selector's answer property by property, so a selector that builds a new object, such as { theme, density }, does not re-render the component on every change. Lesson 7.3.
useState
The Hook that gives a component one piece of state: const [query, setQuery] = useState(''). Pass a type argument when the initial value does not show every possible value (useState<StatusFilter>('all')). Lesson 3.4.
useSuspenseQuery
A query Hook that suspends (lets a Suspense boundary show its fallback) until the data is there and throws errors to the nearest error boundary. Its data is never undefined, so no narrowing is needed. Lesson 7.1.
useSyncExternalStore
The React Hook that subscribes a component to an external store and reads a snapshot of it, so React renders when the store changes; the HQ's AuthProvider reads the session this way. Lesson 6.3. Lesson 7.3.
Utility type

Variable font

Vendor chunk
A chunk that holds the libraries (React, React Router, TanStack Query, Zustand). They change less often than your code, so the browser can keep the file cached across your deploys. Lesson 10.1.
verbatimModuleSyntax
A tsconfig option (on in the Vite template) that keeps imports exactly as written, so types must be imported with import type (TS1484 otherwise). Lesson 2.4.
viewBox
An SVG attribute that sets the drawing's own coordinate system. The Impact chart draws in a 0 0 360 … box and CSS stretches it to the card's width, so everything scales together. Lesson 7.1.
Viewer (in data keys)

Virtual DOM
A popular name for what React does: compare the new description of the page (React elements) with the previous one and change only what differs in the real page. Lesson 3.1.
Visually hidden text
Text that screen readers read but the screen does not show, such as "for Weekend Cove Cleanup" after a "Show details" button. The HQ's VisuallyHidden component does it. Lesson 3.6.
Vite
The build tool and development server the course uses (npm create vite@latest shoreline-hq -- --template react-ts). It serves the app while you work and bundles it for production. Lesson 1.2.
vite:preloadError
An event Vite fires on window when loading a lazy file fails, typically in a tab left open across a deploy whose old files are gone. Listening for it and reloading loads the new version. Lesson 10.2.
Vitest
The test runner made for Vite projects: it reuses the app's own vite.config.ts (plugins included) and gives you describe, it, expect and vi. The course uses Vitest 5. Lesson 9.1.
void
The return type of a function that gives nothing back, such as an event handler or a function that only logs. Lesson 2.3.
VS Code

waitFor
Testing Library's function that runs a check again and again until it stops throwing (or times out): await waitFor(() => expect(onUploaded).toHaveBeenCalled()). Use it for things that are not elements. Lesson 9.2.
Walking skeleton
The thinnest version of an app that goes all the way from the types to a public draft address, with almost no features: a practice run that finds the closed stairs before the big day. Lesson 11.1.
watch / useWatch
React Hook Form tools that read a value while the person types, for example to show "Ends 2 hours after it starts". useWatch is the Hook form. Lesson 8.1.

How npm test runs Vitest: everything once, then again for the affected tests each time you save a file. Press q to stop. On a CI service the same command runs once and exits. Lesson 9.1.
Waterfall (requests)
Requests that wait for each other in a chain, such as a page's data and then its lazily loaded code. Each step adds a round trip; Lesson 10.1's exercise measures one. Lesson 10.1.
WCAG
The Web Content Accessibility Guidelines, the W3C standard that public and many commercial sites must meet. Its A and AA levels are what the course checks against. Lesson 3.6. Lesson 9.3.
Weak type
A type whose properties are all optional, such as RequestInit. Passing a value with none of them (an AbortSignal instead of { signal }) fails with "has no properties in common". Lesson 5.2.
Web-first assertion
A Playwright check that retries until it passes or times out (5 seconds by default): await expect(locator).toBeVisible(). It replaces checking "right now" and fixed pauses such as waitForTimeout. Lesson 9.3.
webServer
The playwright.config.ts option that starts the servers the tests need: in the HQ, shoreline-api and npm run build && npm run preview. With reuseExistingServer: true it uses ones that are already running. Lesson 9.3.
when (refine option)
A Zod 4 refine option that says when the rule may run. An object's refine normally waits until every field is valid; the HQ's end-time rule uses when so its message appears together with the others. Lesson 8.1.

TypeScript turning a literal type into its general type, such as 'draft' into string for a let or an object property. It is why a value can lose the exact type a union needs. Lesson 2.2.
withTypes
A React Redux helper that creates typed versions of its Hooks once (useDispatch.withTypes<AppDispatch>(), useSelector.withTypes<RootState>()), so components never repeat the store's types. Lesson 7.3.

A separate process that runs test files. Playwright normally runs several in parallel; the HQ sets workers: 1 because all tests share one real API, and a reset in one worker would wipe another's data. Lesson 9.3.

A YAML file in .github/workflows/ that says when GitHub Actions runs (on: pushes, pull requests) and which jobs it runs. The course's is ci.yml. Lesson 10.2.
